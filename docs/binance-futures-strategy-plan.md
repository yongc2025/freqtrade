# Binance 永续合约压缩策略方案

> 基于 Binance 原生数据的 Freqtrade 自动化交易策略
> 无需外部 API，零额外成本，回测完整支持

---

## 一、策略定位

| 项目 | 说明 |
|------|------|
| 交易所 | Binance Futures（USDT 永续） |
| 交易对 | Binance 上线的主流 + 中等市值合约 |
| 策略类型 | 压缩突破 + 多因子过滤 |
| 时间框架 | 1h 主图 + 5m 入场 |

## 二、数据源架构

所有数据均来自 Binance API，通过 ccxt 统一获取。

### 2.1 K 线数据（已有）

| 指标 | 用途 | 来源 |
|------|------|------|
| OHLCV | 计算所有技术指标 | `ccxt.fetchOHLCV()` |
| 成交量 | 量价关系分析 | 同上 |

### 2.2 合约专属数据（新增）

| 数据 | 接口 | 更新频率 | 信号含义 |
|------|------|---------|---------|
| **资金费率** | `/fapi/v1/fundingRate` | 每 8h | 正值=多头付费，负值=空头付费 |
| **持仓量(OI)** | `/fapi/v1/openInterest` | 实时 | OI 增+价涨=趋势强，OI 增+价平=变盘前兆 |
| **大户多空比** | `/futures/data/topLongShortPositionRatio` | 每 5min | 大户持仓方向偏置 |
| **账户多空比** | `/futures/data/topLongShortAccountRatio` | 每 5min | 大户账户数量占比 |
| **Taker 买卖比** | `/futures/data/takerlongshortRatio` | 每 5min | 主动买入 vs 卖出力量 |
| **清算数据** | `/fapi/v1/allForceOrders` | 实时 | 仅实盘可用，回测不可用 |

### 2.3 ccxt 调用示例

```python
import ccxt

exchange = ccxt.binance({
    'options': {'defaultType': 'future'},
    'proxies': {'http': 'http://127.0.0.1:10808', 'https': 'http://127.0.0.1:10808'},
})

# 资金费率
funding = exchange.fetch_funding_rate('BTC/USDT:USDT')

# 持仓量
oi = exchange.fetch_open_interest('BTC/USDT:USDT')

# 多空比（需要私有 API 调用）
ratio = exchange.fapiPrivateGetPositionRatio({
    'symbol': 'BTCUSDT', 'period': '5m', 'limit': 1
})
```

## 四、合约数据评分体系（新增）

### 4.1 资金费率信号（满分 10 分）

资金费率是 Binance 最有价值的反向指标。

| 条件 | 分数 | 逻辑 |
|------|------|------|
| 费率 ≤ -0.01% | 10 | 空头极度拥挤 → 做多信号最强 |
| -0.01% < 费率 ≤ -0.005% | 8 | 空头偏重 |
| -0.005% < 费率 ≤ 0.005% | 5 | 中性 |
| 0.005% < 费率 ≤ 0.01% | 3 | 多头偏重 |
| 费率 > 0.01% | 0 | 多头极度拥挤 → 做多风险高 |

**原理：** 资金费率为负时，空头向多头付费。极端负值意味着空头过度拥挤，一旦价格反弹会引发空头踩踏（轧空）。

### 4.2 持仓量变化信号（满分 10 分）

| 条件 | 分数 | 逻辑 |
|------|------|------|
| OI 5min 变化 > +3% 且价格横盘 | 10 | 大资金入场蓄势 |
| OI 5min 变化 > +2% 且价格微涨 | 8 | 趋势确认 |
| OI 变化 < 1% | 5 | 平静 |
| OI 5min 变化 > +3% 且价格大跌 | 2 | 可能是空头加仓 |
| OI 5min 变化 < -2% | 0 | 资金撤离 |

**原理：** OI 增加 + 价格不动 = 大资金在悄悄建仓；OI 暴增 + 价格暴跌 = 空头主导，但可能被轧。

### 4.3 大户多空比信号（满分 10 分）

| 条件 | 分数 | 逻辑 |
|------|------|------|
| 大户多空比 > 1.5 | 10 | 大户明显做多 |
| 1.2 < 比 ≤ 1.5 | 8 | 大户偏多 |
| 0.8 < 比 ≤ 1.2 | 5 | 中性 |
| 0.5 < 比 ≤ 0.8 | 3 | 大户偏空 |
| 比 ≤ 0.5 | 0 | 大户明显做空 |

**原理：** 大户持仓方向是"聪明钱"的代理指标。大户做多 + 技术面压缩 = 共振信号。

### 4.4 Taker 买卖比信号（满分 5 分）

| 条件 | 分数 | 逻辑 |
|------|------|------|
| Taker 买卖比 < 0.8 | 5 | 卖压过度 → 反弹概率高 |
| 0.8 < 比 ≤ 1.0 | 3 | 略偏卖 |
| 比 > 1.0 | 0 | 买压正常或偏高 |

### 4.5 合约数据总分

| 维度 | 满分 |
|------|------|
| 资金费率 | 10 |
| 持仓量变化 | 10 |
| 大户多空比 | 10 |
| Taker 买卖比 | 5 |
| **合计** | **35** |

## 六、入场条件（4 层过滤）

```
第1层：基础过滤
  ├── 交易对在 Binance 合约白名单
  ├── 24h 成交量 > 100万 USDT
  └── 有足够 K 线数据（≥ 100 根）

第2层：技术面压缩（必须全部满足）
  ├── 布林带宽度分位数 < 阈值（默认 20%）
  ├── 成交量萎缩比 < 阈值（默认 0.5）
  └── RSI 在低位区间（默认 25-65）

第3层：合约数据确认（加分项，非硬性门槛）
  ├── 资金费率偏空（负值加分）
  ├── OI 增加（蓄势信号）
  ├── 大户偏多（多空比 > 1.0）
  └── Taker 卖压过度

第4层：评分门槛
  └── 总分 ≥ 动态门槛（完整模式55/95，降级模式35/60）
```

| 优先级 | 信号 | 动作 | 逻辑 |
|--------|------|------|------|
| 1 | 资金费率反转 > 0.03% | 减仓 50% | 多头极度拥挤，回调风险 |

| 3 | 大户多空比 < 0.5 | 全部平仓 | 大户翻空 |
| 4 | RSI > 75 | 减仓 50% | 超买 |
| 5 | 布林带宽度扩大 > 2x | 全部平仓 | 波动率爆发，行情走完 |
| 6 | 止损 -3% | 全部平仓 | 硬止损 |
| 7 | 止盈 +8% | 减仓 50% | 锁定利润 |

| 规则 | 参数 |

## 十二、风险提示

1. **资金费率滞后**：每 8h 更新一次，不是实时指标，可能错过快速变化
2. **大户多空比误导**：大户可能同时在现货和合约对冲，多空比不等于真实方向
3. **OI 数据噪音**：OI 变化可能来自合约到期/结算，不全是真实资金流动
4. **回测偏差**：多空比/OI 历史数据有限（Binance 最多保留 30 天），长期回测受限
5. **过拟合风险**：参数不宜过多，建议保持在 5 个以内可优化参数
