# Freqtrade 基础知识

本页向您介绍 Freqtrade 的一些基本工作原理和概念。

## Freqtrade 术语

* **Strategy (策略)**：您的交易策略，告诉机器人该做什么。
* **Trade (交易)**：已开启的持仓（头寸）。
* **Open Order (未完成订单)**：当前已在交易所挂出但尚未完全成交的订单。
* **Pair (币对)**：可交易的资产对，通常格式为 基础货币/报价货币（例如：现货为 `XRP/USDT`，期货为 `XRP/USDT:USDT`）。
* **Timeframe (时间框架)**：使用的 K 线长度（例如：`"5m"`，`"1h"`，...）。
* **Indicators (指标)**：技术指标（SMA, EMA, RSI, ...）。
* **Limit order (限价单)**：在指定的限价或更好的价格执行的订单。
* **Market order (市价单)**：保证成交，但根据订单大小可能会对价格产生冲击。
* **Current Profit (当前累计利润)**：该笔交易当前待定（未实现）的利润。这主要用于整个机器人和 UI 界面。
* **Realized Profit (已实现利润)**：已经落袋为安的利润。仅在涉及 [部分退出/减仓](strategy-callbacks.md#adjust-trade-position) 时相关 - 该文档也解释了其计算逻辑。
* **Total Profit (总利润)**：已实现利润和未实现利润的总和。百分比（%）数值是相对于该笔交易的总投资额计算的。

## 手续费处理

Freqtrade 的所有利润计算都包含手续费。对于回测（Backtesting）、超参数优化（Hyperopt）和模拟盘（Dry-run）模式，使用交易所的默认手续费（交易所最低级别费率）。对于实盘操作，则使用交易所实际收取的费用（包含 BNB 抵扣优惠等）。

## 币对命名

Freqtrade 遵循 [ccxt 命名规范](https://docs.ccxt.com/#/README?id=consistency-of-base-and-quote-currencies)。
在错误的市场使用错误的命名规范通常会导致机器人无法识别币对，通常会触发“该币对不可用（this pair is not available）”之类的错误。

### 现货币对命名

对于现货币对，命名格式为 `基础货币/报价货币`（例如：`ETH/USDT`）。

### 期货币对命名

对于期货币对，命名格式为 `基础货币/报价货币:结算货币`（例如：`ETH/USDT:USDT`）。

## 机器人执行逻辑

以模拟盘或实盘模式启动 freqtrade（使用 `freqtrade trade`）将启动机器人并进入机器人迭代循环。
这也会触发 `bot_start()` 回调。

默认情况下，机器人循环每隔几秒钟运行一次（受 `internals.process_throttle_secs` 控制），并执行以下操作：

* 从持久化存储中获取已开启的交易。
* 计算当前可交易的币对列表。
* 下载币对列表中的 OHLCV 数据，包括所有 [辅助指标币对 (informative pairs)](strategy-customization.md#get-data-for-non-tradeable-pairs)。
  此步骤每根 K 线仅执行一次，以避免不必要的网络流量。
* 调用策略的 `bot_loop_start()` 回调。
* 对每个币对进行策略分析。
  * 调用 `populate_indicators()`。
  * 调用 `populate_entry_trend()`。
  * 调用 `populate_exit_trend()`。
* 从交易所更新未完成订单的状态。
  * 为已成交订单调用 `order_filled()` 策略回调。
  * 检查未完成订单是否超时。
    * 为未成交的开仓订单调用 `check_entry_timeout()` 策略回调。
    * 为未成交的平仓订单调用 `check_exit_timeout()` 策略回调。
    * 为未完成订单调用 `adjust_order_price()` 策略回调。
      * 为未成交的开仓订单调用 `adjust_entry_price()` 策略回调。*仅在未实现 `adjust_order_price()` 时调用*。
      * 为未成交的平仓订单调用 `adjust_exit_price()` 策略回调。*仅在未实现 `adjust_order_price()` 时调用*。
* 验证现有持仓，并在适当时执行平仓订单。
  * 考虑止损（stoploss）、投资回报率（ROI）、平仓信号（exit-signal）、`custom_exit()` 和 `custom_stoploss()`。
  * 根据 `exit_pricing` 配置设置或使用 `custom_exit_price()` 回调确定平仓价格。
  * 在挂出平仓订单前，会调用 `confirm_trade_exit()` 策略回调。
* 如果启用了加减仓功能，则通过调用 `adjust_trade_position()` 检查现有交易的仓位调整，并在需要时下达额外订单。
* 检查交易槽位是否仍可用（是否达到 `max_open_trades` 上限）。
* 验证开仓信号，尝试进入新头寸。
  * 根据 `entry_pricing` 配置设置或使用 `custom_entry_price()` 回调确定开仓价格。
  * 在保证金（Margin）和期货（Futures）模式下，调用 `leverage()` 策略回调以确定所需的杠杆倍数。
  * 通过调用 `custom_stake_amount()` 回调确定投入资金大小。
  * 在挂出开仓订单前，会调用 `confirm_trade_entry()` 策略回调。

该循环将不断重复，直到机器人停止。

## 回测 / 超参数优化执行逻辑

[回测](backtesting.md) 或 [超参数优化](hyperopt.md) 仅执行上述逻辑的一部分，因为大多数交易操作都是完全模拟的。

* 加载配置币对列表的历史数据。
* 调用一次 `bot_start()`。
* 计算指标（每个币对调用一次 `populate_indicators()`）。
* 计算开仓/平仓信号（每个币对调用一次 `populate_entry_trend()` 和 `populate_exit_trend()`）。
* 逐根 K 线循环，模拟进场和出场点。
  * 调用策略的 `bot_loop_start()` 回调。
  * 检查订单超时，通过 `unfilledtimeout` 配置，或通过 `check_entry_timeout()` / `check_exit_timeout()` 策略回调。
  * 为未完成订单调用 `adjust_order_price()` 策略回调。
    * 为未成交开仓单调用 `adjust_entry_price()` 回调。*仅在未实现 `adjust_order_price()` 时调用！*
    * 为未成交平仓单调用 `adjust_exit_price()` 回调。*仅在未实现 `adjust_order_price()` 时调用！*
  * 检查交易进入信号（`enter_long` / `enter_short` 列）。
  * 确认交易进入/退出（如果在策略中实现了 `confirm_trade_entry()` 和 `confirm_trade_exit()`）。
  * 调用 `custom_entry_price()`（如果在策略中实现）以确定进场价格（价格会被平移至开盘 K 线范围内）。
  * 在保证金和期货模式下，调用 `leverage()` 回调确定所需杠杆。
  * 通过 `custom_stake_amount()` 回调确定投入大小。
  * 如果启用，检查持仓调整并调用 `adjust_trade_position()` 以确定是否需要追加订单。
  * 为已成交的开仓单调用 `order_filled()` 回调。
  * 调用 `custom_stoploss()` 和 `custom_exit()` 寻找自定义出场点。
  * 对于基于平仓信号、自定义平仓和部分平仓的出场：调用 `custom_exit_price()` 确定平仓价格（价格会被平移至收盘 K 线范围内）。
  * 为已成交的平仓单调用 `order_filled()` 回调。
* 生成回测报告输出。
