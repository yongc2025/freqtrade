## 交易所配置

Freqtrade 基于 [CCXT 库](https://github.com/ccxt/ccxt)，该库支持超过 100 个加密货币交易所市场和交易 API。完整的最新列表可以在 [CCXT 仓库主页](https://github.com/ccxt/ccxt/tree/master/python) 中找到。
然而，开发团队仅对少数交易所进行了测试。这些交易所的当前列表可以在本文档的 "首页（Home）" 部分找到。

欢迎测试其他交易所，并提交您的反馈或 PR 以改进机器人或确认交易所工作无误。

某些交易所需要特殊配置，具体见下文。

### 示例交易所配置

针对 "binance" 的交易所配置如下所示：

```json
"exchange": {
    "name": "binance",
    "key": "your_exchange_key",
    "secret": "your_exchange_secret",
    "ccxt_config": {},
    "ccxt_async_config": {},
    // ... 
```

### 设置频率限制（Rate Limits）

通常，CCXT 设置的频率限制是可靠且有效的。
如果遇到与频率限制相关的问题（通常日志中会出现 DDOS 异常），可以轻松地将 `rateLimit` 设置更改为其他值。

```json
"exchange": {
    "name": "kraken",
    "key": "your_exchange_key",
    "secret": "your_exchange_secret",
    "ccxt_config": {"enableRateLimit": true},
    "ccxt_async_config": {
        "enableRateLimit": true,
        "rateLimit": 3100
    },
```

此配置启用了 Kraken，并设置了频率限制以避免被交易所封禁。
`"rateLimit": 3100` 定义了每次调用之间 3.1 秒的等待事件。也可以通过将 `"enableRateLimit"` 设置为 false 来完全禁用此功能。

!!! Note "注意"
    频率限制的最佳设置取决于交易所和白名单的大小，因此理想参数会因许多其他设置而异。
    我们尽可能为每个交易所提供合理的默认值，如果您遇到封禁，请确保启用了 `"enableRateLimit"` 并逐步增加 `"rateLimit"` 参数。

## 币安 (Binance)

!!! Warning "服务器位置和地理 IP 限制"
    请注意，币安会根据服务器所属国家/地区限制 API 访问。目前且不完全的被屏蔽国家包括加拿大、马来西亚、荷兰和美国。请前往 [币安条款 > b. 资格](https://www.binance.com/en/terms) 获取最新列表。

币安支持 [生效时间策略 (time_in_force)](configuration.md#understand-order_time_in_force)。

!!! Tip "交易所止损 (Stoploss on Exchange)"
    币安支持 `stoploss_on_exchange` 并使用 `stop-loss-limit`（限价止损）订单。它具有巨大的优势，因此我们建议通过启用交易所止损来从中受益。
    在期货方面，币安同时支持 `stop-limit`（限价止损）和 `stop-market`（市价止损）订单。您可以在 `order_types.stoploss` 配置设置中使用 `"limit"` 或 `"market"` 来决定使用哪种类型。

### 币安黑名单建议

对于币安，建议将 `"BNB/<STAKE>"` 添加到您的黑名单中以避免问题，除非您愿意在账户中保留足够的额外 `BNB`，或者您愿意禁用使用 `BNB` 抵扣费用。
币安账户可能会使用 `BNB` 支付费用，如果某次交易恰好是 `BNB`，后续交易可能会消耗这一仓位，导致最初的 BNB 交易由于所需金额不足而无法卖出。

如果没有足够的 `BNB` 来支付交易费用，则费用将不会由 `BNB` 覆盖，也不会发生费用减免。Freqtrade 永远不会购买 BNB 来抵扣费用。为此，需要手动购买和监控 BNB。

### 币安站点

币安已分为 2 个站点，用户必须为其交易所使用正确的 CCXT 交易所 ID，否则 API 密钥将无法识别。

* [binance.com](https://www.binance.com/) - 国际用户。使用交易所 ID：`binance`。
* [binance.us](https://www.binance.us/) - 美国用户。使用交易所 ID：`binanceus`。

### 币安 RSA 密钥

Freqtrade 支持币安 RSA API 密钥。

我们建议将它们作为环境变量使用。

``` bash
export FREQTRADE__EXCHANGE__SECRET="$(cat ./rsa_binance.private)"
```

不过，它们也可以通过配置文件进行配置。由于 JSON 不支持多行字符串，您必须将所有换行符替换为 `\n` 才能拥有有效的 JSON 文件。

``` json
// ...
 "key": "<someapikey>",
 "secret": "-----BEGIN PRIVATE KEY-----\nMIIEvQIBABACAFQA<...>s8KX8=\n-----END PRIVATE KEY-----"
// ...
```

### 币安期货 (Binance Futures)

币安有特定且复杂的 [期货交易定量规则](https://www.binance.com/zh-CN/support/faq/4f462ebe6ff445d4a170be7d9e897272)，必须遵守这些规则，这些规则禁止对过多订单使用过低的筹码金额（stake-amount）。违反这些规则将导致交易限制。

在币安期货市场交易时，必须使用挂单簿，因为期货没有价格行情（ticker）数据。

``` jsonc
  "entry_pricing": {
      "use_order_book": true,
      "order_book_top": 1,
      "check_depth_of_market": {
          "enabled": false,
          "bids_to_ask_delta": 1
      }
  },
  "exit_pricing": {
      "use_order_book": true,
      "order_book_top": 1
  },
```

#### 币安逐仓期货设置

用户还必须将期货设置 "持仓模式（Position Mode）" 设置为 "单向持仓模式（One-way Mode）"，将 "资产模式（Asset Mode）" 设置为 "单资产模式（Single-Asset Mode）"。这些设置将在启动时进行检查，如果设置错误，Freqtrade 将显示错误。

![币安期货设置](assets/binance_futures_settings.png)

Freqtrade 不会尝试更改这些设置。

#### 币安 BNFCR 期货

BNFCR 模式是币安上的一种特殊期货模式，用于解决欧洲的合规性问题。
要使用 BNFCR 期货，您需要进行以下设置组合：

``` jsonc
{
    // ...
    "trading_mode": "futures",
    "margin_mode": "cross",
    "proxy_coin": "BNFCR",
    "stake_currency": "USDT" // 或 "USDC"
    // ...
}
```

`stake_currency` 设置定义了机器人将运行的市场。这一选择非常灵活。

在交易所端，您必须使用 "多资产模式（Multi-asset Mode）"，且 "持仓模式" 设置为 "单向持仓模式（One-way Mode）"。
Freqtrade 在启动时会检查这些设置，但不会尝试修改它们。

### Kraken 历史数据

Kraken API 仅提供 720 根历史 K 线，这对于 Freqtrade 的干跑（Dry-run）和实盘交易模式已经足够，但对于回测（Backtesting）来说是个问题。
要下载 Kraken 交易所的数据，使用 `--dl-trades` 是强制性的，否则机器人将一遍又一遍地下载相同的 720 根 K 线，您将没有足够的回测数据。

为了加快下载速度，您可以下载 Kraken 提供的 [交易成交 zip 文件](https://support.kraken.com/hc/en-us/articles/360047543791-Downloadable-historical-market-data-time-and-sales-)。
这些文件通常每季度更新一次。Freqtrade 期望这些文件被放置在 `user_data/data/kraken/trades_csv` 中。

如果使用增量文件，如下所示的结构可能是有意义的，"完整" 历史在一个目录中，增量文件在不同的目录中。这种模式的假设是数据已被下载并解压，且保持文件名不变。重复内容将被忽略（基于时间戳）——尽管假设是数据中没有缺口。

这意味着，如果您的 "完整" 历史在 2022 年第四季度结束，那么 2023 年第一季度和 2023 年第二季度的增量更新都应可用。如果没有这些，将导致数据不完整，从而在使用数据时得出无效的结果。

```
└── trades_csv
    ├── Kraken_full_history
    │   ├── BCHEUR.csv
    │   └── XBTEUR.csv
    ├── Kraken_Trading_History_Q1_2023
    │   ├── BCHEUR.csv
    │   └── XBTEUR.csv
    └── Kraken_Trading_History_Q2_2023
        ├── BCHEUR.csv
        └── XBTEUR.csv
```

您可以将这些文件转换为 Freqtrade 文件：

``` bash
freqtrade convert-trade-data --exchange kraken --format-from kraken_csv --format-to feather
# 将交易数据转换为不同的 OHLCV 时间范围
freqtrade trades-to-ohlcv -p BTC/EUR BCH/EUR --exchange kraken -t 1m 5m 15m 1h
```

转换后的数据也可以进行后续数据下载，下载将从加载的最后一笔交易之后开始。

``` bash
freqtrade download-data --exchange kraken --dl-trades -p BTC/EUR BCH/EUR 
```

!!! Warning "从 Kraken 下载数据"
    从 Kraken 下载数据将需要比任何其他交易所显著更多的内存 (RAM)，因为成交数据需要在您的机器上转换为 K 线。这也会耗费很长时间，因为 Freqtrade 需要下载该交易对/时间范围组合在交易所发生的所有每一笔交易，因此请耐心等待。

!!! Warning "频率限制调整（rateLimit tuning）"
    请注意，`rateLimit` 配置项持有的是请求之间的延迟（以毫秒为单位），而不是 每秒请求率（requests/sec rate）。因此，为了缓解 Kraken API “超出频率限制（Rate limit exceeded）”的异常，此配置应增加，而不是减少。

## 欧易 (OKX)

OKX 为每个 API 密钥都需要一个密码（passphrase），因此您需要将此密码添加到配置中，使您的交易所部分如下所示：

```json
"exchange": {
    "name": "okx",
    "key": "your_exchange_key",
    "secret": "your_exchange_secret",
    "password": "your_exchange_api_key_password",
    // ...
}
```

如果您在 OKX 上的注册域名是 `my.okx.com` (OKX EAA) —— 您将需要使用 `"myokx"` 作为交易所名称。使用错误的交易所名称将导致错误 "OKX Error 50119: API key doesn't exist" —— 因为两者是独立的实体。

!!! Warning "警告"
    OKX 在每次 API 调用中仅提供 100 根 K 线。因此，在回测模式下策略可用的数据量将相当低。

!!! Warning "期货"
    OKX 期货有 "持仓模式" 的概念 —— 可以是 "买/卖" 模式或 多/空（对冲模式）。Freqtrade 支持这两种模式（我们建议使用 买/卖 模式）—— 但在交易过程中更改模式是不受支持的，将导致异常和下达交易失败。OKX 也仅提供过去约 3 个月的标记价格（MARK）K 线。因此在该日期之前的期货回测会导致轻微的偏差，因为没有这些数据就无法正确计算资金费用（funding-fees）。

## 芝麻开门 (Gate.io)

!!! Tip "交易所止损 (Stoploss on Exchange)"
    Gate.io 支持 `stoploss_on_exchange` 并使用 `stop-loss-limit` 订单。它具有巨大的优势，因此我们建议通过启用交易所止损来从中受益。

Gate.io 支持 [生效时间策略 (time_in_force)](configuration.md#understand-order_time_in_force)，设置包括 "GTC"（成交为止有效）和 "IOC"（立即成交或取消）。

Gate.io 允许使用 `POINT` 抵扣费用。由于这并非一种可交易的货币（没有常规市场），自动费用计算将失败（默认费用为 0）。配置参数 `exchange.unknown_fee_rate` 可用于指定 Point 与筹码货币（stake currency）之间的汇率。显而易见，更改筹码货币也需要更改此值。

Gate API 密钥在您想要交易的市场类型之外，还需要以下权限：

* "现货交易 (Spot Trade)" _或_ "永续期货 (Perpetual Futures)" (允许读写)（要么两者都选，要么选择与您要交易的市场匹配的那一个）
* "钱包 (Wallet)" (只读)
* "账户 (Account)" (只读)

如果没有这些权限，机器人将无法正确启动并显示 "缺少权限 (permission missing)" 之类的错误。

## Bybit

!!! Tip "交易所止损 (Stoploss on Exchange)"
    Bybit（仅限期货）支持 `stoploss_on_exchange` 并使用 `stop-loss-limit` 订单。它具有巨大的优势，因此我们建议通过启用交易所止损来从中受益。

Bybit 支持 [生效时间策略 (time_in_force)](configuration.md#understand-order_time_in_force)，设置包括 "GTC"（成交为止有效）、"FOK"（全部成交或取消）、"IOC"（立即成交或取消）和 "PO"（只做 Maker）。

!!! Warning "统一账户"
    Freqtrade 假设账户是专门分配给机器人的。因此，我们建议为每个机器人使用一个子账户。在使用统一账户时这一点尤为重要。其他配置（一个账户上运行多个机器人，在机器人账户上进行手动非机器人交易）不受支持，并可能导致意外行为。

### Bybit 期货

Bybit 期货交易支持逐仓（isolated）期货模式。

启动时，Freqtrade 会将整个（子）账户的持仓模式设置为 "单向持仓模式（One-way Mode）"。这避免了反复进行此调用（减慢机器人运行），但也意味着手动更改此设置可能会导致异常和错误。

由于 Bybit 不提供资金费率历史，因此干跑计算结果也用于实盘交易。

进行实盘期货交易的 API 密钥必须具备以下权限：

* 读写 (Read-write)
* 合约 (Contract) —— 订单 (Orders)
* 合约 (Contract) —— 持仓 (Positions)

我们强烈建议将所有 API 密钥限制为您将要使用的 IP 访问。

## Hyperliquid

!!! Tip "交易所止损 (Stoploss on Exchange)"
    Hyperliquid 支持 `stoploss_on_exchange` 并使用 `stop-loss-limit` 订单。它具有巨大的优势，因此我们建议从中受益。

Hyperliquid 是一家去中心化交易所 (DEX)。去中心化交易所的工作方式与普通交易所略有不同。私有 API 调用不是使用 API 密钥进行身份验证，而是需要使用您钱包的私钥进行签名（我们建议为此使用专门生成的 API 钱包，可以在 Hyperliquid 上生成或在您选择的钱包中生成）。
其配置必须如下所示：

```json
"exchange": {
    "name": "hyperliquid",
    "walletAddress": "your_eth_wallet_address",  // 这里不应该是您的 API 钱包地址！
    "privateKey": "your_api_private_key",
    // ...
}
```

* `walletAddress` 为十六进制格式：`0x<40 位十六进制字符>` —— 可以轻松地从您的钱包复制 —— 且应该是您的主钱包地址，而不是 API 钱包地址。
* `privateKey` 为十六进制格式：`0x<64 位十六进制字符>` —— 使用 API 钱包在创建时显示的密钥。

Hyperliquid 在 Arbitrum One 链上处理充值和提现，这是一种建立在以太坊之上的 Layer 2 扩展方案。Hyperliquid 使用 USDC 作为报价货币/抵押品。在 Hyperliquid 上充值 USDC 的过程需要几个步骤，详情请参阅 [如何启动交易](https://hyperliquid.gitbook.io/hyperliquid-docs/onboarding/how-to-start-trading)。

!!! Note "Hyperliquid 一般用途说明"
    Hyperliquid 不支持市价单 (market orders)，但 CCXT 会通过下达最大滑点为 5% 的限价单来模拟市价单。不幸的是，Hyperliquid 仅提供 5000 根历史 K 线，因此回测要么需要历史积累 K 线（通过等待并随时间增量下载数据），要么将受限于最后的 5000 根 K 线。

!!! Info "一些常规最佳实践（不完全列举）"
    * 谨防供应链攻击，如 pip 包投毒等。无论何时使用私钥，请确保您的环境安全。
    * 不要使用您真正的主钱包私钥进行交易。使用 Hyperliquid [API 生成器](https://app.hyperliquid.xyz/API) 创建一个单独的 API 钱包。
    * 不要将您真实钱包的私钥存储在运行 Freqtrade 的服务器上。改用 API 钱包私钥。此密钥不允许提现，只能进行交易。
    * 始终保持您的助记词和私钥私密。
    * 不要使用与初始化硬件钱包时相同的助记词，使用相同的助记词基本上等于消除了硬件钱包的安全性。
    * 创建一个不同的软件钱包，仅将您想用于交易的资金转入该钱包，并使用该钱包在 Hyperliquid 上交易。
    * 如果您有不想用于交易的资金（例如在获利后），请将其转回您的硬件钱包。

### Hyperliquid 金库 (Vault) / 子账户 (Subaccount)

Hyperliquid 允许您创建金库或子账户。要在 Freqtrade 中使用这些功能，您需要使用以下配置模式：

``` json
"exchange": {
    "name": "hyperliquid",
    "walletAddress": "your_master_wallet_address", // 您的主钱包地址（不是 API 钱包地址，也不是金库/子账户地址）。
    "privateKey": "your_api_private_key", // API 钱包私钥 (见 https://app.hyperliquid.xyz/API)。您只需要私钥。
    "ccxt_config": {
        "options": {
            "vaultAddress": "your_vault_address", // 可选，仅当您想使用金库时 ...
            "subAccountAddress": "your_subaccount_address" // 或可选，仅当您想使用子账户时
        }
    },
    // ...
}
```

您的余额和交易现在将从您的金库 / 子账户中使用，而不再是从您的主账户中使用。

!!! Note "注意"
    您只能使用金库或子账户中的一个 —— 不能同时使用。

### Hyperliquid 历史数据

Hyperliquid API 除单次请求获取当前数据外不提供历史数据，因此下载历史数据是不可能的，因为下载下来的数据不构成正式的历史数据。

### HIP-3 DEX 交易

Hyperliquid 支持 HIP-3 去中心化交易所 (DEX)，它们是建立在 Hyperliquid 基础设施之上的独立交易所。这些 DEX 操作方式与 Hyperliquid 主站类似，但由社区创建和管理。

要在 Freqtrade 中交易 HIP-3 DEX，您需要在配置中使用 `hip3_dexes` 参数添加它们：

```json
"exchange": {
    "name": "hyperliquid",
    "walletAddress": "your_master_wallet_address",
    "privateKey": "your_api_private_key",
    "hip3_dexes": ["dex_name_1", "dex_name_2"]
}
```

将 `"dex_name_1"` 和 `"dex_name_2"` 替换为您想要交易的 HIP-3 DEX 的实际名称（例如 `vntl` 和 `xyz`）。

!!! Warning "性能和频率限制影响"
    添加每个 HIP-3 DEX 都会显著影响机器人性能和频率限制。

    * **额外的 API 调用**：对于配置的每个 HIP-3 DEX，Freqtrade 都需要进行额外的 API 调用。
    * **频率限制压力**：额外的 API 调用计入 Hyperliquid 严格的频率限制。使用多个 DEX，您可能会更快达到频率限制，或者由于强制延迟而导致机器人运行变慢。

    请仅添加您正在积极交易的 HIP-3 DEX。监控您的日志以识别频率限制警告或运行变慢的迹象，并相应地调整配置。不同的 HIP-3 DEX 也可能使用不同的报价货币 —— 因此请确保仅添加与您的筹码货币兼容的 DEX，以避免不必要的延迟。

!!! Note "注意"
    HIP-3 DEX 共享与 Hyperliquid 主账户相同的钱包和抵押品。在不同的 DEX 上进行的交易将影响您的总体账户余额和保证金。

## Bitvavo

如果您的账户需要使用 `operatorId`，可以按如下方式在配置文件中设置：

``` json
"exchange": {
        "name": "bitvavo",
        "key": "",
        "secret": "",
        "ccxt_config": {
            "options": {
                "operatorId": "123567"
            }
        },
   }
```

Bitvavo 期望 `operatorId` 为整数。

### 获取最新价格 / 不完整的 K 线

大多数交易所通过其 OHLCV/klines API 接口返回当前不完整的 K 线。
缺省情况下，Freqtrade 假设从交易所获取了不完整的 K 线，并假定最后一根 K 线是不完整的从而将其移除。

您的交易所是否返回不完整 K 线，可以使用贡献者文档中的[辅助脚本](developer.md#incomplete-candles)进行检查。

由于存在重绘（Repainting）的危险，Freqtrade 不允许您使用这种不完整的 K 线。
