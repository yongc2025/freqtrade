# 策略自定义

本页面说明如何自定义策略、添加新指标以及设置交易规则。

如果您还没有阅读过以下内容，请先熟悉它们：

- [Freqtrade 策略 101](strategy-101.md)：提供策略开发的快速入门。
- [Freqtrade 机器人基础](bot-basics.md)：提供机器人运作的总体信息。

## 开发您自己的策略

机器人包含一个默认的策略文件。

此外，在 [策略仓库](https://github.com/freqtrade/freqtrade-strategies) 中还有其他几种策略可供参考。

不过，您很可能对自己想要什么样的策略有自己的想法。

本文档旨在帮助您将想法转化为可运行的策略。

### 生成策略模板

要开始开发，您可以使用以下命令：

```bash
freqtrade new-strategy --strategy AwesomeStrategy
```

这将基于模板创建一个名为 `AwesomeStrategy` 的新策略，其文件位于 `user_data/strategies/AwesomeStrategy.py`。

!!! Note "注意"
    策略的 *名称* 与文件名是有区别的。在大多数命令中，Freqtrade 使用策略的 *名称*，而不是文件名。

!!! Note "注意"
    `new-strategy` 命令生成的示例在开箱即用时通常不会盈利。

??? Hint "提示：不同的模板级别"
    `freqtrade new-strategy` 有一个额外的参数 `--template`，用于控制创建策略时预置的信息量。使用 `--template minimal` 可获得一个没有任何指标示例的空策略，使用 `--template advanced` 则可获得包含更多复杂功能定义的模板。

### 策略剖析

一个策略文件包含了构建策略逻辑所需的所有信息：

- OHLCV 格式的 K 线数据
- 指标 (Indicators)
- 入场逻辑 (Entry logic)
  - 信号 (Signals)
- 出场逻辑 (Exit logic)
  - 信号 (Signals)
  - 最小 ROI (Minimal ROI)
  - 回调函数 ("custom functions")
- 止损 (Stoploss)
  - 固定/绝对止损
  - 追踪止损 (Trailing)
  - 回调函数 ("custom functions")
- 定价 [可选]
- 仓位调整 (Position adjustment) [可选]

机器人包含一个名为 `SampleStrategy` 的示例策略，您可以将其作为基础：`user_data/strategies/sample_strategy.py`。
您可以使用以下参数进行测试：`--strategy SampleStrategy`。请记住，您使用的是策略类名，而不是文件名。

此外，还有一个名为 `INTERFACE_VERSION` 的属性，它定义了机器人应使用的策略接口版本。
当前版本为 3 - 如果在策略中未显式设置，则默认为版本 3。

您可能会看到旧策略设置为接口版本 2，这些策略需要更新为 v3 的术语，因为未来的版本将要求必须设置此项。

使用 `trade` 命令以干跑或实盘模式启动机器人：

```bash
freqtrade trade --strategy AwesomeStrategy
```

### 机器人模式

Freqtrade 策略可以由 Freqtrade 机器人在 5 种主要模式下处理：

- 回测 (backtesting)
- 超参数优化 (hyperopting)
- 干跑 ("forward testing")
- 实盘 (live)
- FreqAI (此处未涵盖)

请查看 [配置文档](configuration.md) 了解如何将机器人设置为干跑或实盘模式。

**在测试时务必使用干跑模式，因为它可以让您了解策略在现实中运行的情况，而无需承担资金风险。**

## 深入探索

**接下来的部分我们将使用 [user_data/strategies/sample_strategy.py](https://github.com/freqtrade/freqtrade/blob/develop/freqtrade/templates/sample_strategy.py) 文件作为参考。**

!!! Note "注意：策略与回测"
    为了避免回测与干跑/实盘模式之间出现问题和意外差异，请注意，在回测期间，完整的运行时间范围会一次性传递给 `populate_*()` 方法。
    因此，最好使用向量化操作（针对整个 DataFrame，而不是通过循环），并避免索引引用（如 `df.iloc[-1]`），而是使用 `df.shift()` 来访问前一个 K 线。

!!! Warning "警告：使用未来数据"
    由于回测将完整的时间范围传递给 `populate_*()` 方法，策略作者需要注意避免策略利用来自未来的数据。
    本文档的 [策略开发常见错误](#策略开发中的常见错误) 章节列出了一些常见的避坑模式。

??? Hint "提示：前瞻与递归分析"
    Freqtrade 包含两个有用的命令来评估常见的前瞻（使用未来数据）和递归偏差（指标值方差）问题。在以干跑或实盘模式运行策略之前，您应始终先运行这些命令。请查看 [前瞻分析](lookahead-analysis.md) 和 [递归分析](recursive-analysis.md) 的相关文档。

### Dataframe (数据帧)

Freqtrade 使用 [pandas](https://pandas.pydata.org/) 来存储和提供 K 线 (OHLCV) 数据。
Pandas 是一个专门为处理表格格式的大量数据而开发的优秀库。

DataFrame 中的每一行对应图表上的一个 K 线，最新的完整 K 线始终位于 DataFrame 的最后（按日期排序）。

如果我们使用 pandas 的 `head()` 函数查看主 DataFrame 的前几行，可以看到：

```output
> dataframe.head()
                       date      open      high       low     close     volume
0 2021-11-09 23:25:00+00:00  67279.67  67321.84  67255.01  67300.97   44.62253
1 2021-11-09 23:30:00+00:00  67300.97  67301.34  67183.03  67187.01   61.38076
2 2021-11-09 23:35:00+00:00  67187.02  67187.02  67031.93  67123.81  113.42728
3 2021-11-09 23:40:00+00:00  67123.80  67222.40  67080.33  67160.48   78.96008
4 2021-11-09 23:45:00+00:00  67160.48  67160.48  66901.26  66943.37  111.39292
```

DataFrame 是一个表格，其列不是单个值，而是一系列数据。因此，像下面这样的简单 python 比较是行不通的：

``` python
    if dataframe['rsi'] > 30:
        dataframe['enter_long'] = 1
```

以上部分将报错 `The truth value of a Series is ambiguous [...]`。

相反，这必须以兼容 pandas 的方式编写，以便操作在整个 DataFrame 上执行，即“向量化 (vectorisation)”。

``` python
    dataframe.loc[
        (dataframe['rsi'] > 30)
    , 'enter_long'] = 1
```

通过这部分代码，您的 DataFrame 中就有了一个新列，每当 RSI 大于 30 时，该列就被赋值为 `1`。

Freqtrade 使用这个新列作为入场信号，并假设交易随后将在下一个开盘 K 线开仓。

Pandas 提供了快速计算指标的方法，即“向量化”。为了从这种速度中获益，建议不使用循环，而是使用向量化方法。

向量化操作在整个数据范围内执行计算，因此与循环遍历每一行相比，在计算指标时要快得多。

??? Hint "提示：信号 vs 交易"
    - 信号是在 K 线收盘时由指标生成的，表示入场交易的意图。
    - 交易是已执行的订单（在实盘模式下的交易所），交易将尽可能接近下一个 K 线开盘时开仓。

!!! Warning "警告：交易订单假设"
    在回测中，信号在 K 线收盘时生成。交易随后立即在下一个 K 线开盘时发起。

    在干跑和实盘中，这可能会有所延迟，因为需要先分析所有交易对的 DataFrame，然后再处理每个交易对的交易。这意味着在干跑/实盘中，您需要注意尽可能减少计算延迟，通常的做法是运行较少数量的交易对，并使用具有良好时钟频率的 CPU。

#### 为什么我看不到“实时”K 线数据？

Freqtrade 不会在 DataFrame 中存储不完整/未完成的 K 线。

使用不完整的数据做出的策略决策被称为“重绘 (repainting)”，您可能会看到其他平台允许这样做。

Freqtrade 则不然。DataFrame 中仅提供已完成/结束的 K 线数据。

### 自定义指标

入场和出场信号需要指标。您可以通过扩展策略文件中 `populate_indicators()` 方法包含的列表来添加更多指标。

您应该只添加在 `populate_entry_trend()`、`populate_exit_trend()` 或用于填充另一个指标时所用到的指标，否则性能可能会受到影响。

重要的是始终从这三个函数返回 DataFrame，不要删除或修改 `"open", "high", "low", "close", "volume"` 这些列，否则这些字段可能会包含意外的内容。

示例：

```python
def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
    """
    向给定的 DataFrame 添加几种不同的 TA 指标

    性能说明：为了获得最佳性能，请节约使用指标的数量。
    仅取消注释您在策略或超参数优化配置中使用的指标，否则会浪费内存和 CPU 使用率。
    :param dataframe: 来自交易所数据的 Dataframe
    :param metadata: 附加信息，如当前交易的交易对
    :return: 包含所有策略必选指标的 Dataframe
    """
    dataframe['sar'] = ta.SAR(dataframe)
    dataframe['adx'] = ta.ADX(dataframe)
    stoch = ta.STOCHF(dataframe)
    dataframe['fastd'] = stoch['fastd']
    dataframe['fastk'] = stoch['fastk']
    dataframe['bb_lower'] = ta.BBANDS(dataframe, nbdevup=2, nbdevdn=2)['lowerband']
    dataframe['sma'] = ta.SMA(dataframe, timeperiod=40)
    dataframe['tema'] = ta.TEMA(dataframe, timeperiod=9)
    dataframe['mfi'] = ta.MFI(dataframe)
    dataframe['rsi'] = ta.RSI(dataframe)
    dataframe['ema5'] = ta.EMA(dataframe, timeperiod=5)
    dataframe['ema10'] = ta.EMA(dataframe, timeperiod=10)
    dataframe['ema50'] = ta.EMA(dataframe, timeperiod=50)
    dataframe['ema100'] = ta.EMA(dataframe, timeperiod=100)
    dataframe['ao'] = awesome_oscillator(dataframe)
    macd = ta.MACD(dataframe)
    dataframe['macd'] = macd['macd']
    dataframe['macdsignal'] = macd['macdsignal']
    dataframe['macdhist'] = macd['macdhist']
    hilbert = ta.HT_SINE(dataframe)
    dataframe['htsine'] = hilbert['sine']
    dataframe['htleadsine'] = hilbert['leadsine']
    dataframe['plus_dm'] = ta.PLUS_DM(dataframe)
    dataframe['plus_di'] = ta.PLUS_DI(dataframe)
    dataframe['minus_dm'] = ta.MINUS_DM(dataframe)
    dataframe['minus_di'] = ta.MINUS_DI(dataframe)

    # 记得始终返回 dataframe
    return dataframe
```

!!! Note "想要更多指标示例？"
    请查看 [user_data/strategies/sample_strategy.py](https://github.com/freqtrade/freqtrade/blob/develop/freqtrade/templates/sample_strategy.py)。
    然后取消注释您需要的指标。

### 策略启动期 (Startup period)

某些指标具有不稳定的启动期，在此期间没有足够的 K 线数据来计算任何值 (NaN)，或者计算结果不正确。这可能会导致不一致，因为 Freqtrade 不知道这个不稳定期有多长，并直接使用 DataFrame 中的任何指标值。

为了解决这个问题，可以为策略分配 `startup_candle_count` 属性。

这应该设置为策略计算稳定指标所需的最大 K 线数量。如果用户包含具有提示交易对（informative pairs）的高时间范围，`startup_candle_count` 不一定随之改变。该值是任何提示性时间范围计算稳定指标所需的最大周期（以 K 线为单位）。

您可以使用 [递归分析](recursive-analysis.md) 来检查并找到要使用的正确 `startup_candle_count`。当递归分析显示方差为 0% 时，您就可以确定拥有足够的启动 K 线数据。

在此示例策略中，应将其设置为 400 (`startup_candle_count = 400`)，因为 ema100 计算需要 400 根 K 线历史才能确保数值正确。

``` python
    dataframe['ema100'] = ta.EMA(dataframe, timeperiod=100)
```

通过让机器人知道需要多少历史数据，回测交易可以在回测和超参数优化期间指定的计时范围内启动。

!!! Warning "警告：使用 X 次调用获取 OHLCV"
    如果您收到类似 `WARNING - Using 3 calls to get OHLCV. This can result in slower operations for the bot. Please check if you really need 1500 candles for your strategy` 的警告，您应该考虑是否真的需要这么多历史数据来产生信号。
    这样做会导致 Freqtrade 对同一交易对进行多次调用，这显然比一次网络请求要慢。
    结果是 Freqtrade 刷新 K 线的时间会变长，因此应尽可能避免。
    此项被限制为总共 5 次调用，以避免交易所过载或使 Freqtrade 运行太慢。

!!! Warning "警告"
    `startup_candle_count` 应低于 `ohlcv_candle_limit * 5`（大多数交易所为 500 * 5）—— 因为在干跑/实盘交易操作期间仅提供此数量的 K 线。

#### 示例

让我们尝试使用带有 EMA100 的示例策略回测 1 个月（2019 年 1 月）的 5 分钟 K 线。

``` bash
freqtrade backtesting --timerange 20190101-20190201 --timeframe 5m
```

假设 `startup_candle_count` 设置为 400，回测程序知道它需要 400 根 K 线来生成有效的入场信号。它将加载从 `20190101 - (400 * 5m)` 开始的数据，即大约 2018-12-30 11:40:00 之后的数据。

如果此数据可用，指标将使用此扩展的计时范围进行计算。不稳定的启动期（直到 2019-01-01 00:00:00）随后将在执行回测之前被移除。

!!! Note "注意：启动期 K 线数据不可用"
    如果启动期的数据不可用，则计时范围将针对此启动期进行调整。在我们的示例中，回测将从 2019-01-02 09:20:00 开始。

### 入场信号规则

编辑策略文件中的 `populate_entry_trend()` 方法以更新您的入场策略。

重要的是始终返回 DataFrame，不要删除或修改 `"open", "high", "low", "close", "volume"` 指标列，否则这些字段可能会包含意外内容。策略可能会因此产生无效值或完全停止工作。

此方法还将定义一个新列 `"enter_long"`（对于做空为 `"enter_short"`），入场时需包含 `1`，"无操作"为 `0`。`enter_long` 是必填列，即使策略仅进行做空也必须设置。

您可以使用 `"enter_tag"` 列为您入场信号命名，这有助于以后调试和评估您的策略。

来自 `user_data/strategies/sample_strategy.py` 的示例：

```python
def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
    """
    根据 TA 指标填充给定 Dataframe 的买入信号
    :param dataframe: 已填充指标的 DataFrame
    :param metadata: 附加信息，如当前交易的交易对
    :return: 带有 buy 列的 DataFrame
    """
    dataframe.loc[
        (
            (qtpylib.crossed_above(dataframe['rsi'], 30)) &  # 信号：RSI 向上穿越 30
            (dataframe['tema'] <= dataframe['bb_middleband']) &  # 过滤条件
            (dataframe['tema'] > dataframe['tema'].shift(1)) &  # 过滤条件
            (dataframe['volume'] > 0)  # 确保成交量不为 0
        ),
        ['enter_long', 'enter_tag']] = (1, 'rsi_cross')

    return dataframe
```

??? Note "做空交易入场"
    做空入场可以通过设置 `enter_short`（对应做多交易的 `enter_long`）来创建。
    `enter_tag` 列保持相同。
    做空需要您的交易所和市场配置的支持！
    此外，如果您打算做空，请确保在策略中适当设置 [`can_short`](#可以做空)。

    ```python
    # 允许做多和做空交易
    can_short = True

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        dataframe.loc[
            (
                (qtpylib.crossed_above(dataframe['rsi'], 30)) &  # 信号：RSI 向上穿越 30
                (dataframe['tema'] <= dataframe['bb_middleband']) &  # 过滤条件
                (dataframe['tema'] > dataframe['tema'].shift(1)) &  # 过滤条件
                (dataframe['volume'] > 0)  # 确保成交量不为 0
            ),
            ['enter_long', 'enter_tag']] = (1, 'rsi_cross')

        dataframe.loc[
            (
                (qtpylib.crossed_below(dataframe['rsi'], 70)) &  # 信号：RSI 向下穿越 70
                (dataframe['tema'] > dataframe['bb_middleband']) &  # 过滤条件
                (dataframe['tema'] < dataframe['tema'].shift(1)) &  # 过滤条件
                (dataframe['volume'] > 0)  # 确保成交量不为 0
            ),
            ['enter_short', 'enter_tag']] = (1, 'rsi_cross')

        return dataframe
    ```

!!! Note "注意"
    买入需要有卖家可买。因此成交量需要 > 0 (`dataframe['volume'] > 0`)，以确保机器人不在无交易活动期间买入/卖出。

### 出场信号规则

在策略文件中编辑 `populate_exit_trend()` 方法以更新您的出场策略。

通过在配置或策略中将 `use_exit_signal` 设置为 false，可以抑制出场信号。

`use_exit_signal` 不会影响 [信号冲突规则](#冲突的信号) - 这些规则仍将适用并可能阻止入场。

重要的是始终返回 DataFrame，不要删除或修改 `"open", "high", "low", "close", "volume"` 指标列，否则这些字段可能会包含意外的内容。策略可能会产生无效值或完全停止工作。

此方法还将定义一个新列 `"exit_long"`（对于做空为 `"exit_short"`），出场时需包含 `1`，"无操作"为 `0`。

您可以使用 `"exit_tag"` 列为您的出场信号命名，这有助于以后调试和评估。

来自 `user_data/strategies/sample_strategy.py` 的示例：

```python
def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
    """
    根据 TA 指标，填充给定 Dataframe 的出场信号
    :param dataframe: 已填充指标的 DataFrame
    :param metadata: 附加信息，如当前交易的交易对
    :return: 带有 buy 列的 DataFrame
    """
    dataframe.loc[
        (
            (qtpylib.crossed_above(dataframe['rsi'], 70)) &  # 信号：RSI 向上穿越 70
            (dataframe['tema'] > dataframe['bb_middleband']) &  # 过滤条件

            (dataframe['volume'] > 0)  # 确保成交量不为 0

        ['exit_long', 'exit_tag']] = (1, 'rsi_too_high')
    return dataframe
```

    `exit_tag` 列保持相同。
    做空需要您的交易所和市场配置支持！
    此外，如果您打算做空，请确保在策略中适当设置 [`can_short`](#可以做空)。

    ```python
                (dataframe['tema'] > dataframe['tema'].shift(1)) &  # 过滤条件
                (dataframe['volume'] > 0)  # 确保成交量不为 0

            ['exit_short', 'exit_tag']] = (1, 'rsi_too_low')
    ```

### 最小 ROI (Minimal ROI)

`minimal_roi` 策略变量定义了一笔交易在出场之前应达到的最小投资回报率 (ROI)，独立于出场信号。

其格式如下，即一个 python `dict`，键（冒号左侧）是交易开启后经过的分钟数，值（冒号右侧）是百分比。

```python
minimal_roi = {
    "40": 0.0,
    "30": 0.01,
    "20": 0.02,
    "0": 0.04
}
```

因此，上述配置意味着：

- 只要盈利达到 4% 就出场
- 盈利达到 2% 时出场（交易 20 分钟后生效）
- 盈利达到 1% 时出场（交易 30 分钟后生效）
- 交易持平（无亏损）时出场（交易 40 分钟后生效）

计算中包含手续费。

#### 禁用最小 ROI

要完全禁用 ROI，请将其设置为空字典：

```python
minimal_roi = {}
```

#### 在最小 ROI 中使用计算

若要使用基于 K 线时长（时间范围）的时间，可以使用以下代码段。

这将允许您更改策略的时间范围，但最小 ROI 时间仍将设置为 K 线数量，例如在 3 个 K 线之后。

``` python
from freqtrade.exchange import timeframe_to_minutes

class AwesomeStrategy(IStrategy):

    timeframe = "1d"
    timeframe_mins = timeframe_to_minutes(timeframe)
    minimal_roi = {
        "0": 0.05,                      # 前 3 个 K 线为 5%
        str(timeframe_mins * 3): 0.02,  # 3 个 K 线后为 2%
        str(timeframe_mins * 6): 0.01,  # 6 个 K 线后为 1%
    }
```

??? info "无法立即成交的订单"
    `minimal_roi` 将以 `trade.open_date` 作为参考，即交易初始化的时间，也就是为该交易下达第一个订单的时间。
    这也适用于无法立即成交的限价单（通常通过 `custom_entry_price()` 与“非当前价格”结合使用），以及初始订单价格通过 `adjust_entry_price()` 被替换的情况。
    所用的时间仍将来自初始的 `trade.open_date`（第一个订单下达的时间），而不是新下达或调整后的订单日期。

### 止损 (Stoploss)

强烈建议设置止损以保护您的资金免受剧烈反向波动的损失。

设置 10% 止损的示例：

``` python
stoploss = -0.10
```

有关止损功能的完整文档，请参阅专门的 [止损页面](stoploss.md)。

### 时间范围 (Timeframe)

这是机器人应在策略中使用的 K 线周期。

常见值为 `"1m", "5m", "15m", "1h"`，不过您的交易所支持的所有值都应该有效。

请注意，相同的入场/出场信号在一个时间范围内可能表现良好，但在其他时间范围内可能表现不佳。

此设置可在策略方法中通过 `self.timeframe` 属性访问。

### 可以做空 (Can short)

要在期货市场使用做空信号，您必须设置 `can_short = True`。

开启此设置的策略将无法在现货市场加载。

如果您在 `enter_short` 列中有 `1` 值以发出做空信号，但设置 `can_short = False`（默认值），则意味着这些做空信号将被忽略，即使您在配置中指定了期货市场。

### Metadata 字典

`metadata` 字典（在 `populate_entry_trend`, `populate_exit_trend`, `populate_indicators` 中可用）包含附加信息。
目前这包含 `pair`，可以通过 `metadata['pair']` 访问，它将返回 `XRP/BTC` 格式（期货市场为 `XRP/BTC:BTC`）的交易对。

metadata 字典不应被修改，且不会在策略的多个函数之间持久化信息。

相反，请查看 [存储信息](strategy-advanced.md#storing-information-persistent) 章节。

## 提示交易对 (Informative Pairs)

### 获取非交易对的数据

某些策略可以从额外提示对（参考对）的数据中获益，以便查看更宽时间范围的数据。

这些对的 OHLCV 数据将作为常规白名单刷新过程的一部分被下载，并可通过 `DataProvider` 访问（见下文）。

除非这些对也在交易对白名单中指定，或者被动态白名单（例如 `VolumePairlist`）选中，否则它们将 **不会** 被交易。

这些对需要指定为元组，格式为 `("pair", "timeframe")`，pair 为第一个参数，timeframe 为第二个参数。

示例：

``` python
def informative_pairs(self):
    return [("ETH/USDT", "5m"),
            ("BTC/TUSD", "15m"),
            ]
```

完整的示例可以在 [DataProvider 章节](#完整的-dataprovider-示例)中找到。

!!! Warning "警告"
    由于这些对将作为常规白名单刷新的一部分进行刷新，因此最好保持该列表简短。
    只要在所使用的交易所上可用（且处于活跃状态），就可以指定所有时间范围和所有对。
    不过，尽可能使用重采样（resampling）到更长的时间范围会更好，以避免对交易所发起过多请求，从而面临被封锁的风险。

??? Note "另一种 K 线类型"
    Informative_pairs 还可以提供第 3 个元组元素，显式定义 K 线类型。
    可选的 K 线类型取决于交易模式和交易所。
    通常，现货对不能在期货市场使用，期货 K 线也不能作为现货机器人的提示对。
    这方面的细节可能有所不同，如果有变化，可以在交易所文档中找到。

    ``` python
    def informative_pairs(self):
        return [
            ("ETH/USDT", "5m", ""),   # 使用默认 K 线类型，取决于 trading_mode（推荐）
            ("ETH/USDT", "5m", "spot"),   # 强制使用现货 K 线（仅对比现货市场上运行的机器人有效）。
            ("BTC/TUSD", "15m", "futures"),  # 使用期货 K 线（仅限 `trading_mode=futures` 的机器人）
            ("BTC/TUSD", "15m", "mark"),  # 使用标记价格 K 线（仅限 `trading_mode=futures` 的机器人）
        ]
    ```
***

### 提示对装饰器 (`@informative()`)

为了方便定义提示对，请使用 `@informative` 装饰器。所有带装饰器的 `populate_indicators_*` 方法都是隔离运行的，无法访问来自其他提示对的数据。但是，每个对的所有提示数据帧都会合并并传递给主 `populate_indicators()` 方法。

!!! Note "注意"
    如果您在生成一个提示对时需要使用来自另一个提示对的数据，请不要使用 `@informative` 装饰器。相反，请按照 [DataProvider 章节](#完整的-dataprovider-示例) 所述手动定义提示对。

进行超参数优化时，不支持使用超参数优化参数的 `.value` 属性。请使用 `.range` 属性。有关更多信息，请参阅 [优化指标参数](hyperopt.md#优化指标参数)。

??? info "完整文档"
    ``` python
    def informative(
        timeframe: str,
        asset: str = "",
        fmt: str | Callable[[Any], str] | None = None,
        *,
        candle_type: CandleType | str | None = None,
        ffill: bool = True,
    ) -> Callable[[PopulateIndicators], PopulateIndicators]:
        """
        populate_indicators_Nn(self, dataframe, metadata) 的装饰器，
        允许这些函数定义提示指标。

        用法示例：

            @informative('1h')
            def populate_indicators_1h(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
                dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
                return dataframe

        :param timeframe: 提示性时间范围。必须始终等于或高于策略时间范围。
        :param asset: 提示性资产，例如 BTC, BTC/USDT, ETH/BTC。如果不指定，则使用当前交易对。
                    还支持有限的交易对格式字符串（见下文）。
        :param fmt: 列格式 (str) 或列格式化器 (callable(name, asset, timeframe))。
                    未指定时，默认为：
        * 如果指定了 asset，则为 {base}_{quote}_{column}_{timeframe}。
        * 如果未指定 asset，则为 {column}_{timeframe}。
        交易对格式支持这些格式变量：
        * {base} - 小写的基准货币，例如 'eth'。
        * {BASE} - 与 {base} 相同，但为大写。
        * {quote} - 小写的报价货币，例如 'usdt'。
        * {QUOTE} - 与 {quote} 相同，但为大写。
        格式字符串还支持这些变量：
        * {asset} - 资产的全名，例如 'BTC/USDT'。
        * {column} - dataframe 列名。
        * {timeframe} - 提示 dataframe 的时间范围。
        :param ffill: 合并提示对后对 dataframe 执行向后填充 (ffill)。
        :param candle_type: '', mark, index, premiumIndex, 或 funding_rate
        """
    ```

??? Example "定义提示对的快捷方式"

    大多数情况下，我们不需要 `merge_informative_pair()` 提供的功能和灵活性，因此我们可以使用装饰器快速定义提示对。

    ``` python

    from datetime import datetime
    from freqtrade.persistence import Trade
    from freqtrade.strategy import IStrategy, informative

    class AwesomeStrategy(IStrategy):

        # 这个方法不是必需的。
        # def informative_pairs(self): ...

        # 为每一对定义提示性的高时间范围。装饰器可以叠加在同一方法上。
        # 在 populate_indicators 中可以作为 'rsi_30m' 和 'rsi_1h' 使用。
        @informative('30m')
        @informative('1h')
        def populate_indicators_1h(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
            return dataframe

        # 定义 BTC/STAKE 提示对。在 populate_indicators 及其他方法中可作为 'btc_rsi_1h' 使用。
        # 当前结算货币应指定为 {stake} 格式变量，而不是硬编码实际数值。
        # 在 populate_indicators 及其他方法中可作为 'btc_usdt_rsi_1h' 使用（当 stake 为 USDT 时）。
        @informative('1h', 'BTC/{stake}')
        def populate_indicators_btc_1h(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
            return dataframe

        # 定义 BTC/ETH 提示对。如果报价货币与结算货币不同，则必须指定它。
        # 在 populate_indicators 及其他方法中可作为 'eth_btc_rsi_1h' 使用。
        @informative('1h', 'ETH/BTC')
        def populate_indicators_eth_btc_1h(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
            return dataframe

        # 定义 BTC/STAKE 提示对。可以指定自定义格式化程序来格式化列名。
        # 可以指定一个回调函数 `fmt(**kwargs) -> str` 来实现自定义格式化。
        # 在 populate_indicators 及其他方法中可作为 'rsi_upper_1h' 使用。
        @informative('1h', 'BTC/{stake}', '{column}_{timeframe}')
        def populate_indicators_btc_1h_2(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            dataframe['rsi_upper'] = ta.RSI(dataframe, timeperiod=14)
            return dataframe

        def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            # 当前交易对策略时间范围内的指标。
            dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
            # 提示对在该方法中可用。
            dataframe['rsi_less'] = dataframe['rsi'] < dataframe['rsi_1h']
            return dataframe

    ```

!!! Note "注意"
    访问其他交易对的提示 Dataframe 时使用字符串格式化。这将允许您在配置中轻松更改结算货币，而无需调整策略代码。

    ``` python
    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        stake = self.config['stake_currency']
        dataframe.loc[
            (
                (dataframe[f'btc_{stake}_rsi_1h'] < 35)
                &
                (dataframe['volume'] > 0)
            ),
            ['enter_long', 'enter_tag']] = (1, 'buy_signal_rsi')

        return dataframe
    ```

    或者可以使用列重命名来从列名中删除结算货币：`@informative('1h', 'BTC/{stake}', fmt='{base}_{column}_{timeframe}')`。

!!! Warning "警告：方法名称重复"
    标记为 `@informative()` 装饰器的方法必须始终具有唯一的名称！由于 Python 编程语言的限制，重复使用相同的名称（例如在复制粘贴已定义的提示性方法时）将覆盖先前定义的方法，且不产生任何错误。在这种情况下，您会发现策略文件中位置较高的方法中创建的指标在 Dataframe 中不可用。请仔细检查方法名称，确保它们是唯一的！

### *merge_informative_pair()*

此方法可帮助您安全一致地将提示对合并到常规主 Dataframe 中，且不会产生前瞻偏差。

选项：

- 重命名列以创建唯一列
- 合并 Dataframe 且无前瞻偏差
- 向后填充 (forward-fill) [可选]

有关完整示例，请参阅下面的 [完整的数据提供者示例](#完整的-dataprovider-示例)。

提示 Dataframe 的所有列都将以重命名的形式在返回的 Dataframe 中可用：

!!! Example "列名替换示例"
    假设 `inf_tf = '1d'`，结果列将为：

    ``` python
    'date', 'open', 'high', 'low', 'close', 'rsi'                     # 来自原 dataframe
    'date_1d', 'open_1d', 'high_1d', 'low_1d', 'close_1d', 'rsi_1d'   # 来自提示性 dataframe
    ```

??? Example "列名替换 - 1h 示例"
    假设 `inf_tf = '1h'`，结果列将为：

    ``` python
    'date', 'open', 'high', 'low', 'close', 'rsi'                     # 来自原 dataframe
    'date_1h', 'open_1h', 'high_1h', 'low_1h', 'close_1h', 'rsi_1h'   # 来自提示性 dataframe
    ```

??? Example "自定义实现"
    此项功能的自定义实现是可行的，可以按如下方式完成：

    ``` python

    # 将日期偏移 1 个 K 线
    # 这是必需的，因为数据始终是“开盘日期”
    # 哪怕是 12:15 开始的 15 分钟 K 线也不应知道从 12:00 到 13:00 的 1 小时 K 线收盘价
    minutes = timeframe_to_minutes(inf_tf)
    # 仅当时间范围不同时才这样做：
    informative['date_merge'] = informative["date"] + pd.to_timedelta(minutes, 'm')

    # 重命名列以确保唯一
    informative.columns = [f"{col}_{inf_tf}" for col in informative.columns]
    # 假设 inf_tf = '1d' - 那么列名将变为：
    # date_1d, open_1d, high_1d, low_1d, close_1d, rsi_1d

    # 合并 2 个 dataframe
    # 提示性样本上的所有指标必须在此之前计算完成
    dataframe = pd.merge(dataframe, informative, left_on='date', right_on=f'date_merge_{inf_tf}', how='left')
    # FFill（向后填充）以使 1d 值在全天每一行中可用。
    # 如果不这样做，比较每天只能生效一次。
    dataframe = dataframe.ffill()

    ```

!!! Warning "警告：提示时间范围 < 策略时间范围"
    不推荐使用小于主 Dataframe 时间范围的提示时间范围，因为这样无法利用这些额外信息。
    要正确使用更详细的信息，需要应用更高级的方法（这超出了本文档的范围）。

## 附加数据 (DataProvider)

策略提供了对 `DataProvider` 的访问。这允许您在策略中使用额外的数据。

所有方法在失败的情况下都返回 `None`，即失败不会引发异常。

请务必检查运行模式以选择正确的方法获取数据（见下文示例）。

!!! Warning "超参数优化的局限性"
    DataProvider 在超参数优化（hyperopt）期间可用，但它只能在 **策略中** 的 `populate_indicators()` 中使用，而不能在 hyperopt 类文件中使用。
    它在 `populate_entry_trend()` 和 `populate_exit_trend()` 方法中也不可用。

### DataProvider 的可选选项

- [`available_pairs`](#available_pairs) - 列出缓存交易对及其时间范围 (pair, timeframe) 的元组属性。
- [`current_whitelist()`](#current_whitelist) - 返回当前的白名单对。有助于访问动态白名单（即 VolumePairlist）。
- [`get_pair_dataframe(pair, timeframe)`](#get_pair_dataframepair-timeframe) - 这是一个通用方法，返回历史数据（用于回测）或缓存的实盘数据（用于干跑和实盘模式）。
- [`get_analyzed_dataframe(pair, timeframe)`](#get_analyzed_dataframepair-timeframe) - 返回已分析的 Dataframe（在调用 `populate_indicators()`、`populate_buy()`、`populate_sell()` 之后）以及最新分析的时间。
- `historic_ohlcv(pair, timeframe)` - 返回存储在磁盘上的历史数据。
- `market(pair)` - 返回该交易对的市场数据：费率、限制、精度、活跃标志等。有关市场数据结构的更多详细信息，请参阅 [ccxt 文档](https://github.com/ccxt/ccxt/wiki/Manual#markets)。
- `ohlcv(pair, timeframe)` - 当前缓存的交易对 K 线 (OHLCV) 数据，返回 DataFrame 或空 DataFrame。
- [`orderbook(pair, maximum)`](#orderbookpair-maximum) - 返回该交易对的最新挂单簿数据，一个包含买价/卖价且总共有 `maximum` 个条目的字典。
- [`ticker(pair)`](#tickerpair) - 返回该交易对的最新行情 (ticker) 数据。有关行情数据结构的更多详细信息，请参阅 [ccxt 文档](https://github.com/ccxt/ccxt/wiki/Manual#price-tickers)。
- [`check_delisting(pair)`](#check_delistingpair) - 返回交易对下架时间的 Datetime（如果有），否则返回 None。
- [`funding_rate(pair)`](#funding_ratepair) - 返回该交易对的当前资金费率数据。
- `runmode` - 包含当前运行模式的属性。

### 使用示例

### *available_pairs*

``` python
for pair, timeframe in self.dp.available_pairs:
    print(f"available {pair}, {timeframe}")
```

### *current_whitelist()*

想象一下，您开发了一个使用 `5m` 时间范围进行交易的策略，该策略利用来自交易额前 10 名交易对的 `1d` 时间范围信号。

策略逻辑可能如下所示：

*每 5 分钟通过 `VolumePairList` 扫描交易额前 10 的交易对，并使用 14 天 RSI 进行入场和出场。*

由于可用数据有限，很难将 `5m` 的 K 线重新采样为用于 14 天 RSI 的日 K 线。大多数交易所限制用户只能获取 500-1000 根 K 线，这实际上只给了我们大约 1.74 根日 K 线。我们至少需要 14 天的数据！

由于我们无法重采样数据，我们必须使用提示对，而且由于白名单是动态的，我们不知道要使用哪个对！我们遇到了问题！

这时调用 `self.dp.current_whitelist()` 就派上用场了，它只检索白名单中的那些交易对。

```python
    def informative_pairs(self):

        # 访问白名单中可用的所有交易对。
        pairs = self.dp.current_whitelist()
        # 为每一对分配时间范围，以便为策略下载和缓存它们。
        informative_pairs = [(pair, '1d') for pair in pairs]
        return informative_pairs
```

??? Note "使用 current_whitelist 进行绘图"
    `plot-dataframe` 不支持当前的白名单，因为该命令通常通过提供显式的 pairlist 来使用，因此会使此方法的返回值产生误导。
    FreqUI 在 [Web 服务器模式](utils.md#webserver-mode) 下的可视化也不支持此功能，因为 Web 服务器模式的配置不要求设置 pairlist。

### *get_pair_dataframe(pair, timeframe)*

``` python
# 获取第一个提示对的实盘/历史 K 线 (OHLCV) 数据
inf_pair, inf_timeframe = self.informative_pairs()[0]
informative = self.dp.get_pair_dataframe(pair=inf_pair,
                                         timeframe=inf_timeframe)
```

!!! Warning "有关回测的警告"
    在回测中，`dp.get_pair_dataframe()` 的行为取决于它的调用位置。
    在 `populate_*()` 方法中调用时，`dp.get_pair_dataframe()` 返回完整的计时范围。请确保不要“窥视未来”，以避免在干跑/实盘模式运行时产生意外。
    在 [回调函数](strategy-callbacks.md) 中，您将获得截至当前（模拟）K 线的完整计时范围。

### *get_analyzed_dataframe(pair, timeframe)*

它也可以在特定的回调函数中使用，以获取导致该动作的信号（有关可用回调的更多详细信息，请参阅 [高级策略文档](strategy-advanced.md)）。

``` python
# 获取当前 dataframe
dataframe, last_updated = self.dp.get_analyzed_dataframe(pair=metadata['pair'],
                                                         timeframe=self.timeframe)
```

    如果请求的交易对未被缓存，则返回一个空的 DataFrame。
    您可以使用 `if dataframe.empty:` 来检查此情况并相应地处理。使用白名单中的交易对时不应发生这种情况。

### *orderbook(pair, maximum)*

检索交易对当前的挂单簿。

``` python
if self.dp.runmode.value in ('live', 'dry_run'):
    ob = self.dp.orderbook(metadata['pair'], 1)
    dataframe['best_bid'] = ob['bids'][0][0]
    dataframe['best_ask'] = ob['asks'][0][0]
```

挂单簿结构与 [ccxt](https://github.com/ccxt/ccxt/wiki/Manual#order-book-structure) 的订单结构一致，结果格式如下：

``` js
{
    'bids': [
        [ price, amount ], // [ float, float ]
        [ price, amount ],
        ...
    ],
    'asks': [
        [ price, amount ],
        [ price, amount ],
        //...
    ],
    //...
}
```

因此，如上所示使用 `ob['bids'][0][0]` 将使用最佳买价。`ob['bids'][0][1]` 则表示该挂单位置的成交量。

!!! Warning "有关回测的警告"
    挂单簿不是历史数据的一部分，这意味着如果使用此方法，回测和超参数优化将无法正确运行，因为该方法将返回最新值。

### *ticker(pair)*

``` python
if self.dp.runmode.value in ('live', 'dry_run'):
    ticker = self.dp.ticker(metadata['pair'])
    dataframe['last_price'] = ticker['last']
    dataframe['volume24h'] = ticker['quoteVolume']
    dataframe['vwap'] = ticker['vwap']
```

!!! Warning "警告"
    尽管行情数据结构是 ccxt 统一接口的一部分，但不同交易所返回的值可能有所不同。例如，许多交易所不返回 `vwap` 值，有些交易所并不总是填写 `last` 字段（因此它可能为 None）等。因此，您需要仔细核实交易所返回的行情数据，并添加适当的错误处理/默认值。

!!! Warning "有关回测的警告"
    此方法将始终返回实时值。因此，在回测/超参数优化中不进行运行模式检查而直接使用，将导致错误结果。例如，您的整个 Dataframe 在所有行中都将包含相同的单个数值。

### 发送通知

DataProvider 的 `.send_msg()` 函数允许您从策略发送自定义通知。
相同的通知在每个 K 线期间只会发送一次，除非第二个参数 (`always_send`) 设置为 True。

``` python
    self.dp.send_msg(f"{metadata['pair']} 热度上升！")

    # 强制发送此通知，避免缓存（请阅读下方的警告！）
    self.dp.send_msg(f"{metadata['pair']} 热度上升！", always_send=True)
```

通知仅在交易模式（实盘/干跑）下发送 - 因此该方法在回测时可以无条件调用。

!!! Warning "刷屏警告"
    通过在该方法中设置 `always_send=True`，您可能会被通知刷屏。请务必谨慎使用，并仅在您确信不会在整个 K 线内持续触发的情况下使用，以避免每 5 秒收到一条消息。

### 完整的 DataProvider 示例

```python
from freqtrade.strategy import IStrategy, merge_informative_pair
from pandas import DataFrame

class SampleStrategy(IStrategy):
    # 策略初始化内容...

    timeframe = '5m'

    # 更多策略初始化内容...

    def informative_pairs(self):

        # 获取白名单中可用的所有交易对。
        pairs = self.dp.current_whitelist()
        # 为每一对分配时间范围，以便下载并为策略缓存。
        informative_pairs = [(pair, '1d') for pair in pairs]
        # 可选：添加额外的“静态”交易对
        informative_pairs += [("ETH/USDT", "5m"),
                              ("BTC/TUSD", "15m"),
                            ]
        return informative_pairs

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        if not self.dp:
            # 如果 DataProvider 不可用，则不执行任何操作。
            return dataframe

        inf_tf = '1d'
        # 获取提示对
        informative = self.dp.get_pair_dataframe(pair=metadata['pair'], timeframe=inf_tf)
        # 获取 14 天 RSI
        informative['rsi'] = ta.RSI(informative, timeperiod=14)

        # 使用辅助函数 merge_informative_pair 来安全合并该交易对
        # 自动重命名列，并合并较短时间范围的 dataframe 和较长时间范围的提示对
        # 使用 ffill 以使 1d 值在全天每一行中可用。
        # 如果不这样做，原交易对列与提示对列之间的比较每天只能生效一次。
        # 此方法的完整文档，见下文
        dataframe = merge_informative_pair(dataframe, informative, self.timeframe, inf_tf, ffill=True)

        # 计算原始 Dataframe（5m 时间范围）的 RSI
        dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)

        # 执行其他操作
        # ...

        return dataframe

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:

        dataframe.loc[
            (
                (qtpylib.crossed_above(dataframe['rsi'], 30)) &  # 信号：RSI 向上穿越 30
                (dataframe['rsi_1d'] < 30) &                     # 确保日线 RSI < 30
                (dataframe['volume'] > 0)                        # 确保该 K 线有成交量（对回测很重要）
            ),
            ['enter_long', 'enter_tag']] = (1, 'rsi_cross')

```

## 防止特定交易对发生交易

当交易对离场时，Freqtrade 会自动在当前 K 线（直到该 K 线结束）内锁定该交易对，以防止该交易对立即重新入场。

这是为了防止在单个 K 线内发生多次频繁交易（称为“瀑布流”交易）。

被锁定的交易对将显示消息 `Pair <pair> is currently locked.`。

### 从策略内部锁定交易对

有时可能希望在发生某些事件（例如连续多次亏损交易）后锁定交易对。

Freqtrade 提供了一种从策略内部轻松实现此目的的方法，即调用 `self.lock_pair(pair, until, [reason])`。
`until` 必须是未来的 datetime 对象，此后该对的交易将重新启用；而 `reason` 是一个可选字符串，详细说明锁定原因。

也可以手动解除锁定，通过调用 `self.unlock_pair(pair)` 或 `self.unlock_reason(<reason>)`（提供解锁原因）。
`self.unlock_reason(<reason>)` 将解锁当前使用指定原因锁定的所有交易对。

要验证某对目前是否已锁定，请使用 `self.is_pair_locked(pair)`。

!!! Note "注意"
    锁定的交易对将始终四舍五入到下一个 K 线。假设是 `5m` 时间范围，将 `until` 设置为 10:18 的锁定将锁定该对，直到 10:15-10:20 的 K 线结束。

!!! Warning "警告"
    在回测期间不支持手动锁定。仅允许通过保护机制（Protections）进行锁定。

#### 锁定交易对示例

``` python
from freqtrade.persistence import Trade
from datetime import timedelta, datetime, timezone
# 将以上行放在策略文件的顶部，与其他所有导入并列
# --------

# 在 populate indicators (或 populate_entry_trend) 中：
if self.config['runmode'].value in ('live', 'dry_run'):
    # 获取过去 2 天内已成交的交易
    trades = Trade.get_trades_proxy(
        pair=metadata['pair'], is_open=False, 
        open_date=datetime.now(timezone.utc) - timedelta(days=2))
    # 分析您想要锁定该交易对的条件 .... 对每个策略来说可能都不同
    sumprofit = sum(trade.close_profit for trade in trades)
    if sumprofit < 0:
        # 将交易对锁定 12 小时
        self.lock_pair(metadata['pair'], until=datetime.now(timezone.utc) + timedelta(hours=12))
```

## 策略开发中的常见错误

### 回测时“窥视未来”

出于性能原因，回测会一次性分析整个 Dataframe 的耗时范围。正因为如此，策略作者需要确保策略不会“窥视未来”，即不使用在干跑或实盘模式下无法获取的数据。

这是一个常见的痛点，它会导致回测与干跑/实盘运行之间产生巨大差异。在回测期间表现出色、通常具有难以置信的利润或胜率，但在实际条件下却失败或表现不佳。

以下列表包含一些常见的应避免使用的模式，以防止挫败感：

- 不要使用 `shift(-1)` 或其他负值。这在回测中使用了来自未来的数据，而在干跑或实盘模式下是获取不到的。
- 在 `populate_` 函数中不要使用 `.iloc[-1]` 或 Dataframe 中的任何其他绝对位置，因为这在干跑和回测之间会有所不同。不过，绝对的 `iloc` 索引在回调函数中可以安全使用 - 请参阅 [策略回调](strategy-callbacks.md)。
- 不要使用分析整个 Dataframe 或整列值的函数，例如 `dataframe['mean_volume'] = dataframe['volume'].mean()`。由于回测使用完整的 Dataframe，在 Dataframe 的任何位置，`'mean_volume'` 序列都会包含来自未来的数据。请使用滚动计算（rolling()）代替，例如 `dataframe['volume'].rolling(<window>).mean()`。
- 不要使用 `.resample('1h')`。这会使用周期间隔的左边界，从而将数据从整小时边界移动到该小时的开始。请改用 `.resample('1h', label='right')`。
- 不要使用 `.merge()` 将长时间范围合并到短时间范围。请使用 [提示对](#提示交易对-informative-pairs) 辅助函数。（普通的合并可能会隐式导致前瞻偏差，因为日期指的是开盘日期，而不是收盘日期）。

!!! Tip "技巧：识别问题"
    您应该始终使用两个辅助命令 [前瞻分析](lookahead-analysis.md) 和 [递归分析](recursive-analysis.md)，它们可以分别以不同的方式帮助您找出策略中的问题。
    请按其本意来对待它们 - 即帮助识别最常见问题的辅助工具。即使这两项分析结果都是阴性，也不能保证上面列举的错误完全不存在。

### 冲突的信号

当冲突信号发生冲突（例如 `'enter_long'` 和 `'exit_long'` 都被设置为 `1`）时，freqtrade 将不执行任何操作并忽略入场信号。这将避免出现入场后立即出场的交易。显然，这可能会导致错过进场机会。

以下规则适用，如果设置了 3 个信号中的多个，入场信号将被忽略：

- `enter_long` -> `exit_long`, `enter_short`
- `enter_short` -> `exit_short`, `enter_long`
