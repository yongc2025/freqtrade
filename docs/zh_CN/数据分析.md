# 使用 Jupyter Notebook 分析机器人数据

您可以使用 Jupyter Notebook 轻松分析回测结果和交易历史。在通过 `freqtrade create-userdir --userdir user_data` 初始化用户目录后，示例 Notebook 位于 `user_data/notebooks/`。

## 使用 Docker 快速开始

Freqtrade 提供了一个 docker-compose 文件，可以启动 Jupyter Lab 服务器。
您可以使用以下命令运行此服务器：`docker compose -f docker/docker-compose-jupyter.yml up`

这将创建一个运行 Jupyter Lab 的 Docker 容器，可以通过 `https://127.0.0.1:8888/lab` 访问。
启动后请使用控制台中打印的链接进行简化登录。

有关更多信息，请访问 [使用 Docker 进行数据分析](docker_quickstart.md#data-analysis-using-docker-compose) 部分。

### 专业提示

* 有关使用说明，请访问 [jupyter.org](https://jupyter.org/documentation)。
* 不要忘记从您的 Conda 或虚拟环境（venv）中启动 Jupyter Notebook 服务器，或使用 [nb_conda_kernels](https://github.com/Anaconda-Platform/nb_conda_kernels)。
* 在使用前请复制示例 Notebook，以免您的更改在下次 Freqtrade 更新时被覆盖。

### 在系统级 Jupyter 安装中使用虚拟环境

有时可能希望使用系统范围安装的 Jupyter Notebook，并使用来自虚拟环境的 Jupyter 内核。
这可以防止按系统多次安装完整的 Jupyter 套件，并提供了一种在任务（Freqtrade/其他分析任务）之间切换的简便方法。

为此，首先激活您的虚拟环境并运行以下命令：

``` bash
# 激活虚拟环境
source .venv/bin/activate

pip install ipykernel
ipython kernel install --user --name=freqtrade
# 重启 Jupyter (lab / notebook)
# 在 Notebook 中选择内核 "freqtrade"
```

!!! Note "注意"
    提供本部分是为了保证完整性，Freqtrade 团队不会对这种设置中的问题提供全面支持，并建议直接在虚拟环境中安装 Jupyter，因为这是运行 Jupyter Notebooks 最简单的方法。如需有关此设置的帮助，请参阅 [Project Jupyter](https://jupyter.org/) [文档](https://jupyter.org/documentation) 或 [帮助频道](https://jupyter.org/community)。

!!! Warning "警告"
    某些任务在 Notebook 中的效果并不理想。例如，任何使用异步执行的操作对于 Jupyter 来说都是一个问题。此外，Freqtrade 的主入口是 Shell CLI，因此在 Notebook 中使用纯 Python 会绕过那些为辅助函数提供所需对象和参数的参数。您可能需要手动设置这些值或创建预期的对象。

## 推荐工作流程

| 任务 | 工具 |
| --- | --- |
| 机器人操作 | CLI |
| 重复性任务 | Shell 脚本 |
| 数据分析和可视化 | Notebook |

1. 使用 CLI 进行以下操作：

    * 下载历史数据
    * 运行回测
    * 使用实时数据运行
    * 导出结果

1. 将这些操作收集在 Shell 脚本中：

    * 保存带有参数的复杂命令
    * 执行多步操作
    * 自动测试策略和准备用于分析的数据

1. 使用 Notebook 进行以下操作：

    * 可视化数据
    * 数据处理（Mangle）和绘图以生成洞见

## 示例实用程序代码片段

### 将目录更改为根目录

Jupyter Notebook 从 Notebook 所在目录执行。以下代码片段搜索项目根目录，以便相对路径保持一致。

```python
import os
from pathlib import Path

# 更改目录
# 修改此单元格以确保输出显示正确的路径。
# 定义相对于单元格输出中显示的项目根目录的所有路径
project_root = "somedir/freqtrade"
i=0
try:
    os.chdir(project_root)
    assert Path('LICENSE').is_file()
except:
    while i<4 and (not Path('LICENSE').is_file()):
        os.chdir(Path(Path.cwd(), '../'))
        i+=1
    project_root = Path.cwd()
print(Path.cwd())
```

### 加载多个配置文件

此选项对于检查传入多份配置的结果非常有用。
这也将运行整个配置初始化过程，以便配置已完全初始化，可以传递给其他方法。

``` python
import json
from freqtrade.configuration import Configuration

# 从多个文件加载配置
config = Configuration.from_files(["config1.json", "config2.json"])

# 显示内存中的配置
print(json.dumps(config['original_config'], indent=2))
```

对于交互式环境，准备一份指定了 `user_data_dir` 的额外配置，并将其放在最后传入，这样在运行机器人时就不必更改目录。
最好避免使用相对路径，因为除非更改目录，否则相对路径是从 Jupyter Notebook 的存储位置开始的。

``` json
{
    "user_data_dir": "~/.freqtrade/"
}
```
