# 超参数优化 (Hyperopt)

本页解释了如何通过寻找最优参数来调整您的策略，这一过程被称为超参数优化。机器人使用 `optuna` 软件包中包含的算法来完成此任务。
搜索过程将消耗您的所有 CPU 核心，让您的笔记本电脑听起来像一架战斗机，并且仍然需要很长时间。

通常，搜索最佳参数始于几个随机组合（有关更多详细信息，请参阅[下文](#可重复的结果)），然后使用 optuna 的一种采样器算法（目前为 NSGAIIISampler）在搜索超空间中快速找到使[损失函数](#损失函数)值最小化的参数组合。

超参数优化需要历史数据，就像回测一样（超参数优化会多次运行回测，并使用不同的参数）。
要了解如何获取您感兴趣的交易对和交易所的数据，请参阅文档的[数据下载](数据下载.md)部分。

!!! Bug
    如 [Issue #1133](https://github.com/freqtrade/freqtrade/issues/1133) 中发现的，当仅使用 1 个 CPU 核心时，超参数优化可能会崩溃。

!!! Note
    自 2021.4 版本发布以来，您不再需要编写单独的超参数优化类，可以直接在策略中配置参数。
    旧方法在 2021.8 之前一直受支持，并已在 2021.9 中删除。

### 超参数优化清单

超参数优化中所有任务/可能性的清单

根据您想要优化的空间，只需完成以下部分操作：

* 定义 `space='buy'` 的参数 - 用于买入信号优化
* 定义 `space='sell'` 的参数 - 用于卖出信号优化
* 定义 `space='enter'` 的参数 - 用于入场信号优化
* 定义 `space='exit'` 的参数 - 用于出场信号优化
* 定义 `space='protection'` 的参数 - 用于保护措施优化
* 定义 `space='random_spacename'` 的参数 - 以更好地控制哪些参数一起进行优化

选择最适合参数的空间名称。为了清晰起见，我们建议使用 `buy` / `sell` 或 `enter` / `exit`（但在技术上没有限制）。

!!! Note
    `populate_indicators` 需要创建任何空间可能使用的所有指标，否则超参数优化将无法工作。

极少数情况下，您可能还需要创建一个名为 `HyperOpt` 的[嵌套类](高级超参数优化.md#覆盖预定义空间)并实现：

* `roi_space` - 用于自定义 ROI 优化（如果您在优化超空间中需要不同于默认值的 ROI 参数范围）
* `generate_roi_table` - 用于自定义 ROI 优化（如果您需要 ROI 表中的数值范围或 ROI 表中的条目数（步长）不同于默认的 4 步）
* `stoploss_space` - 用于自定义止损优化（如果您在优化超空间中需要不同于默认值的止损参数范围）
* `trailing_space` - 用于自定义移动止损优化（如果您在优化超空间中需要不同于默认值的移动止损参数范围）
* `max_open_trades_space` - 用于自定义最大持仓数优化（如果您在优化超空间中需要不同于默认值的 max_open_trades 参数范围）

!!! Tip "快速优化 ROI、止损和移动止损"
    您可以快速优化 `roi`、`stoploss` 和 `trailing` 空间，而无需更改策略中的任何内容。

    ``` bash
    # 准备一个可用的策略。
    freqtrade hyperopt --hyperopt-loss SharpeHyperOptLossDaily --spaces roi stoploss trailing --strategy MyWorkingStrategy --config config.json -e 100
    ```

### 超参数优化执行逻辑

超参数优化将首先将数据加载到内存中，然后为每对交易对运行一次 `populate_indicators()` 以生成所有指标，除非指定了 `--analyze-per-epoch`。

然后，超参数优化将衍生到不同的进程中（处理器数量，或 `-j <n>`），并一遍又一遍地运行回测，更改作为定义的 `--spaces` 一部分的参数。

对于每一组新参数，freqtrade 将首先运行 `populate_entry_trend()`，然后运行 `populate_exit_trend()`，接着运行常规回测过程来模拟交易。

在回测之后，结果将传递给[损失函数](#损失函数)，该函数将评估此结果是否优于或劣于之前的结果。
基于损失函数的结果，超参数优化将确定在下一轮回测中尝试的下一组参数。

### 配置您的守卫 (Guards) 和触发器 (Triggers)

在您的策略文件中，有两个地方需要更改以添加用于优化的新超参数优化参数：

* 在类级别定义超参数优化应优化的参数。
* 在 `populate_entry_trend()` 中 - 使用定义的参数值而不是原始常量。

在那里您有两种不同类型的指标：1. `guards`（守卫）和 2. `triggers`（触发器）。

1. 守卫是类似“如果 ADX < 10 则永不进场”或“如果当前价格超过 EMA10 则永不进场”的条件。
2. 触发器是在特定时刻实际触发入场的指标，例如“当 EMA5 向上穿越 EMA10 时进场”或“当收盘价触及布林带下轨时进场”。

!!! Hint "守卫和触发器"
    从技术上讲，守卫和触发器之间没有区别。
    但是，本指南将进行这种区分，以明确信号不应是“粘性”的。
    粘性信号是指在多个 K 线中都处于活动状态的信号。这可能导致信号进场较晚（由于在信号消失前进场，这意味着成功的机会比刚开始时要低得多）。

超参数优化将为每一轮 epoch 选择一个触发器，并可能选择多个守卫。

#### 出场信号优化

与上面的入场信号类似，出场信号也可以进行优化。
将相应的设置放入以下方法中

* 在类级别定义超参数优化应优化的参数，可以命名为 `sell_*`，也可以通过参数显式定义 `space='sell'`。
* 在 `populate_exit_trend()` 中 - 使用定义的参数值而不是原始常量。

配置和规则与买入信号相同。

## 解开谜团

假设您很好奇：应该使用 MACD 交叉还是布林带下轨来触发做多入场？
您还想知道是否应该使用 RSI 或 ADX 来辅助这些决策。
如果您决定使用 RSI 或 ADX，应该为它们使用什么数值？

那么，让我们使用超参数优化来解开这个谜团。

### 定义待使用的指标

我们首先计算策略将要使用的指标。

``` python
class MyAwesomeStrategy(IStrategy):

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        """
        生成策略使用的所有指标
        """
        dataframe['adx'] = ta.ADX(dataframe)
        dataframe['rsi'] = ta.RSI(dataframe)
        macd = ta.MACD(dataframe)
        dataframe['macd'] = macd['macd']
        dataframe['macdsignal'] = macd['macdsignal']
        dataframe['macdhist'] = macd['macdhist']

        bollinger = ta.BBANDS(dataframe, timeperiod=20, nbdevup=2.0, nbdevdn=2.0)
        dataframe['bb_lowerband'] = bollinger['lowerband']
        dataframe['bb_middleband'] = bollinger['middleband']
        dataframe['bb_upperband'] = bollinger['upperband']
        return dataframe
```

### 可优化的超参数

我们继续定义可优化的超参数：

```python
class MyAwesomeStrategy(IStrategy):
    buy_adx = DecimalParameter(20, 40, decimals=1, default=30.1, space="buy")
    buy_rsi = IntParameter(20, 40, default=30, space="buy")
    buy_adx_enabled = BooleanParameter(default=True, space="buy")
    buy_rsi_enabled = CategoricalParameter([True, False], default=False, space="buy")
    buy_trigger = CategoricalParameter(["bb_lower", "macd_cross_signal"], default="bb_lower", space="buy")
```

上述定义表示：我有五个想要随机组合的参数，以寻找最佳组合。
`buy_rsi` 是一个整数参数，将在 20 到 40 之间进行测试。该空间的大小为 20。
`buy_adx` 是一个小数参数，将在 20.0 到 40.0 之间进行评估（小数点后 1 位，即值为 20.1, 20.2, ...）。该空间的大小为 200。
然后我们有三个类别变量。前两个是 `True` 或 `False`。
我们使用这些来启用或禁用 ADX 和 RSI 守卫。
最后一个我们称之为 `trigger`，并使用它来决定我们要使用哪个买入触发器。

!!! Note "参数空间分配"
    - 参数必须分配给名为 `buy_*`、`sell_*`、`enter_*`、`exit_*` 或 `protection_*` 的变量，或者通过参数显式分配空间（`space='buy'`、`space='sell'`、`space='protection'`）。
    - 具有冲突分配的参数（例如 `buy_adx = IntParameter(4, 24, default=14, space='sell')`）将使用显式空间分配。
    - 如果某个空间没有可用参数，运行超参数优化时，您将收到未找到空间的错误。
    空间不明确的参数（例如 `adx_period = IntParameter(4, 24, default=14)` - 既没有显式也没有隐式空间）将不会被检测到，因此将被忽略。
    空间也可以自定义命名（例如 `space='my_custom_space'`），唯一的限制是空间名称不能是 `all`、`default` - 并且必须是有效的 python 标识符。

接下来让我们使用这些值编写买入策略：

```python
    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        conditions = []
        # 守卫和趋势
        if self.buy_adx_enabled.value:
            conditions.append(dataframe['adx'] > self.buy_adx.value)
        if self.buy_rsi_enabled.value:
            conditions.append(dataframe['rsi'] < self.buy_rsi.value)

        # 触发器
        if self.buy_trigger.value == 'bb_lower':
            conditions.append(dataframe['close'] < dataframe['bb_lowerband'])
        if self.buy_trigger.value == 'macd_cross_signal':
            conditions.append(qtpylib.crossed_above(
                dataframe['macd'], dataframe['macdsignal']
            ))

        # 检查成交量不为 0
        conditions.append(dataframe['volume'] > 0)

        if conditions:
            dataframe.loc[
                reduce(lambda x, y: x & y, conditions),
                'enter_long'] = 1

        return dataframe
```

超参数优化现在将多次调用 `populate_entry_trend()`（`epochs` 轮次），并使用不同的数值组合。
它将使用给定的历史数据，并根据上述函数生成的买入信号模拟买入。
基于结果，超参数优化将告诉您哪种参数组合产生了最佳结果（基于配置的[损失函数](#损失函数)）。

!!! Note
    上述设置期望在生成的指标中找到 ADX、RSI 和布林带。
    当您想要测试机器人目前未使用的指标时，请记住将其添加到策略或超参数优化文件中的 `populate_indicators()` 方法中。

## 参数类型

有四种参数类型，每种都适用于不同的目的。

* `IntParameter` - 定义一个带有搜索空间上限和下限的整数参数。
* `DecimalParameter` - 定义一个带有有限小数位数（默认为 3）的浮点参数。在大多数情况下，应优先于 `RealParameter`。
* `RealParameter` - 定义一个带有上限和下限且没有精度限制的浮点参数。极少使用，因为它会创建一个具有近乎无限种可能性的空间。
* `CategoricalParameter` - 定义一个具有预定选择数量的参数。
* `BooleanParameter` - `CategoricalParameter([True, False])` 的简写 - 非常适合“启用”参数。

### 参数选项

有两个参数选项可以帮助您快速测试各种想法：

* `optimize` - 当设置为 `False` 时，参数将不包含在优化过程中。（默认值：True）
* `load` - 当设置为 `False` 时，先前超参数优化运行的结果（在策略或 JSON 输出文件中的 `buy_params` 和 `sell_params` 中）将不会用作后续超参数优化的起始值。而是使用参数中指定的默认值。（默认值：True）

!!! Tip "`load=False` 对回测的影响"
    请注意，将 `load` 选项设置为 `False` 意味着回测也将使用参数中指定的默认值，而*不是*通过超参数优化找到的值。

!!! Warning
    超参数优化参数不能在 `populate_indicators` 中使用 - 因为超参数优化不会为每个 epoch 重新计算指标，因此在这种情况下将使用起始值。

## 优化指标参数

假设您心中有一个简单的策略 - EMA 交叉策略（2 条移动平均线交叉） - 并且您想找到该策略的理想参数。
默认情况下，我们假设止损为 5% - 止盈（`minimal_roi`）为 10% - 这意味着当利润达到 10% 时，freqtrade 将卖出该交易。

``` python
from pandas import DataFrame
from functools import reduce

import talib.abstract as ta

from freqtrade.strategy import (BooleanParameter, CategoricalParameter, DecimalParameter, 
                                IStrategy, IntParameter)
import freqtrade.vendor.qtpylib.indicators as qtpylib

class MyAwesomeStrategy(IStrategy):
    stoploss = -0.05
    timeframe = '15m'
    minimal_roi = {
        "0":  0.10
    }
    # 定义参数空间
    buy_ema_short = IntParameter(3, 50, default=5)
    buy_ema_long = IntParameter(15, 200, default=50)


    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        """生成策略使用的所有指标"""
        
        # 计算所有的 ema_short 值
        for val in self.buy_ema_short.range:
            dataframe[f'ema_short_{val}'] = ta.EMA(dataframe, timeperiod=val)
        
        # 计算所有的 ema_long 值
        for val in self.buy_ema_long.range:
            dataframe[f'ema_long_{val}'] = ta.EMA(dataframe, timeperiod=val)
        
        return dataframe

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        conditions = []
        conditions.append(qtpylib.crossed_above(
                dataframe[f'ema_short_{self.buy_ema_short.value}'], dataframe[f'ema_long_{self.buy_ema_long.value}']
            ))

        # 检查成交量不为 0
        conditions.append(dataframe['volume'] > 0)

        if conditions:
            dataframe.loc[
                reduce(lambda x, y: x & y, conditions),
                'enter_long'] = 1
        return dataframe

    def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        conditions = []
        conditions.append(qtpylib.crossed_above(
                dataframe[f'ema_long_{self.buy_ema_long.value}'], dataframe[f'ema_short_{self.buy_ema_short.value}']
            ))

        # 检查成交量不为 0
        conditions.append(dataframe['volume'] > 0)

        if conditions:
            dataframe.loc[
                reduce(lambda x, y: x & y, conditions),
                'exit_long'] = 1
        return dataframe
```

分解：

使用 `self.buy_ema_short.range` 将返回一个包含参数低值和高值之间所有条目的 range 对象。
在此示例中 (`IntParameter(3, 50, default=5)`)，循环将针对 3 到 50 之间的所有数字运行 (`[3, 4, 5, ... 49, 50]`)。
通过在循环中使用它，超参数优化将生成 48 个新列 (`['buy_ema_3', 'buy_ema_4', ... , 'buy_ema_50']`)。

然后，超参数优化本身将使用所选值来创建买入和卖出信号。

虽然这种策略很可能过于简单，无法提供持续盈利，但它可以作为如何优化指标参数的示例。

!!! Note
    `self.buy_ema_short.range` 在超参数优化和其他模式之间表现不同。对于超参数优化，上述示例可能会生成 48 个新列，但对于所有其他模式（回测、模拟/实盘），它将仅为所选值生成列。因此，您应避免将生成的列与显式值（除 `self.buy_ema_short.value` 以外的值）一起使用。

!!! Note
    `range` 属性也可以与 `DecimalParameter` 和 `CategoricalParameter` 一起使用。`RealParameter` 由于搜索空间无限而未提供此属性。

??? Hint "性能提示"
    在正常的超参数优化过程中，指标只计算一次并提供给每个 epoch，RAM 使用量随着核心数量的增加呈线性增加。由于这也对性能有影响，因此有两种替代方法可以减少 RAM 使用量：

    * 将 `ema_short` 和 `ema_long` 的计算从 `populate_indicators()` 移动到 `populate_entry_trend()`。由于每个 epoch 都会计算 `populate_entry_trend()`，因此您无需使用 `.range` 功能。
    * 超参数优化提供了 `--analyze-per-epoch` 选项，这会将 `populate_indicators()` 的执行移动到 epoch 进程中，为每个 epoch 的每个参数计算一个值，而不是使用 `.range` 功能。在这种情况下，`.range` 功能将仅返回实际使用的值。

    这些替代方案将减少 RAM 使用量，但会增加 CPU 使用率。但是，您的超参数优化运行由于内存不足 (OOM) 而失败的可能性会大大降低。

    无论您是使用 `.range` 功能还是上述替代方案，您都应尝试将空间范围设置得尽可能小，因为这将提高 CPU/RAM 的使用效率。

## 优化保护措施 (Protections)

Freqtrade 还可以优化保护措施。如何优化保护措施取决于您，以下内容仅供参考。

策略只需要定义“protections”条目，该条目作为一个返回保护配置列表的属性。

``` python
from pandas import DataFrame
from functools import reduce

import talib.abstract as ta

from freqtrade.strategy import (BooleanParameter, CategoricalParameter, DecimalParameter, 
                                IStrategy, IntParameter)
import freqtrade.vendor.qtpylib.indicators as qtpylib

class MyAwesomeStrategy(IStrategy):
    stoploss = -0.05
    timeframe = '15m'
    # 定义参数空间
    cooldown_lookback = IntParameter(2, 48, default=5, space="protection", optimize=True)
    stop_duration = IntParameter(12, 200, default=5, space="protection", optimize=True)
    use_stop_protection = BooleanParameter(default=True, space="protection", optimize=True)


    @property
    def protections(self):
        prot = []

        prot.append({
            "method": "CooldownPeriod",
            "stop_duration_candles": self.cooldown_lookback.value
        })
        if self.use_stop_protection.value:
            prot.append({
                "method": "StoplossGuard",
                "lookback_period_candles": 24 * 3,
                "trade_limit": 4,
                "stop_duration_candles": self.stop_duration.value,
                "only_per_pair": False
            })

        return prot

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # ...
        
```

然后您可以按如下方式运行超参数优化：
`freqtrade hyperopt --hyperopt-loss SharpeHyperOptLossDaily --strategy MyAwesomeStrategy --spaces protection`

!!! Note
    保护空间不是默认空间的一部分，仅在使用超参数参数接口（Parameters Hyperopt interface）时可用，而非在旧版超参数优化接口（需要单独的超参数优化文件）中可用。
    如果选择了保护空间，Freqtrade 还将自动更改 "--enable-protections" 标志。

!!! Warning
    如果保护措施定义为属性，则配置中的条目将被忽略。
    因此建议不要在配置中定义保护措施。

### 从先前的属性设置迁移

从旧设置迁移非常简单，可以通过将保护项转换为属性来完成。
简单来说，以下配置将被转换为下方代码。

``` python
class MyAwesomeStrategy(IStrategy):
    protections = [
        {
            "method": "CooldownPeriod",
            "stop_duration_candles": 4
        }
    ]
```

结果

``` python
class MyAwesomeStrategy(IStrategy):
    
    @property
    def protections(self):
        return [
            {
                "method": "CooldownPeriod",
                "stop_duration_candles": 4
            }
        ]
```

然后，您显然还需要将潜在感兴趣的条目更改为参数，以便进行超参数优化。

### 优化 `max_entry_position_adjustment`

虽然 `max_entry_position_adjustment` 不是一个单独的空间，但仍可以通过上面显示的属性方法在超参数优化中使用它。

``` python
from pandas import DataFrame
from functools import reduce

import talib.abstract as ta

from freqtrade.strategy import (BooleanParameter, CategoricalParameter, DecimalParameter, 
                                IStrategy, IntParameter)
import freqtrade.vendor.qtpylib.indicators as qtpylib

class MyAwesomeStrategy(IStrategy):
    stoploss = -0.05
    timeframe = '15m'

    # 定义参数空间
```

## 损失函数 (Loss-functions)

每次超参数调整都需要一个目标。这通常定义为损失函数（有时也称为目标函数），对于更理想的结果，该函数应该减小，而对于不理想的结果，该函数应该增加。

必须通过 `--hyperopt-loss <Class-name>` 参数（或者可选地通过配置中的 `"hyperopt_loss"` 键）指定损失函数。
此类应位于 `user_data/hyperopts/` 目录中其自己的文件中。

目前，内置了以下损失函数：

* `ShortTradeDurHyperOptLoss` -（默认的旧版 Freqtrade 超参数优化损失函数）- 主要针对短交易持续时间并避免损失。
* `OnlyProfitHyperOptLoss` - 仅考虑利润额。
* `SharpeHyperOptLoss` - 优化基于交易回报相对于标准偏差计算出的夏普比率 (Sharpe Ratio)。
* `SharpeHyperOptLossDaily` - 优化基于**每日**交易回报相对于标准偏差计算出的夏普比率。
* `SortinoHyperOptLoss` - 优化基于交易回报相对于**下行**标准偏差计算出的索提诺比率 (Sortino Ratio)。
* `SortinoHyperOptLossDaily` - 优化基于**每日**交易回报相对于**下行**标准偏差计算出的索提诺比率。
* `MaxDrawDownHyperOptLoss` - 优化最大绝对回撤。
* `MaxDrawDownRelativeHyperOptLoss` - 优化最大绝对回撤，同时也根据最大相对回撤进行调整。
* `MaxDrawDownPerPairHyperOptLoss` - 计算每对交易对的利润/回撤比率，并返回最差的结果作为目标，强制超参数优化为交易列表中的所有交易对优化参数。通过这种方式，我们可以防止一个或多个结果良好的交易对使指标虚高，而结果较差的交易对不仅没有代表性，更没有得到优化。
* `CalmarHyperOptLoss` - 优化基于交易回报相对于最大回撤计算出的卡玛比率 (Calmar Ratio)。
* `ProfitDrawDownHyperOptLoss` - 通过最大化利润和最小化回撤的目标进行优化。可以调整 hyperoptloss 文件中的 `DRAWDOWN_MULT` 变量，以在回撤目的上变得更严格或更灵活。
* `MultiMetricHyperOptLoss` - 通过多个关键指标进行优化，以实现平衡的绩效。主要焦点是最大化利润和最小化回撤，同时也考虑额外的指标，如利润因子、期望比和胜率。此外，它还对 epoch 交易次数过少的情况应用惩罚，鼓励具有足够交易频率的策略。

自定义损失函数的创建在文档的[高级超参数优化](高级超参数优化.md)部分中进行了介绍。

## 执行超参数优化

一旦更新了超参数优化配置，您就可以运行它了。
因为超参数优化会尝试大量的组合来寻找最佳参数，所以需要时间才能获得好的结果。

我们强烈建议使用 `screen` 或 `tmux` 来防止任何连接中断。

```bash
freqtrade hyperopt --config config.json --hyperopt-loss <hyperoptlossname> --strategy <strategyname> -e 500 --spaces all
```

`-e` 选项将设置超参数优化将进行的评估次数。由于超参数优化使用贝叶斯搜索，因此一次运行过多的 epoch 可能不会产生更好的结果。经验表明，在 500-1000 个 epoch 之后，最佳结果通常不会有太大改善。
`--early-stop` 选项将设置在多少个 epoch 没有改进后超参数优化将停止。一个好的值是总 epoch 的 20-30%。任何大于 0 且小于 20 的值都将被替换为 20。早期停止默认是禁用的 (`--early-stop=0`)。

进行多次运行（执行），每次几千个 epoch 并且使用不同的随机状态，很可能会产生不同的结果。

`--spaces all` 选项决定应优化所有可能的参数。可能性列在下面。

!!! Note
    超参数优化将以超参数优化开始时间的时间戳存储结果。
    读取命令 (`hyperopt-list`, `hyperopt-show`) 可以使用 `--hyperopt-filename <filename>` 来读取和显示旧的超参数优化结果。
    您可以使用 `ls -l user_data/hyperopt_results/` 查看文件名列表。

### 使用不同的历史数据源执行超参数优化

如果您想使用磁盘上已有的备用历史数据集来优化超参数，请使用 `--datadir PATH` 选项。默认情况下，超参数优化使用目录 `user_data/data` 中的数据。

### 使用较小的测试集运行超参数优化

使用 `--timerange` 参数来更改您想要使用的测试集的数量。
例如，要使用一个月的数据，请将 `--timerange 20210101-20210201`（从 2021 年 1 月到 2021 年 2 月）传递给超参数优化调用。

完整命令：

```bash
freqtrade hyperopt --strategy <strategyname> --timerange 20210101-20210201
```

### 使用更小的搜索空间运行超参数优化

使用 `--spaces` 选项来限制超参数优化使用的搜索空间。
让超参数优化优化所有内容通常会导致一个非常庞大的搜索空间。
通常，先从搜索初始入场算法开始可能更有意义。
或者也许您只想为您拥有的那个棒极了的新策略优化止损或 ROI 表。

合法值包括：

* `all`: 优化所有内容（包括自定义空间）
* `buy`: 仅搜索新的买入策略
* `sell`: 仅搜索新的卖出策略
* `enter`: 仅搜索新的入场逻辑
* `exit`: 仅搜索新的出场逻辑
* `roi`: 仅为您的策略优化最小利润表
* `stoploss`: 搜索最佳止损值
* `trailing`: 搜索最佳移动止损值
* `trades`: 搜索最佳最大持仓数
* `protection`: 搜索最佳保护参数（阅读[保护措施部分](#优化保护措施)以了解如何正确定义这些）
* `default`: 除了 `trailing`、`trades` 和 `protection` 之外的 `all`
* `custom_space_name`: 策略中任何参数使用的任何自定义空间
* 上述任何值的以空格分隔的列表，例如 `--spaces roi stoploss`

当未指定 `--space` 命令行选项时，使用的默认超参数优化搜索空间不包括 `trailing` 超空间。我们建议在找到、验证并粘贴到自定义策略中的其他超空间的最佳参数后，单独为 `trailing` 超空间运行优化。

## 理解超参数优化结果

一旦超参数优化完成，您就可以使用结果来更新您的策略。
假设有以下超参数优化结果：

```

    44/100:    135 trades. Avg profit  0.57%. Total profit  0.03871918 BTC (0.7722%). Avg duration 180.4 mins. Objective: 1.94367

    # Buy hyperspace params:

        'buy_adx_enabled': False,
        'buy_rsi_enabled': True,
        'buy_trigger': 'bb_lower'
    }
```

您应该这样理解这个结果：

* 最有效的买入触发器是 `bb_lower`。
* 您不应该使用 ADX，因为 `'buy_adx_enabled': False`。
* 您应该**考虑**使用 RSI 指标 (`'buy_rsi_enabled': True`)，且最佳值为 `29.0` (`'buy_rsi': 29.0`)。

### 自动应用参数到策略

当使用可优化的超参数时，超参数优化的运行结果将写入策略邻近的一个 json 文件中（因此对于 `MyAwesomeStrategy.py`，该文件将是 `MyAwesomeStrategy.json`）。
当使用 `hyperopt-show` 子命令时，该文件也会被更新，除非在这两个命令中提供了 `--disable-param-export`。

将整个超参数优化结果转移到您的策略中如下所示：

    配置文件中的值将覆盖参数文件级别的参数——并且两者都将覆盖策略中的参数。

如果您正在优化 ROI，Freqtrade 会为您创建 'roi' 优化超空间——它是 ROI 表组件的超空间。默认情况下，Freqtrade 生成的每个 ROI 表由 4 行（步）组成。超参数优化实现并运用了针对 ROI 表的自适应范围，其中 ROI 步骤中值的范围取决于所使用的时间框架。默认情况下，这些值在以下范围内变化（对于一些最常用的时间框架，值四舍五入到小数点后 3 位）：

如果您在自定义超参数优化中使用了 `generate_roi_table()` 和 `roi_space()` 方法，请将其删除，以便利用 Freqtrade 默认生成的这些自适应 ROI 表和 ROI 超优化空间。

### 可重复的结果

最优参数的搜索始于参数超空间中的一些（目前为 30 个）随机组合，即随机超参数优化 epoch。这些随机 epoch 在超参数优化输出的第一列中用星号 (`*`) 标记。

这些随机值生成的初始状态（随机状态）由 `--random-state` 命令行选项的值控制。您可以将其设置为您选择的某个任意值，以获得可重复的结果。

如果您尚未在命令行选项中明确设置此值，超参数优化会为您使用某个随机值作为随机状态的种子。每次超参数优化运行的随机状态值都会显示在日志中，因此您可以复制并将其粘贴到 `--random-state` 命令行选项中，以重复所使用的初始随机 epoch 集。

如果您未在命令行选项、配置、时间范围、策略和超参数优化类、历史数据以及损失函数中更改任何内容，您在使用相同的随机状态值时，应获得相同的超参数优化结果。

## 输出格式化

默认情况下，超参数优化打印彩色结果——总利润为正的 epoch 以绿色打印。此高亮显示可帮助您查找可能对以后分析感兴趣的 epoch。总利润为零或利润为负（亏损）的 epoch 以正常颜色打印。如果您不需要结果彩色化（例如，当您将超参数优化输出重定向到文件时），可以通过在命令行中指定 `--no-color` 选项来关闭彩色化。

如果您想在超参数优化输出中看到所有结果，而不仅仅是最好的结果，可以使用 `--print-all` 命令行选项。当使用 `--print-all` 时，当前的最佳结果默认也是彩色化的——它们以粗体（亮）样式打印。这也可以通过 `--no-color` 命令行选项关闭。

!!! Note "Windows 与彩色输出"
    Windows 不原生支持彩色输出，因此它是自动禁用的。要在 Windows 下运行超参数优化时获得彩色输出，请考虑使用 WSL。

## 持仓堆叠和禁用最大市场持仓数

在某些情况下，您可能需要使用 `--eps`/`--enable-position-staking` 参数运行超参数优化（和回测），或者您可能需要将 `max_open_trades` 设置为一个非常大的数字，以禁用对持仓交易数量的限制。

默认情况下，超参数优化模拟 Freqtrade 实盘运行/模拟运行的行为，其中每对交易对仅允许一笔未平仓交易。所有交易对打开的交易总数也受到 `max_open_trades` 设置的限制。在超参数优化/回测期间，这可能导致潜在的交易被已打开的交易隐藏（或遮蔽）。

`--eps`/`--enable-position-stacking` 参数允许模拟多次购买同一交易对。
将 `--max-open-trades` 设置为一个非常大的数字将禁用对持仓交易数量的限制。

!!! Note
    模拟/实盘运行将**不会**使用持仓堆叠——因此，在不使用此功能的情况下验证策略也是有意义的，因为它更接近现实。

您也可以在配置文件中通过显式设置 `"position_stacking"=true` 来启用持仓堆叠。

## 内存不足 (Out of Memory) 错误

由于超参数优化会消耗大量内存（完整数据需要为每个并行回测进程在内存中保留一份），您很可能会遇到“内存不足”错误。
为了应对这些错误，您有多个选择：

* 减少交易对的数量。
* 缩短所使用的时间范围 (`--timerange <timerange>`)。
* 避免使用 `--timeframe-detail`（这会将大量额外数据加载到内存中）。
* 减少并行进程的数量 (`-j <n>`)。
* 增加机器内存。
* 如果您正在使用具有 `.range` 功能的大量参数，请使用 `--analyze-per-epoch`。

## 目标点在此之前已被评估过 (The objective has been evaluated at this point before.)

如果您看到 `The objective has been evaluated at this point before.` - 这表明您的搜索空间已经耗尽，或接近耗尽。
基本上，您空间中的所有点都已被命中（或已命中局部最小值） - 并且超参数优化在多维空间中已找不到尚未尝试过的点。
在此情况下，Freqtrade 会尝试通过使用新的随机点来解决“局部最小值”问题。

示例：

``` python
buy_ema_short = IntParameter(5, 20, default=10, space="buy", optimize=True)
# 这是买入空间中唯一的参数
```

`buy_ema_short` 空间有 15 个可能的值 (`5, 6, ... 19, 20`)。如果您现在为买入空间运行超参数优化，在选项用尽之前，超参数优化将只有 15 个值可以尝试。
因此，您的 epoch 应与可能的值保持一致 - 或者如果您注意到大量 `The objective has been evaluated at this point before.` 警告，您应该准备好中断运行。

## 显示超参数优化结果详情

在运行所需数量的 epoch 的超参数优化之后，您可以在以后列出所有结果进行分析，仅选择最佳或盈利的结果，并显示先前评估过的任何 epoch 的详情。这可以通过 `hyperopt-list` 和 `hyperopt-show` 子命令来完成。这些子命令的用法在[实用工具](实用工具.md#列出超参数优化结果)章节中有所描述。

## 从策略中输出调试消息

如果您想从策略中输出调试消息，可以使用 `logging` 模块。默认情况下，Freqtrade 将输出级别为 `INFO` 或更高的所有消息。

``` python
import logging


logger = logging.getLogger(__name__)


class MyAwesomeStrategy(IStrategy):
    ...

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        logger.info("这是一条调试消息")
        ...

```

!!! Note "使用 print"
    通过 `print()` 打印的消息不会显示在超参数优化输出中，除非禁用了并行化 (`-j 1`)。
    建议改用 `logging` 模块。

## 验证回测结果

一旦优化后的策略已在您的策略中实施，您应该回测此策略，以确保一切都按预期工作。

为了在回测期间获得与超参数优化期间相同的结果（交易数量、持续时间、利润等），请在回测中使用用于超参数优化的相同配置和参数（时间范围、时间框架等）。

### 为什么我的回测结果与我的超参数优化结果不匹配？

如果结果不匹配，请检查以下因素：

* 您可能在 `populate_indicators()` 中添加了超参数，它们将仅**为所有 epoch** 计算一次。例如，如果您尝试优化多个 SMA 时间周期值，则可优化的时间周期参数应放置在每个 epoch 都会计算的 `populate_entry_trend()` 中。请参阅[优化指标参数](https://www.freqtrade.io/en/stable/hyperopt/#optimizing-an-indicator-parameter)。
* 如果您禁用了超参数自动导出到 JSON 参数文件的功能，请仔细检查以确保您已将所有优化后的值正确转移到策略中。
* 检查日志以验证设置了哪些参数以及使用了哪些值。
* 特别注意止损、max_open_trades 和移动止损参数，因为它们通常在配置文件中设置，这会覆盖对策略的更改。检查回测日志，确保配置没有不经意地设置任何参数（如 `stoploss`、`max_open_trades` 或 `trailing_stop`）。
* 验证是否没有意外的参数 JSON 文件覆盖了策略中的参数或默认超参数优化设置。
* 验证在回测中启用的任何保护措施在进行超参数优化时也已启用，反之亦然。当使用 `--space protection` 时，在超参数优化时会自动启用保护措施。
