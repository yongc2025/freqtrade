# 递归分析 (Recursive analysis)

本页说明如何验证您的策略是否因某些指标的递归问题而导致不准确。

递归公式根据序列的前项定义任何项。递归公式的一个例子是 a<sub>n</sub> = a<sub>n-1</sub> + b。

为什么这对于 Freqtrade 很重要？在回测中，机器人将根据指定的时间范围获取交易对的完整数据。但在干跑/实盘运行中，机器人将受到每个交易所提供的数据量的限制。

例如，为了计算一个名为 `steps` 的非常基础的指标，第一行的值始终为 0，而后续各行的值等于前一行的值加 1。如果我使用最近的 1000 根 K 线进行计算，那么第一行的 `steps` 值为 0，最后一根已闭合 K 线的 `steps` 值为 999。

如果计算仅使用最近的 500 根 K 线会发生什么？那么在最后一根已闭合 K 线处，`steps` 的值将是 499 而不是 999。该值的差异意味着您的回测结果可能与您的干跑/实盘运行结果不同。

`recursive-analysis` 命令要求有可用的历史数据。要了解如何获取您感兴趣的交易对和交易所的数据，请参阅文档的 [数据下载](数据下载.md) 章节。

此命令通过准备不同长度的数据并根据它们计算指标来进行分析。它并不对策略本身进行回测，而仅计算指标。在完成不同启动 K 线值 (`startup_candle_count`) 的指标计算后，将比较所有指定 `startup_candle_count` 下最后一行数据的值，以观察它们与基准计算相比显示出多少差异。

命令设置：

- 使用 `-p` 选项设置您想要分析的交易对。由于我们只关注指标值，因此使用多个交易对是多余的。建议使用价格较高且至少具有中等波动性的交易对（如 BTC 或 ETH），以避免可能会使结果不准确的舍入问题。如果命令中未设置交易对，则分析将使用白名单中的第一个交易对。
- 建议设置较长的时间范围（至少 5000 根 K 线），以便用作基准的初始指标计算本身具有极小或没有递归问题。例如，对于 5 分钟时间范围，5000 根 K 线等于 18 天。
- `--cache` 被强制设为 "none"，以避免自动加载之前的指标计算。

除了递归公式检查外，此命令还对指标值进行简单的前瞻性偏差检查。如需完整的前瞻性检查，请使用 [前瞻性分析](前瞻性分析.md)。

### 为什么默认启动 K 线使用奇数？

启动 K 线（startup candles）的默认值是奇数。当机器人从交易所的 API 获取 K 线数据时，最后一根 K 线是机器人正在检查的，其余数据即为“启动 K 线”。

例如，币安 (Binance) 每次 API 调用允许 1000 根 K 线。当机器人接收 1000 根 K 线时，最后一根是“当前 K 线”，前面的 999 根是“启动 K 线”。通过将启动 K 线计数设为 1000 而不是 999，机器人将尝试获取 1001 根 K 线。交易所 API 随后将以分页形式发送 K 线数据，即在币安 API 的情况下，这将分成两组——一组长度为 1000，另一组长度为 1。这会导致机器人认为策略需要 1001 根 K 线的数据，因此它将下载 2000 根 K 线的数据，这意味着将有 1 根“当前 K 线”和 1999 根“启动 K 线”。

此外，交易所限制了连续批量 API 调用的次数，例如币安允许 5 次调用。在这种情况下，在不触及 API 速率限制的前提下，只能从币安 API 下载 5000 根 K 线，这意味着您可以拥有的最大 `startup_candle_count` 是 4999。

请注意，交易所可能会在未来随时更改此 K 线限制，恕不另行通知。

### 命令是如何运作的？

- 首先，使用提供的时间范围执行初始指标计算，以为指标值生成基准。
- 设定基准后，它将针对每一个不同的启动 K 线计数值执行额外的运行。
- 然后，该命令将比较最后一根 K 线行的指标值，并在表格中报告差异。

## 理解递归分析的输出

这是一个输出结果表的示例，其中至少有一个指标存在递归公式问题：

```text
| 指标         | 20      | 40      | 80     | 100    | 150     | 300     | 999    |
|--------------+---------+---------+--------+--------+---------+---------+--------|
| rsi_30       | nan%    | -6.025% | 0.612% | 0.828% | -0.140% | 0.000%  | 0.000% |
| rsi_14       | 24.141% | -0.876% | 0.070% | 0.007% | -0.000% | -0.000% | -      |
```

列标题表示分析中使用的不同 `startup_candle_count`。表格中的数值表示与基准值相比，计算出的指标的差异百分比。

`nan%` 表示由于缺少数据，该指标的值无法计算。在此例中，仅凭 21 根 K 线（1 根当前 K 线 + 20 根启动 K 线）是不可能计算周期为 30 的 RSI 的。

用户应评估每个指标的表格，以决定指定的 `startup_candle_count` 是否产生了足够小的差异，使得该指标对进场和/或离场没有影响。

因此，追求绝对的零偏差（由 `-` 值表示）可能不是最佳方案，因为某些指标可能需要极长的 `startup_candle_count` 才能达到零偏差。

## 注意事项

- `recursive-analysis` 仅计算并比较最后一行的指标值。输出表报告了不同启动 K 线计数计算与原始基准计算之间的百分比差异。至于这是否对您的进场和离场有实际影响，则不在包含之列。
- 理想的情况是，尽管启动 K 线不同，指标也不应该有差异（或至少非常接近 0%）。现实中，像 EMA 这样的指标使用递归公式来计算值，所以目标不一定是百分比差异为零，而是使差异足够低（因此 `startup_candle_count` 足够高），从而使指标固有的递归不会对交易决策产生任何实际影响。
- `recursive-analysis` 仅对 `populate_indicators` 和 `@informative` 装饰器运行计算。如果您将任何指标计算放在 `populate_entry_trend` 或 `populate_exit_trend` 中，它将不会被计算。
