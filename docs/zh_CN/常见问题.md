# Freqtrade 常见问题 (FAQ)

## 支持的市场

Freqtrade 支持现货交易，以及选定交易所的期货交易。请参阅 [文档起始页](index.md#supported-futures-exchanges-experimental) 获取受支持交易所的最新列表。

### 我的机器人可以开空单（Short）吗？

Freqtrade 可以在期货市场开空。
这需要策略专门为此编写，并在配置中设置 `"trading_mode": "futures"`。
请务必先阅读 [相关文档页面](leverage.md)。

在现货市场，在某些情况下，您可以交易杠杆现货代币，这些代币反映了反向交易对（例如 BTCUP/USD, BTCDOWN/USD, ETHBULL/USD, ETHBEAR/USD 等），Freqtrade 可以交易这些代币。

### 我的机器人可以交易期权（Options）或期货（Futures）吗？

选定的交易所支持期货交易。请参阅 [文档起始页](index.md#supported-futures-exchanges-experimental) 获取受支持交易所的最新列表。

## 初学者小贴士

* 当您编写策略和超参数优化（Hyperopt）文件时，应使用专业的代码编辑器，如 VSCode 或 PyCharm。一个好的代码编辑器将提供语法高亮以及行号，方便查找语法错误（Freqtrade 在启动期间通常会指出这些错误）。

## Freqtrade 常见问题

### Freqtrade 可以并行针对同一个交易对开多个仓位吗？

不可以。Freqtrade 每次只能针对每个交易对开一个仓位。
不过，您可以使用 [`adjust_trade_position()` 回调](strategy-callbacks.md#adjust-trade-position) 来调整已开仓位。

回测在 `--eps` 选项中提供了此功能，但这仅仅是为了突出“隐藏的”信号，在实盘中无效。

### Freqtrade 支持测试网（Sandbox/Testnet）账号吗？

不支持。但您可以使用干跑（Dry-run）模式来模拟交易，而无需承担真实资金风险。

测试网市场是独立的模拟市场，不适合在现实环境中测试您的策略。这些市场通常具有不同的订单簿、流动性和交易行为（通常参与者非常少），因此不适合对策略进行现实的测试。

### 机器人无法启动

运行 `freqtrade trade --config config.json` 显示输出 `freqtrade: command not found`。

这可能是由以下原因引起的：

* 虚拟环境未激活。
  * 运行 `source .venv/bin/activate` 来激活虚拟环境。
* 安装未成功完成。
  * 请检查 [安装文档](installation.md)。

### 机器人启动了，但处于 STOPPED（停止）模式

确保您在 `config.json` 中将 `initial_state` 配置选项设置为 `"running"`。

### 我已经等了 5 分钟了，为什么机器人还没进行任何交易？

* 取决于入场策略、白名单代币数量、市场状况等，寻找一个好的交易入场仓位可能需要数小时或数天。请保持耐心！

* 回测会告诉您大概预期的交易频率，但这并不保证它们会随时间均匀分布。您可能在一天内有 20 笔交易，而本周余下的时间里一笔都没有。

* 可能是由于配置错误。最好检查日志，它们通常会告诉你机器人是否根本没有收到买入信号（仅心跳消息），或者是否有问题（日志中的错误/异常）。

### 我已经做了 12 笔交易了，为什么我的总利润是负的？

我理解您的失望，但不幸的是，12 笔交易还不足以说明问题。如果您运行回测，您可以看到当前的算法确实能让您获利，但这是在成千上万次交易之后的结果。即使在那时，您在交易了数十次甚至数百次的特定代币上可能仍会亏损。我们当然不断力求改进机器人，但这始终是一个博弈，它应该能为您带来每月的小幅盈利，但您无法从几笔交易中得出太多结论。

### 我想修改配置。我可以在不杀死机器人的情况下做到吗？

可以。您可以编辑配置并使用 `/reload_config` 命令重新加载配置。机器人将停止，重新加载配置和策略，并使用新的配置和策略重新启动。

### 为什么我的机器人没有卖掉它买入的所有东西？

这被称为“代币粉尘（Coin Dust）”，在所有交易所都可能发生。
这是因为许多交易所会从“接收货币”中扣除费用。例如：您买入 100 个代币，但您只收到了 99.9 个代币。由于该代币是以完整的整份大小（例如 1 个步骤）交易的，您无法卖出 0.9 个（或 99.9 个），而需要向下舍入到 99 个卖出。

这不是机器人的问题，手动交易也会发生这种情况。

虽然 Freqtrade 可以处理这种情况（它会卖出 99 个），但费用通常低于最小交易单位。将粉尘（0.9 个）留在交易所通常是有意义的，因为下次 Freqtrade 买入该代币时，它会消耗剩余的微小余额，这次卖出它买入的所有东西，从而慢慢降低粉尘余额（尽管它很可能永远不会达到精确的 0）。

在可能的情况下（例如在币安上），使用交易所专门的费用抵扣货币将解决此问题。在币安上，只要您的账户中有 BNB，并在您的个人资料中启用了“使用 BNB 支付费用”即可。您的 BNB 余额会缓慢下降，但您将不再遇到粉尘问题（Freqtrade 会将费用计入利润计算中）。其他交易所没有提供此类可能性，您只能接受或更换交易所。

### 我向交易所存入了更多资金，但我的机器人没识别出来

Freqtrade 会在必要时（下订单前）更新交易所余额。RPC 调用（Telegram 的 `/balance`，API 调用的 `/balance`）最高每小时触发一次。

如果启用了 `adjust_trade_position`（且机器人有符合仓位调整条件的未平仓交易），则钱包余额将每小时刷新一次。要强制立即更新，您可以使用 `/reload_config`，这将重启机器人。

### 我想使用不完整的 K 线

Freqtrade 不会为策略提供不完整的 K 线。使用不完整的 K 线会导致重绘（Repainting），从而导致策略出现“幽灵”买入，这在回测和事后验证中都是不可能实现的。

您可以通过使用 [数据提供者（Dataprovider）](strategy-customization.md#orderbookpair-maximum) 的挂单簿（Orderbook）或行情（Ticker）方法来使用“当前”市场数据，但这在回测期间无法使用。

### 是否有一项设置可以只卖出持有的交易而不执行任何新的入场？

您可以在 Telegram 中使用 `/stopentry` 命令阻止未来的交易入场，然后使用 `/forceexit all`（平仓所有未平仓位）。

### 我卖掉了机器人的资金，现在日志里出错了

Freqtrade 假设其开启的交易仅通过机器人管理。
如果您（意外地）卖掉了机器人的资金，Freqtrade 会尝试通过重新寻找交易所订单来恢复。

这是一项尽力而为的方法，并非在所有情况下都有效，特别是当使用 Freqtrade 不支持的订单类型（OCO、冰山等），或处理较旧的交易（交易所不再提供完整的订单信息）时。具体的限制在交易所之间有所不同，细节通常记录在交易所的 API 文档中。

### 我想在同一台机器上运行多个机器人

请查看 [高级设置文档页面](advanced-setup.md#running-multiple-instances-of-freqtrade)。

### 启动机器人时出现 "Impossible to load Strategy" 错误

当机器人无法加载策略时会显示此消息。通常，您可以使用 `freqtrade list-strategies` 列出所有可用的策略。该命令的输出将包含状态列，显示策略是否可以加载。

请检查以下内容：

* 您是否使用了正确的策略名称？策略名称区分大小写，且必须对应策略类名（而不是文件名！）。
* 策略是否位于 `user_data/strategies` 目录中，且文件后缀是否为 `.py`？
* 机器人在报错前是否有其他警告？也许您的策略缺少一些依赖项，这会在日志中高亮显示。
* 如果是 Docker，策略目录是否挂载正确（检查 docker-compose 文件的 volumes 部分）？

### 日志中出现 "Missing data fillup" 消息

此消息只是一个警告，提示最近的 K 线中有缺失。
取决于交易所，这可能表明该交易对在您使用的时间范围内没有发生交易，而交易所仅返回有成交量的 K 线。在低成交量的交易对上，这是一个相当常见的情况。

如果这对白名单中的所有对都发生，这可能表明交易所最近宕机了。请检查交易所的公告频道了解详情。

无论原因为何，Freqtrade 都会用“空”K 线填充这些缺失，其中开盘价、最高价、最低价和收盘价都设置为上一根 K 线的收盘价，成交量为空。在图表中，这看起来像一个下划线 `_`，并与交易所通常表现 0 成交量 K 线的方式保持一致。

### 我收到 "Price jump between 2 candles detected" 提示

此消息是一项警告，提示 K 线价格跳空超过 30%。
这可能是该交易对停止交易并发生了代币更换（例如 2021 年的 COCOS，价格从 0.0000154 跳到 0.01621）的迹象。此消息通常伴随着 ["Missing data fillup"](#日志中出现-missing-data-fillup-消息)，因为这类代币的交易通常会暂停一段时间。

### 我想重置机器人的数据库

要重置机器人的数据库，您可以删除数据库文件（默认为 `tradesv3.sqlite` 或 `tradesv3.dryrun.sqlite`），或通过 `--db-url` 使用不同的数据库 URL（例如 `sqlite:///mynewdatabase.sqlite`）。

### 日志中出现 "Outdated history for pair xxx"

机器人试图告诉您它得到的是过时的最后一根 K 线（不是最后一根完整的 K 线）。
结果是 Freqtrade 不会进入该对的交易，因为根据旧信息交易通常是不理想的。

此警告可能指向以下问题之一：

* 交易所宕机 -> 检查交易所状态页 / 博客 / Twitter 动态。
* 系统时间错误 -> 确保您的系统时间准确。
* 几乎没有交易的对 -> 在交易所网页上检查该对，查看您的策略使用的时间范围。如果该对在某些 K 线中没有任何成交量（通常可视化为成交量 0 的柱状图和下划线 `_` 样式的 K 线），则该对在此时间范围内没有成交。理想情况下应避免这些交易对，因为它们会导致订单成交问题。
* API 问题 -> API 返回了错误数据（这仅作为完整性列出，在受支持的交易所不应发生）。

### 日志中收到消息 "Couldn't reuse watch for xxx"

这是一条提示信息，表示机器人尝试使用来自 Websocket 的 K 线，但交易所未能提供正确的信息。这可能是因为 Websocket 连接中断，或者该对在您使用的时间范围内没有任何交易发生。

Freqtrade 会通过回退到 REST API 优雅地处理此问题。虽然由于 REST API 调用会使迭代稍慢，但不会给机器人的运行带来任何问题。

### 我收到 "Exchange XXX does not support market orders." 消息，无法运行策略

如消息所述，您的交易所不支持市价单（Market Orders），而您的[订单类型](configuration.md/#understand-order_types)中有设置为 "market" 的项。您的策略可能是为其他交易所编写的，并为 "stoploss"（止损）订单设置了 "market" 订单，这对于大多数支持市价单的交易所是正确且首选的（但不适用于 Gate.io）。

要解决此问题，请在策略中重新定义订单类型，使用 "limit" 代替 "market"：

``` python
    order_types = {
        ...
        "stoploss": "limit",
        ...
    }
```

如果在自定义配置而不是策略中定义了订单类型，则应在配置文件中应用相同的修复。

### 我尝试启动实盘机器人，但出现 API 权限错误

类似 `Invalid API-key, IP, or permissions for action` 的错误正如其字面意思。
您的 API 密钥要么无效（复制粘贴错误？检查配置中是否有前导/尾随空格），要么已过期，或者您运行机器人的 IP 在交易所的 API 控制面板中未启用。
通常需要“现货交易 (Spot Trading)”权限（或您所用交易所的同等权限）。期货通常需要专门启用。

### 如何搜索机器人日志中的某些内容？

默认情况下，机器人将日志写入 stderr 流。这样实现是为了方便您将机器人的诊断消息与回测、Edge 和超参数优化（Hyperopt）结果、其他 Freqtrade 工具子命令的输出以及您插入策略的自定义 `print()` 输出区分开来。因此，如果您需要使用 grep 工具搜索日志消息，需要将 stderr 重定向到 stdout 并忽略 stdout。

* 在 Unix Shell 中，通常可以简单地如下操作：
```shell
$ freqtrade --some-options 2>&1 >/dev/null | grep 'something'
```
（注意，`2>&1` 和 `>/dev/null` 的编写顺序应如此）

* Bash 解释器还支持所谓的进程替换语法，您可以使用它 grep 日志中的字符串：
```shell
$ freqtrade --some-options 2> >(grep 'something') >/dev/null
```
或者
```shell
$ freqtrade --some-options 2> >(grep -v 'something' 1>&2)
```

* 您也可以通过 `--logfile` 选项将 Freqtrade 日志消息的副本写入文件：
```shell
$ freqtrade --logfile /path/to/mylogfile.log --some-options
```
然后按如下方式 grep：
```shell
$ cat /path/to/mylogfile.log | grep 'something'
```
或者在机器人运行日志增长的同时实时搜索：
```shell
$ tail -f /path/to/mylogfile.log | grep 'something'
```
（在单独的终端窗口中执行）。

在 Windows 上，Freqtrade 也支持 `--logfile` 选项，您可以使用 `findstr` 命令来搜索感兴趣的字符串：
```
> type \path\to\mylogfile.log | findstr "something"
```

## 超参数优化 (Hyperopt) 模块

### 为什么 Freqtrade 不支持 GPU？

首先，大多数指标库都不支持 GPU。因此，指标计算几乎没有收益。GPU 的改进仅适用于 Pandas 原生计算或您自己编写的计算。

GPU 仅擅长数字运算（浮点运算）。对于 Hyperopt，我们既需要数字运算（寻找下一个参数），也需要运行 Python 代码（运行回测）。因此，GPU 对于 Hyperopt 的大部分环节并不太适合。

使用 GPU 的收益将非常微薄，不足以抵消引入 GPU 支持所带来的复杂性。

如果您认为必须拥有此功能，没有什么能阻止您在策略中使用支持 GPU 的指标。但您可能会对它带来的微小提升（相对于复杂性）感到失望。

### 我需要多少个 Epoch（周期）才能获得好的 Hyperopt 结果？

默认情况下，调用 Hyperopt 时如果不带 `-e`/`--epochs` 命令行选项，它将仅运行 100 个周期。这意味着对您的触发器（Triggers）、保护（Guards）等进行 100 次评估。这对于寻找一个伟大的结果来说太少了（除非您非常幸运），所以您可能需要运行 10000 个或更多。但这将花费永恒的时间来计算。

由于 Hyperopt 使用贝叶斯搜索（Bayesian search），运行过多的周期可能不会产生更好的结果。

因此建议反复运行 500-1000 个周期，直到总计达到至少 10000 个周期（或者您对结果感到满意为止）。您最好通过观察结果来判断——如果机器人不断发现更好的策略，最好继续运行下去。

```bash
freqtrade hyperopt --hyperopt-loss SharpeHyperOptLossDaily --strategy SampleStrategy -e 1000
```

### 为什么运行 Hyperopt 需要很长时间？

* 使用 Hyperopt 发现一个伟大的策略需要时间。请研究 www.freqtrade.io，Freqtrade 文档页面，加入 Freqtrade [Discord 社区](https://discord.gg/p7nuUNVfP7)。在您耐心等待这款世界上最先进的、免费的加密货币机器人为您手递手提供为您量身定制的、可能的黄金策略时。

* 如果您好奇为什么 1000 个周期可能需要从 20 分钟到几天不等，这里有一些答案：

这个答案是在 0.15.1 版本发布期间编写的，当时我们有：

* 8 个触发器
* 9 个保护：假设我们从每个保护评估 10 个值
* 1 个止损计算：假设我们也想从中评估 10 个值

以下计算仍然非常简略且不十分精确，但它能说明问题。仅凭这些触发器和保护，就已经有 8 * 10^9 * 10 次评估。总计大约 800 亿次评估。您运行了 10 万次评估吗？恭喜你，在假设机器人从不重复测试相同参数的前提下，你大约完成了搜索空间的十万分之一。

* 运行 1000 个 Hyperopt 周期所需的时间取决于：可用的 CPU、硬盘、内存、时间范围（timeframe）、时间段（timerange）、指标设置、指标数量、Hyperopt 测试策略的代币数量以及由此产生的交易数量（根据策略旨在通过少数交易获得高利润还是追求多次低利润交易，一年可能产生 650 笔交易或 100000 笔交易）。

例如：一年的时间内，650 次获得 4% 利润 vs 10000 次一笔交易获得 0.3% 利润。假设您将 `--timerange` 设置为 365 天。

示例：
`freqtrade --config config.json --strategy SampleStrategy --hyperopt SampleHyperopt -e 1000 --timerange 20190601-20200601`
