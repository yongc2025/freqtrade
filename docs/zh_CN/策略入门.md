# Freqtrade 策略开发入门 (Strategies 101)

本入门指南假设您已熟悉交易的基本概念，并且已经阅读了 [Freqtrade 基础知识](机器人基础.md) 页面。

## 必备知识 (Required Knowledge)

Freqtrade 中的策略是一个 Python 类，它定义了买入和卖出加密货币 `资产 (assets)` 的逻辑。

资产被定义为 `交易对 (pairs)`，代表 `币种 (coin)` 和 `本位币 (stake)`。币种是您使用另一种货币（即本位币）进行交易的资产。

交易所提供的数据以 `K 线 (candles)` 的形式呈现，K 线由六个值组成：`date`（日期）、`open`（开盘价）、`high`（最高价）、`low`（最低价）、`close`（收盘价）和 `volume`（成交量）。

`技术分析 (Technical analysis)` 函数使用各种数学和统计公式分析 K 线数据，并产生二次值，称为 `指标 (indicators)`。

通过对交易对 K 线上的指标进行分析，从而产生 `信号 (signals)`。

信号在加密货币 `交易所 (exchange)` 上转化为 `订单 (orders)`，即 `交易 (trades)` 或 `头寸 (positions)`。

我们使用 `入场 (entry)` 和 `出场 (exit)` 而不是 `买入 (buying)` 和 `卖出 (selling)`，因为 Freqtrade 同时支持 `多头 (long)` 和 `空头 (short)` 交易。

- **多头 (Long)**：您根据本位币买入币种（例如使用 USDT 作为本位币买入 BTC），并通过以高于买入价的价格卖出币种来获利。在多头交易中，利润是通过币种相对于本位币贬值的贬值来赚取的。
- **空头 (Short)**：您以币种的形式从交易所借入资本，稍后按该币种的本位币价值偿还。在空头交易中，利润是通过币种相对于本位币价值下跌来赚取的（您以更低的汇率偿还贷款）。

虽然 Freqtrade 支持某些交易所的现货和期货市场，但为了简单起见，我们将仅专注于现货（多头）交易。

## 基本策略的结构 (Structure of a Basic Strategy)

### 主数据帧 (Main dataframe)

Freqtrade 策略使用一种带有行和列的表格数据结构，称为 `数据帧 (dataframe)`，用来生成入场和出场交易的信号。

您配置的交易对列表中的每个交易对都有自己的数据帧。数据帧由 `date` 列建立索引，例如 `2024-06-31 12:00`。

接下来的 5 列代表 `open`、`high`、`low`、`close` 和 `volume` (OHLCV) 数据。

### 填充指标值 (Populate indicator values)

`populate_indicators` 函数向数据帧添加代表技术分析指标值的列。

常见的指标示例包括：相对强弱指数 (RSI)、布林带 (Bollinger Bands)、资金流量指数 (MFI)、移动平均线 (Moving Average) 和平均真实波幅 (ATR)。

通过调用技术分析函数（例如 ta-lib 的 RSI 函数 `ta.RSI()`）并将其分配给一个列名（例如 `rsi`），即可将列添加到数据帧中：

```python
dataframe['rsi'] = ta.RSI(dataframe)
```

??? Hint "技术分析库"
    不同的库通过不同的方式生成指标值。请查阅各个库的文档，以了解如何将其集成到您的策略中。您还可以查看 [Freqtrade 示例策略](https://github.com/freqtrade/freqtrade-strategies) 以获取灵感。

### 填充入场信号 (Populate entry signals)

`populate_entry_trend` 函数定义了入场信号的条件。

数据帧列 `enter_long` 会被添加到数据帧中，当该列中的值为 `1` 时，Freqtrade 就会识别到一个入场信号。

??? Hint "做空"
    要开启空头交易，请使用 `enter_short` 列。

### 填充出场信号 (Populate exit signals)

`populate_exit_trend` 函数定义了出场信号的条件。

数据帧列 `exit_long` 会被添加到数据帧中，当该列中的值为 `1` 时，Freqtrade 就会识别到一个出场信号。

??? Hint "做空"
    要退出空头交易，请使用 `exit_short` 列。

## 一个简单的策略 (A simple strategy)

这是一个最简单的 Freqtrade 策略示例：

```python
from freqtrade.strategy import IStrategy
from pandas import DataFrame
import talib.abstract as ta

class MyStrategy(IStrategy):

    timeframe = '15m'

    # 设置初始止损为 -10%
    stoploss = -0.10

    # 只要利润大于 1%，随时退出盈利头寸
    minimal_roi = {"0": 0.01}

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 生成技术分析指标的值
        dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)

        return dataframe

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 根据指标值生成入场信号
        dataframe.loc[
            (dataframe['rsi'] < 30),
            'enter_long'] = 1

        return dataframe

    def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 根据指标值生成出场信号
        dataframe.loc[
            (dataframe['rsi'] > 70),
            'exit_long'] = 1

        return dataframe
```

## 执行交易 (Making trades)

当发现信号（在入场或出场列中标记为 `1`）时，Freqtrade 将尝试下单，即发起一次 `交易 (trade)` 或建立一个 `头寸 (position)`。

每个新的交易头寸占用一个 `槽位 (slot)`。槽位代表可以同时开启的最大新交易数量。

槽位数量由 [配置文件](配置文件说明.md) 中的 `max_open_trades` 选项定义。

然而，在某些情况下，即使生成了信号也不一定会创建交易订单。这些情况包括：

- 剩余可用本位币不足以购买资产，或者钱包中的资金不足以卖出资产（包括任何手续费）
- 新交易没有足够的剩余空闲槽位（您开启的头寸数量已达到 `max_open_trades` 选项的限制）
- 该交易对已经有一个开启的交易（Freqtrade 不支持头寸叠加 —— 尽管它可以 [调整现有头寸](策略回调.md#调整交易仓位)）
- 如果在同一根 K 线上同时出现入场和出场信号，它们被认为是 [冲突信号](策略自定义.md#信号冲突)，且不会发起任何订单
- 策略根据您通过相关的 [入场](策略回调.md#交易入场确认) 或 [出场](策略回调.md#交易出场确认) 回调指定的逻辑主动拒绝了交易订单

有关更多详细信息，请阅读 [策略自定义](策略自定义.md) 文档。

## 回测与模拟运行 (Backtesting and Dry run)

策略开发可能是一个漫长且令人沮丧的过程，因为将人类的“本能直觉”转化为有效的计算机控制（“算法”）策略并不总是那么直接。

因此，应该测试策略以验证其是否能按预期运行。

Freqtrade 有两种测试模式：

- **回测 (Backtesting)**：使用您 [从交易所下载](数据下载.md) 的历史数据。回测是评估策略性能的快速方法。然而，它非常容易失真，结果可能使策略看起来比实际更有利可图。有关更多信息，请查看 [回测文档](回测指南.md)。
- **模拟运行 (Dry run)**：通常被称为 _前向测试 (forward testing)_，模拟运行使用来自交易所的实时数据。Freqtrade 会像正常交易一样追踪任何会产生交易的信号，但不会在交易所本身开启任何真实交易。前向测试是实时运行的，虽然获得结果需要更长时间，但它比回测更能可靠地反映 **潜在** 性能。

模拟运行通过在您的 [配置文件](配置文件说明.md#使用模拟运行模式) 中将 `dry_run` 设置为 true 来启用。

!!! Warning "回测可能非常不准确"
    回测结果可能与现实不符的原因有很多。请查看 [回测假设](回测指南.md#回测中的假设) 和 [策略开发中的常见错误](策略自定义.md#策略开发中的常见错误) 文档。
    一些列出并对 Freqtrade 策略进行排名的网站展示了令人印象深刻的回测结果。不要假设这些结果是可以实现的或现实的。

??? Hint "实用命令"
    Freqtrade 包含两个用于检查策略基本缺陷的实用命令：[前瞻性分析 (lookahead-analysis)](lookahead-analysis.md) 和 [递归分析 (recursive-analysis)](recursive-analysis.md)。

### 评估回测和模拟运行结果

在对策略进行回测后，务必进行模拟运行，以观察回测和模拟运行结果是否足够相似。

如果存在显著差异，请验证您的入场和出场信号是否一致，以及在两种模式下的同一根 K 线上是否出现。然而，模拟运行和回测之间总会存在差异：

- 回测假设所有订单都能成交。而在模拟运行中，如果使用限价单或交易所没有成交量，则可能并非如此。
- 跟随 K 线收盘时的入场信号，回测假设交易以下一根 K 线开盘价入场（除非您的策略中有自定义定价回调）。在模拟运行中，信号和交易开启之间通常会有延迟。
  这是因为当您的主时间范围出现新 K 线时（例如每 5 分钟一次），Freqtrade 需要时间来分析所有交易对的数据帧。因此，Freqtrade 将在 K 线开启后的几秒钟（理想情况下延迟越短越好）尝试开启交易。
- 由于模拟运行中的入场汇率可能与回测不符，这意味着利润计算也会有所不同。因此，ROI、止损、追踪止损和回调出场不完全相同是正常的。
- 新 K 线进入与发出信号及开启交易之间的“计算延迟”越多，价格的不可预测性就越大。确保您的计算机足够强大，能够在合理的时间内处理您的交易对列表中的数据量。如果存在显著的数据处理延迟，Freqtrade 会在日志中向您发出警告。

## 控制或监控运行中的机器人

一旦您的机器人以模拟或实盘模式运行，Freqtrade 提供了六种机制来控制或监控正在运行的机器人：

- **[FreqUI](freq-ui.md)**：最容易入门的方式。FreqUI 是一个 Web 界面，可以查看和控制机器人的当前活动。
- **[Telegram](telegram-usage.md)**：在移动设备上，可以通过集成 Telegram 来获取有关机器人活动的警报并控制某些方面。
- **[FTUI](https://github.com/freqtrade/ftui)**：FTUI 是 Freqtrade 的终端（命令行）界面，仅允许监控运行中的机器人。
- **[freqtrade-client](rest-api.md#使用-api)**：REST API 的 Python 实现，使您可以轻松地从 Python 应用程序或命令行发出请求并接收机器人响应。
- **[REST API 端点](rest-api.md#可用端点)**：REST API 允许程序员开发自己的工具与 Freqtrade 机器人进行交互。
- **[Webhooks](webhook-config.md)**：Freqtrade 可以通过 webhook 向其他服务（例如 Discord）发送信息。

### 日志 (Logs)

Freqtrade 生成详尽的调试日志，以帮助您了解发生了什么。请熟悉您在机器人日志中可能看到的各种信息和错误消息。

默认情况下，日志输出到标准输出（命令行）。如果您想将其写入文件，许多 freqtrade 命令（包括 `trade` 命令）都接受 `--logfile` 选项来指定日志文件。

查看 [常见问题解答 (FAQ)](常见问题.md#如何在机器人日志中搜索某些内容) 了解示例。

## 结语 (Final Thoughts)

算法交易相当困难，而且大多数公开的策略并不能维持良好的表现，因为让策略在多种情况下都能盈利需要投入大量的时间和精力。

因此，获取公开策略并使用回测来评估性能通常是有问题的。然而，Freqtrade 提供了非常有用的方式来帮助您做出决策并进行尽职调查。

实现盈利的方式有很多，并没有哪一个单一的秘诀、技巧或配置选项可以修复表现不佳的策略。

Freqtrade 是一个开源平台，拥有一个庞大且乐于助人的社区 —— 务必访问我们的 [Discord 频道](https://discord.gg/p7nuUNVfP7) 与他人讨论您的策略！

一如既往，请仅投资您能够承受损失的资金。

在 Freqtrade 中开发策略涉及根据技术指标定义入场和出场信号。通过遵循上述结构和方法，您可以创建并测试自己的交易策略。
