# 配置文件说明

Freqtrade 拥有许多可配置的功能。默认情况下，这些功能可以通过配置文件进行设置。

## Freqtrade 配置文件

机器人使用一组参数运行，这些参数共同构成了配置。默认情况下，机器人会检查当前工作目录中是否存在名为 `config.json` 的文件。

您可以使用 `-c/--config` 命令行参数指定一个或多个配置文件。

如果您遵循了 [快速入门](docker_quickstart.md#docker-quick-start) 指南，安装脚本已经为您创建了一个包含所有必要参数的默认配置文件 (`config.json`)。

如果您还没有配置文件，可以使用 `freqtrade new-config --config user_data/config.json` 来创建一个基本的配置文件。

配置文件采用 JSON 格式。Freqtrade 的配置解析器还支持单行 (`// ...`) 和多行 (`/* ... */`) 注释，以及列表后的尾随逗号。

如果您不熟悉 JSON 格式，不用担心。只需在最喜欢的文本编辑器中打开文件，根据需要调整参数。文件修改后需要重启机器人。Freqtrade 在启动时会验证配置文件格式是否正确，如果格式错误，会打印出错误行以便您更正。

### 环境变量

Freqtrade 允许通过环境变量设置配置项。环境变量将对所有配置参数具有最高优先级（覆盖配置文件和策略，但低于命令行参数）。

环境变量必须以 `FREQTRADE__` 开头（注意是双下划线）。配置结构中的层次结构也用双下划线 `__` 分隔。

- `export FREQTRADE__STAKE_AMOUNT=200` 将设置 `stake_amount`。
- `export FREQTRADE__EXCHANGE__KEY=<yourExchangeKey>` 将设置 `exchange.key`。

任何可以在配置文件中作为顶层或子层配置项使用的设置都可以通过这种方式设置。

以下是一些常见设置：

``` bash
export FREQTRADE__STAKE_AMOUNT=200
export FREQTRADE__DRY_RUN=true
export FREQTRADE__TELEGRAM__ENABLED=true
export FREQTRADE__TELEGRAM__TOKEN=<yourTelegramToken>
export FREQTRADE__TELEGRAM__CHAT_ID=<yourTelegramChatId>
```

设置这些变量后，启动机器人就不再强制要求已包含这些参数的配置文件。

!!! Warning "警告"
    环境变量对系统中的其他程序可见。请谨慎使用环境变量设置密钥或机密信息（尤其是 `exchange.key` 和 `exchange.secret`）。

## 配置参数摘要

下表列出了所有配置参数。除非另有说明，否则所有参数均为非必需。

| 参数 | 描述 | 数据类型
| :--- | :--- | :---

| `max_open_trades` | **必需。** 同时运行的最大订单数。 [策略覆盖](#parameters-in-the-strategy)。 <br> **数据类型:** 正整数
| `stake_currency` | **必需。** 交易所中用于交易的货币（例如：BTC, ETH, USDT 等）。这需要是您钱包中的可用余额。 <br> **数据类型:** 字符串
| `stake_amount` | **必需。** 每个订单要花费的筹码货币数量。将其设置为 `"unlimited"` 以动态利用所有可用余额。 [更多信息](#configuring-amount-per-trade)。 <br> **数据类型:** 正浮点数或 `"unlimited"`
| `tradable_balance_ratio` | 账户余额中允许机器人使用的比例。 [更多信息](#tradable-balance)。 <br>*默认为 `0.99` (99%)。*<br>**数据类型:** 浮点数 (作为比例)
| `available_capital` | 限制机器人可用的初始资金。 [更多信息](#assign-available-capital)。 <br>**数据类型:** 正浮点数
| `amend_last_stake_amount` | 如果最后一个可用的筹码数量不完全等于 `stake_amount`，是否自动调整。 [更多信息](#amend-last-stake-amount)。<br>*默认为 `false`*。<br>**数据类型:** 布尔值
| `last_stake_amount_min_ratio` | 允许的最小最后筹码比例（相对于 `stake_amount`）。 [更多信息](#amend-last-stake-amount)。<br>*默认为 `0.5`*。<br>**数据类型:** 浮点数 (作为比例)
| `fiat_display_currency` | 用于以法定货币（例如：USD, EUR, CNY 等）显示结果的法币名称。 [更多信息](#fiat-conversion)。 <br> **数据类型:** 字符串
| `dry_run` | 启用或禁用干跑模式（模拟交易）。 [更多信息](#using-dry-run-mode)。 <br> **数据类型:** 布尔值
| `dry_run_wallet` | 干跑模式下的起始资金。可以是浮点数或带有每种货币金额的字典。 [更多信息](#dry-run-wallet) <br>*默认为 `1000`。*<br> **数据类型:** 正浮点数或字典

| `timeframe` | 为策略定义的时间范围（K 线间隔）。 [策略覆盖](#parameters-in-the-strategy)。 <br> **数据类型:** 字符串 (例如: `5m`, `1h`)
| | **止损**
| `stoploss` | 默认止损百分比（作为负浮点数）。例如: `-0.10` 表示 10% 止损。 [更多信息](stoploss.md)。 [策略覆盖](#parameters-in-the-strategy)。 <br> **数据类型:** 负浮点数
| `trailing_stop` | 启动追踪止损。 [更多信息](stoploss.md#trailing-stop-loss)。 [策略覆盖](#parameters-in-the-strategy)。 <br>*默认为 `false`。* <br> **数据类型:** 布尔值
| `trailing_stop_positive` | 一旦达到此止盈水平，追踪止损将变为正值。 [更多信息](stoploss.md#trailing-stop-loss)。 [策略覆盖](#parameters-in-the-strategy)。 <br> **数据类型:** 正浮点数 (作为比例)
| `trailing_stop_positive_offset` | 追踪止损将偏移的价格百分比。 [更多信息](stoploss.md#trailing-stop-loss)。 [策略覆盖](#parameters-in-the-strategy)。 <br>*默认为 `0.0` (0%)。* <br> **数据类型:** 正浮点数 (作为比例)
| `trailing_only_offset_is_reached` | 仅在达到 `trailing_stop_positive_offset` 后才激活追踪止损。 [更多信息](stoploss.md#trailing-stop-loss)。 [策略覆盖](#parameters-in-the-strategy)。 <br>*默认为 `false`。* <br> **数据类型:** 布尔值
| `use_custom_stoploss` | 是否在策略中使用自定义止损逻辑。 [更多信息](strategy-callbacks.md#custom-stoploss)。 [策略覆盖](#parameters-in-the-strategy)。 <br>*默认为 `false`。* <br> **数据类型:** 布尔值

| `custom_price_max_distance_ratio` | 配置当前价格与自定义进场或出场价格之间的最大距离率。 <br>*默认为 `0.02` (2%)。*<br> **数据类型:** 正浮点数
| | **订单/信号处理**

### 配置每笔交易的金额

有几种方法可以配置机器人将使用多少筹码货币进入交易。所有方法都遵循如下所述的 [可用余额配置](#tradable-balance)。

#### 最小交易筹码

最小筹码金额取决于交易所和交易对，通常在交易所支持页面中列出。

假设 XRP/USD 的最小既定交易量为 20 XRP（由交易所给出），价格为 0.6 美元，则购买该交易对的最小筹码金额为 `20 * 0.6 ~= 12`。
该交易所还对美元有限制 - 所有订单必须 > 10 美元 - 但在这种情况下不适用。

为了保证安全执行，freqtrade 不允许以 10.1 美元的筹码金额购买，而是会确保有足够的空间在交易对下方设置止损（+ 一个偏移量，由 `amount_reserve_percent` 定义，默认为 5%）。

如果在保留 5% 的情况下，最小筹码金额约为 12.6 美元 (`12 * (1 + 0.05)`)。如果我们在此基础上再考虑 10% 的止损 - 我们最终得到的金额约为 14 美元 (`12.6 / (1 - 0.1)`)。

为了在止损值较大的情况下限制此计算，计算出的最小筹码限制永远不会超过实际限制的 50%。

!!! Warning "警告"
    由于交易所的限制通常很稳定且不经常更新，一些交易对可能会显示相当高的最小限制，仅仅是因为自交易所上次调整限制以来价格上涨了很多。Freqtrade 会将筹码金额调整到此值，除非它比计算/所需的筹码金额高出 30% 以上 - 在这种情况下，交易将被拒绝。

#### 干跑钱包

在干跑模式下运行时，机器人将使用模拟钱包执行交易。该钱包的起始余额由 `dry_run_wallet` 定义（默认为 1000）。
对于更复杂的场景，您还可以向 `dry_run_wallet` 分配一个字典，以定义每种货币的起始余额。

```json
"dry_run_wallet": {
    "BTC": 0.01,
    "ETH": 2,
    "USDT": 1000
}
```

命令行选项 (`--dry-run-wallet`) 可用于覆盖配置值，但仅限于浮点值，不适用于字典。如果您想使用字典，请调整配置文件。

!!! Note "注意"
    不属于筹码货币的余额将不用于交易，但会作为钱包余额的一部分显示。
    在全仓杠杆交易所，钱包余额可用于计算可用的交易抵押品。

#### 可支配余额

默认情况下，机器人假设 `全部金额 - 1%` 由其支配，当使用 [动态筹码金额](#dynamic-stake-amount) 时，它会将全部余额分成 `max_open_trades` 个桶（Bucket）用于每笔交易。
Freqtrade 在进入交易时会保留 1% 以备支付费用，因此默认情况下不会动用这部分资金。

您可以使用 `tradable_balance_ratio` 设置来配置 "不触动" 的金额。

例如，如果您的交易所钱包中有 10 ETH 可用，并且 `tradable_balance_ratio=0.5`（即 50%），那么机器人将最多使用 5 ETH 进行交易，并将其视为可用余额。钱包的其余部分不受交易影响。

!!! Danger "危险"
    在同一账户上运行多个机器人时，**不应**使用此设置。请查看 [分配给机器人的可用资本](#assign-available-capital)。

!!! Warning "警告"
    `tradable_balance_ratio` 设置适用于当前余额（可用余额 + 占用交易的余额）。因此，假设起始余额为 1000，配置 `tradable_balance_ratio=0.99` 不能保证交易所始终保留 10 个货币单位。例如，如果总余额减少到 500（由于连败或提现余额），可用金额可能会减少到 5 个单位。

#### 分配可用资本

为了在同一交易所账户上使用多个机器人时充分利用复利利润，您需要限制每个机器人的起始余额。
这可以通过将 `available_capital` 设置为所需的起始余额来实现。

假设您的账户有 10000 USDT，并且您想在此交易所运行 2 种不同的策略。
您可以设置 `available_capital=5000` - 给予每个机器人 5000 USDT 的初始资金。
机器人然后会将这个起始余额平均分配到 `max_open_trades` 个桶中。
盈利的交易将导致该机器人的筹码规模增加 - 而不影响另一个机器人的筹码规模。

调整 `available_capital` 需要重新加载配置才能生效。调整 `available_capital` 会增加之前的 `available_capital` 与新的 `available_capital` 之间的差值。在交易进行中减少可用资本不会平仓交易。当交易结束时，差额将返回到钱包。其结果取决于调整和交易平仓之间的价格变动。

!!! Warning "警告：与 `tradable_balance_ratio` 不兼容"
    设置此选项将替换 `tradable_balance_ratio` 的任何配置。

#### 修改最后一个筹码金额

假设我们的可交易余额为 1000 USDT，`stake_amount=400`，且 `max_open_trades=3`。
机器人将开始 2 笔交易，并且无法填充最后一个交易位置，因为已经有 800 USDT 被占用在其他交易中，所需的 400 USDT 已不再可用。

为了克服这个问题，可以将选项 `amend_last_stake_amount` 设置为 `True`，这将使机器人能够将最后的一笔筹码金额减少到可用余额，以填满最后一个交易位置。

在上面的示例中，这将意味着：

* 交易1: 400 USDT
* 交易2: 400 USDT
* 交易3: 200 USDT

!!! Note "注意"
    此选项仅适用于 [静态筹码金额](#static-stake-amount) - 因为 [动态筹码金额](#dynamic-stake-amount) 会均匀分配余额。

!!! Note "注意"
    最小最后筹码金额可以使用 `last_stake_amount_min_ratio` 进行配置 - 默认值为 0.5 (50%)。这意味着使用的最小筹码金额始终是 `stake_amount * 0.5`。这可以避免使用非常低的筹码金额（接近该交易对的最小可交易金额）而被交易所拒绝。

#### 静态筹码金额

`stake_amount` 配置静态地配置了您的机器人将为每笔交易使用的筹码货币数量。

最小配置值为 0.0001，但是，请检查您正在使用的筹码货币的交易所交易最小值，以避免出现问题。

此设置与 `max_open_trades` 结合使用。投入交易的最大资金为 `stake_amount * max_open_trades`。
例如，假设配置为 `max_open_trades=3` 且 `stake_amount=0.05`，机器人最多将使用 (0.05 BTC x 3) = 0.15 BTC。

!!! Note "注意"
    此设置遵循 [可用余额配置](#tradable-balance)。

#### 动态筹码金额

或者，您可以使用动态筹码金额，它将使用交易所在使用的可用余额，并将其平均除以允许的交易数量 (`max_open_trades`)。

要进行此配置，请设置 `stake_amount="unlimited"`。我们还建议将 `tradable_balance_ratio=0.99` (99%) - 以保留用于支付最终费用的最低余额。

在这种情况下，交易金额计算如下：

```python
currency_balance / (max_open_trades - current_open_trades)
```

要允许机器人交易您账户中所有可用的 `stake_currency`（减去 `tradable_balance_ratio`），请设置：

```json
"stake_amount" : "unlimited",
"tradable_balance_ratio": 0.99,
```

!!! Tip "小技巧：复利利润"
    这种配置将允许根据机器人的表现增加/减少筹码（如果机器人亏损，筹码就会减少；如果机器人有获胜记录，由于可用余额较高，筹码就会增加），并产生复利利润。

!!! Note "注意：使用干跑模式时"
    当 `"stake_amount" : "unlimited"` 与干跑、回测或超参数优化结合使用时，余额将从 `dry_run_wallet` 开始模拟并不断演变。
    因此，将 `dry_run_wallet` 设置为一个合理的值（例如，BTC 为 0.05 或 0.01，USDT 为 1000 或 100）非常重要，否则，它可能会一次性模拟 100 BTC（或更多）或 0.05 USDT（或更少）的交易 - 这可能不符合您的实际可用余额，或者低于交易所对该筹码货币订单金额的最小限制。

#### 带有仓位调整的动态筹码金额

当您想在无限筹码的情况下使用仓位调整时，您还必须实现 `custom_stake_amount` 以根据您的策略返回一个值。
典型值在建议筹码的 25% - 50% 范围内，但这在很大程度上取决于您的策略以及您希望留在钱包中作为补仓缓冲的金额。

例如，如果您补仓逻辑假设可以使用相同的筹码金额进行 2 次额外购买，那么您的缓冲区应该是最初建议的无限筹码金额的 66.6667%。

或者另一个例子，如果您的仓位调整假设可以用原始筹码金额的 3 倍进行 1 次额外购买，那么 `custom_stake_amount` 应返回建议筹码金额的 25%，并保留 75% 以备以后可能的补仓。

## 更多配置细节

### 理解 minimal_roi

`minimal_roi` 配置参数是一个 JSON 对象，其中键是以分钟为单位的持续时间，值是作为比例的最小投资回报率（ROI）。
请参见下面的示例：

```json
"minimal_roi": {
    "40": 0.0,    // 40 分钟后如果利润不为负则离场
    "30": 0.01,   // 30 分钟后如果有至少 1% 的利润则离场
    "20": 0.02,   // 20 分钟后如果有至少 2% 的利润则离场
    "0":  0.04    // 如果有至少 4% 的利润则立即离场
},
```

大多数策略文件已经包含了最佳 `minimal_roi` 值。
此参数可以在策略或配置文件中设置。如果在配置文件中使用它，它将覆盖策略文件中的 `minimal_roi` 值。
如果在策略或配置中均未设置，则使用默认值 1000% `{"0": 10}`，除非您的交易产生 1000% 的利润，否则最小 ROI 将被禁用。

!!! Note "注意：特定时间后强制离场的特殊情况"
    一个特殊情况是使用 `"<N>": -1` 作为 ROI。这会强制机器人在 N 分钟后退出交易，无论其利润是正还是负，因此代表限时强制离场。

### 理解 force_entry_enable

`force_entry_enable` 配置参数允许通过 Telegram 和 REST API 使用强制进场（`/forcelong`，`/forceshort`）命令。
出于安全原因，默认情况下它是禁用的，如果启用，freqtrade 将在启动时显示警告消息。
例如，您可以向机器人发送 `/forceenter ETH/BTC`，这将导致 freqtrade 购买该交易对并持有它，直到出现常规离场信号（ROI、止损、/forceexit）出现。

这对某些策略来说可能很危险，因此请谨慎使用。

有关详细用法，请参阅 [Telegram 文档](telegram-usage.md)。

### 忽略过期 K 线

当使用较大的时间范围（例如 1 小时或更多）并使用较低的 `max_open_trades` 值时，一旦交易空位可用，就可以处理最后一根 K 线。当处理一根 K 线时，这可能会导致在某些情况下不希望在该 K 线上使用买入信号。例如，在策略中使用交叉（cross-over）条件时，对于您来说，该点可能已经过去太久，无法在其上开始交易。

在这些情况下，您可以通过将 `ignore_buying_expired_candle_after` 设置为正数来启用忽略超过指定期限的 K 线功能，该正数表示买入信号过期的秒数。

例如，如果您的策略使用 1 小时级别，并且您只想在出现新 K 线后的前 5 分钟内买入，则可以将以下配置添加到策略中：

``` json
  {
    //...
    "ignore_buying_expired_candle_after": 300,
    // ...
  }
```

!!! Note "注意"
    此设置在每根新 K 线出现时都会重置，因此它不会阻止持续信号在它们处于活动状态的第 2 或第 3 根 K 线上执行。最好对买入信号使用 "触发器（trigger）" 选择器，它们仅对一根 K 线有效。

### 理解 order_types

`order_types` 配置参数将操作（`entry`、`exit`、`stoploss`、`emergency_exit`、`force_exit`、`force_entry`）映射到订单类型（`market`、`limit` 等），并配置交易所止损并在几秒钟内定义交易所止损更新间隔。

这允许使用限价单（limit）进场、使用限价单离场以及使用市价单（market）创建止损。
它还允许设置 "交易所止损（on exchange）"，这意味着一旦买单完成，止损订单将立即下达。

在配置文件中设置的 `order_types` 会覆盖作为整体设置在策略中的值，因此您需要在一个地方配置整个 `order_types` 字典。

如果配置了此项，则需要存在以下 4 个值（`entry`、`exit`、`stoploss` 和 `stoploss_on_exchange`），否则机器人将无法启动。

有关 (`emergency_exit`、`force_exit`、`force_entry`、`stoploss_on_exchange`、`stoploss_on_exchange_interval`、`stoploss_on_exchange_limit_ratio`) 的详细信息，请参阅止损文档 [交易所止损](stoploss.md)

策略语法：

```python
order_types = {
    "entry": "limit",
    "exit": "limit",
    "emergency_exit": "market",
    "force_entry": "market",
    "force_exit": "market",
    "stoploss": "market",
    "stoploss_on_exchange": False,
    "stoploss_on_exchange_interval": 60,
    "stoploss_on_exchange_limit_ratio": 0.99,
}
```

配置：

```json
"order_types": {
    "entry": "limit",
    "exit": "limit",
    "emergency_exit": "market",
    "force_entry": "market",
    "force_exit": "market",
    "stoploss": "market",
    "stoploss_on_exchange": false,
    "stoploss_on_exchange_interval": 60
}
```

!!! Note "注意：市价单支持"
    并非所有交易所都支持 "市价（market）" 订单。
    如果您的交易所不支持市价单，将显示以下消息：
    `"Exchange <yourexchange> does not support market orders."` 并且机器人将拒绝启动。

!!! Warning "警告：使用市价单"
    使用市价单时，请仔细阅读 [市价单定价](#market-order-pricing) 部分。

!!! Note "注意：交易所止损"
    `order_types.stoploss_on_exchange_interval` 不是强制性的。如果您不确定自己在做什么，请不要更改其值。有关止损如何工作的更多信息，请参考 [止损文档](stoploss.md)。

    如果启用了 `order_types.stoploss_on_exchange` 并且在交易所手动取消了止损单，则机器人将创建一个新的止损单。

!!! Warning "警告：order_types.stoploss_on_exchange 失败"
    如果由于某种原因在交易所创建止损失败，则会启动 "紧急离场（emergency exit）"。默认情况下，这将使用市价单退出交易。紧急离场的订单类型可以通过设置 `order_types` 字典中的 `emergency_exit` 值来更改 - 但是不建议这样做。

### 理解 order_time_in_force

`order_time_in_force` 配置参数定义了订单在交易所执行的策略。
常用的生效时间（Time in force）有：

**GTC (Good Till Canceled - 成交为止有效):**

这在大多数情况下是默认的生效时间。这意味着订单将一直保留在交易所，直到被用户取消。它可以全部或部分成交。如果部分成交，剩余部分将保留在交易所直到取消。

**FOK (Fill Or Kill - 全额成交或取消):**

这意味着如果订单未立即且完全执行，则交易所将取消该订单。

**IOC (Immediate Or Canceled - 立即成交或取消):**

与 FOK 相同，但可以部分成交。剩余部分将由交易所自动取消。

不一定推荐使用，因为这可能会导致低于最小交易金额的部分成交。

**PO (Post only - 只做 Maker):**

只做 Maker 订单。订单要么作为 Maker 订单下达，要么被取消。
这意味着订单必须以未成交状态在挂单簿上放置至少一段时间。

请查看 [交易所文档](exchanges.md) 了解您的交易所支持的生效时间值。

#### time_in_force 配置

`order_time_in_force` 参数包含一个带有进场和离场生效时间策略值的字典。
这可以在配置文件或策略中设置。
在配置文件中设置的值会按照常规的 [优先规则](#configuration-option-prevalence) 覆盖策略中的值。

可能的值为：`GTC`（默认）、`FOK` 或 `IOC`。

``` python
"order_time_in_force": {
    "entry": "GTC",
    "exit": "GTC"
},
```

!!! Warning "警告"
    除非您知道自己在做什么并且已经研究过为特定交易所使用不同值的影响，否则请不要更改默认值。


### 法币转换

Freqtrade 使用 Coingecko API 将代币价值转换为 Telegram 报告对应的法币价值。
可以在配置文件中将法币设置为 `fiat_display_currency`。

从配置中完全删除 `fiat_display_currency` 将跳过 coingecko 的初始化，并且不会显示任何法币转换。这对于机器人的正常运行并不重要。

#### fiat_display_currency 可以使用哪些值？

`fiat_display_currency` 配置参数设置了机器人 Telegram 报告中从代币到法币转换所使用的基础货币。

有效值为：

```json
"AUD", "BRL", "CAD", "CHF", "CLP", "CNY", "CZK", "DKK", "EUR", "GBP", "HKD", "HUF", "IDR", "ILS", "INR", "JPY", "KRW", "MXN", "MYR", "NOK", "NZD", "PHP", "PKR", "PLN", "RUB", "SEK", "SGD", "THB", "TRY", "TWD", "ZAR", "USD"
```

除了法定货币外，还支持一系列加密货币。

有效值为：

```json
"BTC", "ETH", "XRP", "LTC", "BCH", "BNB"
```

#### Coingecko 频率限制问题

在某些 IP 范围内，coingecko 的频率限制非常严格。
在这种情况下，您可能希望在配置中添加您的 coingecko API 密钥。

``` json
{
    "fiat_display_currency": "USD",
    "coingecko": {
        "api_key": "your-api",
        "is_demo": true
    }
}
```

Freqtrade 同时支持 Demo 和 Pro 版 coingecko API 密钥。

Coingecko API 密钥不是机器人正常运行所必需的。它仅用于 Telegram 报告中代币到法币的转换，即使没有 API 密钥通常也能工作。

## 消费交易所 Websockets

Freqtrade 可以通过 ccxt.pro 使用 websockets。

Freqtrade 旨在确保数据始终可用。
如果 websocket 连接失败（或被禁用），机器人将回退到 REST API 调用。

如果您遇到怀疑是由 websockets 引起的问题，可以通过设置 `exchange.enable_ws` 禁用它们，该设置默认为 true。

```jsonc
"exchange": {
    // ...
    "enable_ws": false,
    // ...
}
```

如果您需要使用代理，请参阅 [代理部分](#using-a-proxy-with-freqtrade) 了解更多信息。

!!! Info "信息：推广"
    我们正在缓慢推广此功能，确保您机器人的稳定性。
    目前，使用仅限于 ohlcv 数据流。
    同时，它也仅限于少数几个交易所，更多的交易所正在不断添加中。

## 使用干跑模式

我们建议在干跑模式下启动机器人，看看机器人的行为如何以及策略的表现如何。在干跑模式下，机器人不会动用您的资金。它只是在不创建交易所交易的情况下运行实盘模拟。

1. 编辑您的 `config.json` 配置文件。
2. 将 `dry-run` 切换为 `true` 并为持久化数据库指定 `db_url`。

```json
"dry_run": true,
"db_url": "sqlite:///tradesv3.dryrun.sqlite",
```

3. 删除您的交易所 API 密钥和密钥（用空值或假凭据替换它们）：

```json
"exchange": {
    "name": "binance",
    "key": "key",
    "secret": "secret",
    ...
}
```

一旦您对干跑模式下运行的机器人表现感到满意，就可以将其切换到生产模式。

!!! Note "注意"
    模拟钱包在干跑模式下可用，并将假设起始资本为 `dry_run_wallet`（默认为 1000）。

### 干跑注意事项

* API 密钥可提供也可不提供。在干跑模式下，仅在交易所执行只读操作（即不改变账户状态的操作）。
* 钱包 (`/balance`) 根据 `dry_run_wallet` 进行模拟。
* 订单是模拟的，不会发布到交易所。
* 市价单在挂单下单的那一刻根据挂单簿成交量成交，最大滑点为 5%。
* 限价单在价格达到定义水平时成交 - 或者根据 `unfilledtimeout` 设置超时。
* 如果限价单超过价格 1% 以上，则将转换为市价单，并将立即根据常规市价单规则成交（见上面关于市价单的点）。
* 结合 `stoploss_on_exchange`，假设 stop_loss 价格可以成交。
* 在机器人重新启动后，挂单（不是存储在数据库中的交易）将保持开启状态，假设它们在离线期间未成交。

## 切换到生产模式

在生产模式下，机器人将动用您的资金。请小心，因为错误的策略可能会损失您所有的钱。
当您在生产模式下运行时，请清楚自己在做什么。

切换到生产模式时，请务必使用不同的/全新的数据库，以避免干跑交易干扰您的交易所资金，并最终玷污您的统计数据。

### 设置您的交易所账户

您将需要从交易所网站创建 API 密钥（通常会获得 `key` 和 `secret`，某些交易所还需要一个额外的 `password`），并且您需要将其插入到配置及其相应字段中或按 `freqtrade new-config` 命令的要求插入。
API 密钥通常仅用于实盘交易（真钱交易，机器人在 "生产模式" 下运行，在交易所执行真实订单），干跑（交易模拟）模式下运行机器人则不需要。当您在干跑模式下设置机器人时，您可以用空值填充这些字段。

### 将您的机器人切换到生产模式

**编辑您的 `config.json` 文件。**

**将 dry-run 切换为 false，如果已设置，请务必调整您的数据库 URL：**

```json
"dry_run": false,
```

**插入您的交易所 API 密钥（将它们改为假 API 密钥）：**

```json
{
    "exchange": {
        "name": "binance",
        "key": "af8ddd35195e9dc500b9a6f799f6f5c93d89193b",
        "secret": "08a9dc6db3d7b53e1acebd9275677f4b0a04f1a5",
        //"password": "", // 可选，并非所有交易所都需要)
        // ...
    }
    //...
}
```

您还应该确保阅读文档的 [交易所](exchanges.md) 部分，以了解特定于您的交易所的潜在配置细节。

!!! Hint "提示：保守秘密"
    为了保守您的秘密，我们建议为您的 API 密钥使用第二个配置。
    只需在新的配置文件（例如 `config-private.json`）中使用上述代码片段，并在此文件中保存您的设置。
    您可以然后使用 `freqtrade trade --config user_data/config.json --config user_data/config-private.json <...>` 启动机器人来加载您的密钥。

    **永远不要**把您的私人配置文件或您的交易所密钥分享给任何人！

## 在 Freqtrade 中使用代理

要在 freqtrade 中使用代理，请使用设置为适当值的变量 `"HTTP_PROXY"` 和 `"HTTPS_PROXY"` 导出您的代理设置。
这将使代理设置应用于除交易请求**之外**的（Telegram、Coingecko 等）所有内容。

``` bash
export HTTP_PROXY="http://addr:port"
export HTTPS_PROXY="http://addr:port"
freqtrade
```

### 代理交易所请求

要对交易所连接使用代理 - 您必须将代理定义为 ccxt 配置的一部分。

``` json
{ 
  "exchange": {
    "ccxt_config": {
      "httpsProxy": "http://addr:port",
      "wsProxy": "http://addr:port",
    }
  }
}
```

有关可用代理类型的更多信息，请参阅 [ccxt 代理文档](https://docs.ccxt.com/#/README?id=proxy)。
