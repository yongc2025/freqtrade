# 已弃用功能

本页包含机器人开发团队声明为已弃用（DEPRECATED）且不再支持的命令行参数、配置参数和机器人功能的描述。请避免在您的配置中使用它们。

## 已移除的功能

### `--refresh-pairs-cached` 命令行选项

在回测、超参数优化（hyperopt）和 Edge 的上下文中，`--refresh-pairs-cached` 允许刷新用于回测的 K 线数据。
由于这会导致很多混淆，并减慢回测速度（而不属于回测本身的一部分），因此它已被拆分为单独的 freqtrade 子命令 `freqtrade download-data`。

此命令行选项在 2019.7-dev（开发分支）中弃用，并在 2019.9 中移除。

### `--dynamic-whitelist` 命令行选项

此命令行选项在 2018 年弃用，并在 freqtrade 2019.6-dev（开发分支）和 freqtrade 2019.7 中移除。
请参考 [交易对列表（Pairlists）](plugins.md#pairlists-and-pairlist-handlers)。

### `--live` 命令行选项

在回测上下文中，`--live` 允许下载最新的分笔（Tick）数据用于回测。
但由于它仅下载最新的 500 根 K 线，因此在获取良好的回测数据方面无效。
已在 2019-7-dev（开发分支）和 freqtrade 2019.8 中移除。

### `ticker_interval`（现在为 `timeframe`）

对 `ticker_interval` 术语的支持在 2020.6 中弃用，改为使用 `timeframe` - 兼容代码已在 2022.3 中移除。

### 允许按顺序运行多个交易对列表

配置文件中以前的 `"pairlist"` 部分已被移除，并由 `"pairlists"` 取代 - 这是一个用于指定交易对列表序列的列表。

旧的配置参数部分 (`"pairlist"`) 在 2019.11 中弃用，并在 2020.4 中移除。

### 从 volume-pairlist 中弃用 bidVolume 和 askVolume

由于只有报价成交量（quoteVolume）可以在资产之间进行比较，其他选项（bidVolume, askVolume）已在 2020.4 中弃用，并在 2020.9 中移除。

### 使用挂单簿步长确定离场价格

使用 `order_book_min` 和 `order_book_max` 曾允许步进挂单簿并尝试寻找下一个 ROI 插槽 - 尝试提前下达卖单。
由于这会增加风险且没有收益，出于可维护性目的，已在 2021.7 中将其移除。

### 旧版超参数优化（Hyperopt）模式

使用单独的 hyperopt 文件在 2021.4 中弃用，并在 2021.9 中移除。
请切换到新的 [参数化策略](hyperopt.md)，从新的 hyperopt 界面中受益。

## V2 和 V3 之间的策略变更

全仓/逐仓期货/做空交易在 2022.4 中引入。这需要对配置设置、策略接口等进行重大更改。

我们努力保持与现有策略的兼容性，因此如果您只想在现货市场继续使用 freqtrade，则无需进行任何更改。
虽然我们将来可能会停止对当前接口的支持，但我们会单独宣布并留出适当的过渡期。

请遵循 [策略迁移](strategy_migration.md) 指南，将您的策略迁移到新格式以开始使用新功能。

### Webhook - 2022.4 的变化

#### `buy_tag` 已重命名为 `enter_tag`

这应该仅适用于您的策略以及可能的 Webhook。
我们将在 1-2 个版本中保留兼容层（因此 `buy_tag` 和 `enter_tag` 仍将起作用），但之后 Webhook 对此的支持将消失。

#### 命名变更

Webhook 术语从 "sell" 更改为 "exit"，从 "buy" 更改为 "entry"，在此过程中移除了 "webhook"。

* `webhookbuy`, `webhookentry` -> `entry`
* `webhookbuyfill`, `webhookentryfill` -> `entry_fill`
* `webhookbuycancel`, `webhookentrycancel` -> `entry_cancel`
* `webhooksell`, `webhookexit` -> `exit`
* `webhooksellfill`, `webhookexitfill` -> `exit_fill`
* `webhooksellcancel`, `webhookexitcancel` -> `exit_cancel`

## 移除 `populate_any_indicators`

2023.3 版本移除了 `populate_any_indicators`，取而代之的是特征工程和目标的拆分方法。有关详细信息，请阅读 [迁移文档](strategy_migration.md#freqai-strategy)。

## 从配置中移除 `protections`

在引发弃用警告超过 3 年后，2024.10 版本移除了通过 `"protections": [],` 从配置中设置保护的功能。

## hdf5 数据存储

使用 hdf5 作为数据存储在 2024.12 中弃用，并在 2025.1 中移除。我们建议切换到 feather 数据格式。

更新前，请使用 [`convert-data` 子命令](data-download.md#sub-command-convert-data) 将现有的数据转换为受支持的格式之一。

## 通过配置配置高级日志

通过 `--logfile systemd` 和 `--logfile journald` 分别配置 syslog 和 journald 的功能已在 2025.3 中弃用。
请改用基于配置的 [日志设置](advanced-setup.md#advanced-logging)。

## 移除 Edge 模块

Edge 模块在 2023.9 中弃用，并在 2025.6 中移除。
Edge 的所有功能都已移除，配置 Edge 将导致错误。

## 动态资金费率处理的调整

从版本 2025.12 开始，动态资金费率的处理已调整为支持低至 1 小时资金费率间隔的动态资金费率。
因此，每个受支持的期货交易所的标记价格（mark）和资金费率（funding rate）时间范围已更改为 1 小时。

由于标记价格和资金费用 K 线的时间范围都发生了变化（通常从 8 小时改为 1 小时），已下载的数据将需要调整或部分重新下载。
您可以重新下载所有内容 (`freqtrade download-data [...] --erase` - :warning: 可能耗时很长) - 或有选择地下载更新的数据。

### 策略

大多数策略应该不需要调整即可继续按预期运行 - 但是，使用 `@informative("8h", candle_type="funding_rate")` 或类似内容的策略必须将时间范围切换为 1 小时。
对 `dp.get_pair_dataframe(metadata["pair"], "8h", candle_type="funding_rate")` 也是如此 - 需要切换到 1 小时。

freqtrade 将自动调整时间范围，即使给出的时间范围错误，也会返回 `funding_rates`。它会发出警告 - 并且可能仍会破坏您的策略。

### 有选择性地重新下载数据

下面的脚本作为一个示例 - 您可能需要根据需要调整时间范围和交易所！

``` bash
# 清理不再需要的数据
rm user_data/data/<exchange>/futures/*-mark*
rm user_data/data/<exchange>/futures/*-funding_rate*

# 下载新数据（仅需执行一次以修复标记价格和资金费用数据）
freqtrade download-data -t 1h --trading-mode futures --candle-types funding_rate mark [...] --timerange <您拥有其他数据的完整时间范围>

```

上述操作的结果是您的 funding_rates 和标记价格数据将具有 1 小时的时间范围。
您可以使用 `freqtrade list-data --exchange <您的交易所> --show` 进行验证。

!!! Note "额外参数"
    如果上述命令偏离默认设置，可能需要使用额外的参数，例如配置文件或显式指定的 user_data。

**Hyperliquid** 现在是一个特例 - 它不再需要 1 小时标记数据 - 而是将使用常规 K 线（此数据从未存在过，且与 1 小时期货 K 线相同）。由于我们不支持 Hyperliquid 的 download-data（它们不提供历史数据），因此 Hyperliquid 用户不需要采取任何行动。

## freqAI 中的 Catboost 模型

CatBoost 模型已在 2025.12 版本中移除，不再受到积极支持。
如果您有现有的使用 CatBoost 模型的机器人，您仍然可以通过从 Git 历史记录（如下链接所示）中复制/粘贴它们并手动安装 Catboost 库来在您的自定义模型中使用它们。
但是，我们建议切换到其他受支持的模型库，如 LightGBM 或 XGBoost，以获得更好的支持和未来的开发兼容性。

* [CatboostRegressor](https://github.com/freqtrade/freqtrade/blob/c6f3b0081927e161a16b116cc47fb663f7831d30/freqtrade/freqai/prediction_models/CatboostRegressor.py)
* [CatboostClassifier](https://github.com/freqtrade/freqtrade/blob/c6f3b0081927e161a16b116cc47fb663f7831d30/freqtrade/freqai/prediction_models/CatboostClassifier.py)
* [CatboostClassifierMultiTarget](https://github.com/freqtrade/freqtrade/blob/c6f3b0081927e161a16b116cc47fb663f7831d30/freqtrade/freqai/prediction_models/CatboostClassifierMultiTarget.py)
