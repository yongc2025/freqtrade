# 策略回调 (Strategy Callbacks)

虽然主要的策略函数 (`populate_indicators()`, `populate_entry_trend()`, `populate_exit_trend()`) 应该以向量化方式使用，并且在 [回测期间仅调用一次](bot-basics.md#回测与超参优化的执行逻辑)，但回调函数是在“根据需要”时被调用的。

因此，您应避免在回调中执行沉重的计算，以免在操作过程中造成延迟。
根据所使用的回调，它们可能会在入场/出场交易时，或在整个交易持续期间被调用。

目前可用的回调：

* [`bot_start()`](#机器人启动)
* [`bot_loop_start()`](#机器人循环开始)
* [`custom_stake_amount()`](#投资金额管理)
* [`custom_exit()`](#自定义出场信号)
* [`custom_stoploss()`](#自定义止损)
* [`custom_roi()`](#自定义-ROI)
* [`custom_entry_price()` 和 `custom_exit_price()`](#自定义订单价格规则)
* [`check_entry_timeout()` 和 `check_exit_timeout()`](#自定义订单超时规则)
* [`confirm_trade_entry()`](#交易入场确认)
* [`confirm_trade_exit()`](#交易出场确认)
* [`adjust_trade_position()`](#调整交易仓位)
* [`adjust_order_price()`](#调整订单价格)
* [`leverage()`](#杠杆回调)
* [`order_filled()`](#订单成交回调)

!!! Tip "提示：回调调用顺序"
    您可以在 [机器人基础](bot-basics.md#机器人执行逻辑) 中找到回调调用的完整顺序。

## 机器人启动

一个简单的回调，在加载策略时调用一次。
这可以用于执行只需执行一次的操作，并在 DataProvider 和钱包 (Wallet) 设置完成后运行。

``` python
import requests

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    def bot_start(self, **kwargs) -> None:
        """
        仅在机器人实例化后调用一次。
        :param **kwargs: 确保保留此参数，以便后续更新不会破坏您的策略。
        """
        if self.config["runmode"].value in ("live", "dry_run"):
            # 使用 self.* 将其分配给类
            # 随后可供 populate_* 方法使用
            self.custom_remote_data = requests.get("https://some_remote_source.example.com")

```

在超参数优化过程中，这仅在启动时运行一次。

## 机器人循环开始

一个简单的回调，在干跑/实盘模式下（大约每 5 秒，除非有其他配置）的每次机器人循环启动时调用一次，或者在回测/超参数优化模式下的每个 K 线启动时调用一次。
这可以用于执行与交易对无关的计算（适用于所有交易对）、加载外部数据等。

``` python
# 默认导入
import requests

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    def bot_loop_start(self, current_time: datetime, **kwargs) -> None:
        """
        在机器人迭代（一个循环）开始时调用。
        可用于执行与交易对无关的任务
        （例如获取一些远程资源进行比较）
        :param current_time: 包含当前日期时间的 datetime 对象
        :param **kwargs: 确保保留此参数。
        """
        if self.config["runmode"].value in ("live", "dry_run"):
            # 使用 self.* 将其分配给类
            # 随后可供 populate_* 方法使用
            self.remote_data = requests.get("https://some_remote_source.example.com")

```

## 投资金额管理 (Stake size management)

在入场交易之前调用，可以在下单新交易时管理您的头寸大小。

```python
# 默认导入

class AwesomeStrategy(IStrategy):
    def custom_stake_amount(self, pair: str, current_time: datetime, current_rate: float,
                            proposed_stake: float, min_stake: float | None, max_stake: float,
                            leverage: float, entry_tag: str | None, side: str,
                            **kwargs) -> float:

        dataframe, _ = self.dp.get_analyzed_dataframe(pair=pair, timeframe=self.timeframe)
        current_candle = dataframe.iloc[-1].squeeze()

        if current_candle["fastk_rsi_1h"] > current_candle["fastd_rsi_1h"]:
            if self.config["stake_amount"] == "unlimited":
                # 在复利模式下且条件有利时使用整个可用钱包余额。
                return max_stake
            else:
                # 在条件有利时滚存利润，而不是使用固定的投资额。
                return self.wallets.get_total_stake_amount() / self.config["max_open_trades"]

        # 使用默认的投资额。
        return proposed_stake
```

如果您的代码引发异常，Freqtrade 将回退到 `proposed_stake` 值。异常本身将被记录在日志中。

!!! Tip "提示"
    您不 *一定* 要确保 `min_stake <= 返回值 <= max_stake`。交易将成功，因为返回值将被限制在支持的范围内，并且此操作将被记录在日志中。

!!! Tip "提示"
    返回 `0` 或 `None` 将阻止交易下单。

## 自定义出场信号 (Custom exit signal)

在交易关闭之前，每次巡检循环（大约每 5 秒）都会为所有未平仓位调用。

允许定义自定义出场信号，表示应关闭指定的头寸（全额出场）。当我们需要为每笔独立交易自定义出场条件，或者需要交易数据来做出出场决定时，这非常有用。

例如，您可以使用 `custom_exit()` 实现 1:2 的风险回报 ROI。

不过，*不建议* 使用 `custom_exit()` 信号来代替止损。在这方面，使用 `custom_stoploss()` 是更好的方法 - 它还允许您将止损保留在交易所执行。

!!! Note "注意"
    从此方法返回（非空）`string` 或 `True` 等同于在指定时间的 K 线上设置出场信号。当已经设置了出场信号，或者禁用了出场信号 (`use_exit_signal=False`) 时，将不会调用此方法。`string` 的最大长度为 64 个字符，超过限制将被截断。
    `custom_exit()` 将忽略 `exit_profit_only` 设置，并且除非 `use_exit_signal=False`，否则始终会被调用，哪怕此时有新的入场信号。

一个关于如何根据当前利润使用不同指标，以及退出开仓时间超过一天的交易的示例：

``` python
# 默认导入

class AwesomeStrategy(IStrategy):
    def custom_exit(self, pair: str, trade: Trade, current_time: datetime, current_rate: float,
                    current_profit: float, **kwargs):
        dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
        last_candle = dataframe.iloc[-1].squeeze()

        # 利润超过 20% 时，当 RSI < 80 时卖出
        if current_profit > 0.2:
            if last_candle["rsi"] < 80:
                return "rsi_below_80"

        # 利润在 2% 到 10% 之间，如果长期 EMA 高于 短期 EMA 则卖出
        if 0.02 < current_profit < 0.1:
            if last_candle["emalong"] > last_candle["emashort"]:
                return "ema_long_below_80"

        # 如果持仓超过一天且处于亏损状态，则卖出以释放资金。
        if current_profit < 0.0 and (current_time - trade.open_date_utc).days >= 1:
            return "unclog"
```

有关在策略回调中使用 DataFrame 的更多信息，请参阅 [Dataframe 访问](strategy-advanced.md#数据帧访问)。

## 自定义止损 (Custom stoploss)

对于开仓交易，在交易关闭之前每次迭代（大约每 5 秒）都会调用一次。

必须通过在策略对象上设置 `use_custom_stoploss=True` 来启用自定义止损方法的使用。

止损价格只能向上移动 - 如果 `custom_stoploss` 返回的止损值会导致比之前设置的止损价格更低，它将被忽略。传统的 `stoploss` 值作为绝对最低水平，并将被设为初始止损（在该方法第一次被该交易调用之前），且仍然是强制性的。
由于自定义止损作为常规的可变止损运行，它的行为将类似于 `trailing_stop` - 因其出场的交易的出场原因将是 `"trailing_stop_loss"`。

该方法必须返回一个止损值（float / number），作为当前价格的百分比。
例如：如果 `current_rate` 为 200 USD，则返回 `0.02` 将把止损价格设置得低 2%，即 196 USD。
在回测期间，`current_rate`（和 `current_profit`）是根据 K 线的高点（做多）或低点（做空）提供的 - 而产生的止损则是根据 K 线的低点（做多）或高点（做空）评估的。

使用的是返回值的绝对值（忽略正负号），因此返回 `0.05` 或 `-0.05` 的结果相同，即比当前价格低 5% 的止损。
返回 `None` 将被解释为“不想改变”，这是您不想修改止损时唯一安全的返回方式。
`NaN` 和 `inf` 值被视为无效并会被忽略（等同于 `None`）。

交易所止损的工作原理类似于 `trailing_stop`，交易所的止损会按照 `stoploss_on_exchange_interval` 的配置进行更新（[关于交易所止损的更多细节](stoploss.md#交易所止损-freqtrade)）。

如果您在期货市场交易，请注意 [止损与杠杆](stoploss.md#止损与杠杆) 章节，因为 `custom_stoploss` 返回的止损值是这笔交易的风险（相对于投资额的亏损比例），而不是相对价格变动百分比。

!!! Note "注意：日期的使用"
    所有基于时间的计算都应基于 `current_time` 进行 - 不鼓励使用 `datetime.now()` 或 `datetime.utcnow()`，因为它会破坏回测支持。

!!! Tip "提示：移动止损 (Trailing stoploss)"
    使用自定义止损值时，建议禁用 `trailing_stop`。两者可以协作运行，但您可能会遇到移动止损将价格推得更高，而您的自定义函数不希望这样，从而导致冲突行为。

### 头寸调整后的止损调整

根据您的策略，您可能会发现在 [仓位调整](#调整交易仓位) 之后需要在两个方向上调整止损。
为此，Freqtrade 会在订单成交后使用 `after_fill=True` 进行额外调用，这将允许策略在任何方向移动止损（也包括扩大止损与当前价格之间的差距，这在其他情况下是被禁止的）。

!!! Note "注意：向后兼容性"
    仅当 `after_fill` 参数是您的 `custom_stoploss` 函数定义的一部分时，才会进行此调用。
    因此，这不会影响（也就不会意外惊扰到）现有的正在运行的策略。

### 自定义止损示例

下一节将展示一些使用自定义止损函数可以实现的功能。
当然，功能的实现还有很多种可能，所有示例都可以随意组合。

#### 通过自定义止损实现的移动止损

要模拟 4% 的常规移动止损（在最高价之后 4% 移动），您可以使用这个非常简单的方法：

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool, 
                        **kwargs) -> float | None:
        """
        自定义止损逻辑，返回相对于 current_rate 的新距离（作为比例）。
        例如：返回 -0.05 将创建一个比 current_rate 低 5% 的止损。
        自定义止损永远不能低于 self.stoploss，后者作为硬性最大损失限制。

        完整文档请参见 https://www.freqtrade.io/en/latest/strategy-advanced/

        如果策略未实现此方法，则返回初始止损值。
        仅在 use_custom_stoploss 设置为 True 时调用。

        :param pair: 当前分析的交易对
        :param trade: 交易对象。
        :param current_time: 包含当前日期时间的 datetime 对象
        :param current_rate: 价格，基于 exit_pricing 中的定价设置计算。
        :param current_profit: 当前利润比例，基于 current_rate 计算。
        :param after_fill: 如果止损是在订单成交后调用的，则为 True。
        :param **kwargs: 确保保留此参数。
        :return float: 新的止损值，相对于 current_rate
        """
        return -0.04 * trade.leverage
```

#### 基于时间的移动止损

在前 60 分钟内使用初始止损，之后改为 10% 的移动止损，2 小时（120 分钟）后我们使用 5% 的移动止损。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool, 
                        **kwargs) -> float | None:

        # 确保先处理最长的时间间隔 - 这些条件从上往下评估。
        if current_time - timedelta(minutes=120) > trade.open_date_utc:
            return -0.05 * trade.leverage
        elif current_time - timedelta(minutes=60) > trade.open_date_utc:
            return -0.10 * trade.leverage
        return None
```

#### 带有成交后调整的基于时间的移动止损

前 60 分钟使用初始止损，之后改为 10% 移动止损，2 小时（120 分钟）后使用 5% 移动止损。
如果有额外订单成交，则将止损设置为比新 `open_rate`（[按所有入场平均计算](#仓位调整计算)）低 -10%。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool, 
                        **kwargs) -> float | None:

        if after_fill: 
            # 额外加仓后，开始设置比新开仓价低 10% 的止损
            return stoploss_from_open(0.10, current_profit, is_short=trade.is_short, leverage=trade.leverage)
        
        # 确保最长的时间间隔排在前面 - 这些条件从上往下评估。
        if current_time - timedelta(minutes=120) > trade.open_date_utc:
            return -0.05 * trade.leverage
        elif current_time - timedelta(minutes=60) > trade.open_date_utc:
            return -0.10 * trade.leverage
        return None
```

#### 为不同交易对设置不同的止损

根据交易对的不同使用不同的止损。
在此示例中，对 `ETH/BTC` 和 `XRP/BTC` 使用 10% 的移动止损，对 `LTC/BTC` 使用 5% 的移动止损，对所有其他交易对使用 15%。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool,
                        **kwargs) -> float | None:

        if pair in ("ETH/BTC", "XRP/BTC"):
            return -0.10 * trade.leverage
        elif pair in ("LTC/BTC"):
            return -0.05 * trade.leverage
        return -0.15 * trade.leverage
```

#### 带有正利润偏移量的移动止损

初始保持常规止损，直到利润高于 4%，然后使用当前利润的 50% 作为移动止损，最小为 2.5%，最大为 5%。

请注意，止损只能增加，低于当前止损价格的值将被忽略。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool,
                        **kwargs) -> float | None:

        if current_profit < 0.04:
            return None # 返回 None 以继续使用初始止损

        # 达到期望的利润后，允许止损回调利润的一半
        desired_stoploss = current_profit / 2

        # 限制最小为 2.5%，最大为 5%
        return max(min(desired_stoploss, 0.05), 0.025) * trade.leverage
```

#### 阶梯式止损

与其不断地跟在当前价格后面移动，此示例根据当前的利润设置固定的止损价格水平。

* 利润达到 20% 之前使用常规止损。
* 利润 > 20% 后，设置止损为比开仓价高 7%。
* 利润 > 25% 后，设置止损为比开仓价高 15%。
* 利润 > 40% 后，设置止损为比开仓价高 25%。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool,
                        **kwargs) -> float | None:

        # 从高到低评估，以便使用最高可能的止损价
        if current_profit > 0.40:
            return stoploss_from_open(0.25, current_profit, is_short=trade.is_short, leverage=trade.leverage)
        elif current_profit > 0.25:
            return stoploss_from_open(0.15, current_profit, is_short=trade.is_short, leverage=trade.leverage)
        elif current_profit > 0.20:
            return stoploss_from_open(0.07, current_profit, is_short=trade.is_short, leverage=trade.leverage)

        # 返回 None 保持当前止损价不变
        return None
```

#### 基于 DataFrame 指标的自定义止损示例

绝对止损值可以衍生自 DataFrame 中存储的指标。示例使用了价格下方的抛物线 SAR (SAR) 作为止损。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # <...>
        dataframe["sar"] = ta.SAR(dataframe)

    use_custom_stoploss = True

    def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                        current_rate: float, current_profit: float, after_fill: bool,
                        **kwargs) -> float | None:

        dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
        last_candle = dataframe.iloc[-1].squeeze()

        # 使用抛物线 SAR 作为绝对止损价格
        stoploss_price = last_candle["sar"]

        # 将绝对价格转换为相对于 current_rate 的百分比
        if stoploss_price < current_rate:
            return stoploss_from_absolute(stoploss_price, current_rate, is_short=trade.is_short)

        # 返回 None 保持当前止损不变
        return None
```

有关在策略回调中使用 DataFrame 的更多信息，请参阅 [Dataframe 访问](strategy-advanced.md#数据帧访问)。

### 止损计算的常用辅助函数

#### 相对于开盘价的止损 (Stoploss relative to open price)

从 `custom_stoploss()` 返回的止损值必须指定相对于 `current_rate` 的百分比，但有时您可能希望指定相对于 *入场价 (Entry price)* 的止损。
`stoploss_from_open()` 是一个辅助函数，用于计算可以从 `custom_stoploss` 返回的止损值，使其等效于入场价之上预期的交易利润。

??? Example "示例：从自定义止损函数返回相对于开盘价的止损"

    假设开盘价为 $100，`current_price` 为 $121 (`current_profit` 为 `0.21`)。

    如果我们希望止损价格在开盘价上方 7%，我们可以调用 `stoploss_from_open(0.07, current_profit, False)`，它将返回 `0.1157024793`。$121 下方 11.57% 的位置就是 $107，也就是 $100 上方 7% 的位置。

    此函数会考虑杠杆 - 因此在 10 倍杠杆下，实际止损将设置在 $100 之上 0.7% 的位置 (0.7% * 10x = 7%)。

    ``` python
    # 默认导入

    class AwesomeStrategy(IStrategy):

        # ... populate_* 方法

        use_custom_stoploss = True

        def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                            current_rate: float, current_profit: float, after_fill: bool,
                            **kwargs) -> float | None:

            # 一旦利润升至 10% 以上，将止损保持在开盘价上方 7%
            if current_profit > 0.10:
                return stoploss_from_open(0.07, current_profit, is_short=trade.is_short, leverage=trade.leverage)

            return 1

    ```

    完整的示例可以在文档的 [自定义止损](#自定义止损-custom-stoploss) 章节中找到。

!!! Note "注意"
    为 `stoploss_from_open()` 提供无效输入可能会产生 "CustomStoploss function did not return valid stoploss" 警告。
    如果 `current_profit` 参数低于指定的 `open_relative_stop`，则可能会发生这种情况。当平仓被 `confirm_trade_exit()` 方法阻塞时，可能会出现这类情况。可以通过确保 `confirm_trade_exit()` 不阻塞出场原因 (`exit_reason`) 为止损出的卖单来解决，或者使用 `return stoploss_from_open(...) or 1` 写法，这将在 `current_profit < open_relative_stop` 时请求不更改止损。

#### 相对于绝对价格的止损百分比 (Stoploss percentage from absolute price)

从 `custom_stoploss()` 返回的止损值始终指定相对于 `current_rate` 的百分比。为了在指定的绝对价格水平设置止损，我们需要计算相对于 `current_rate` 的百分比，该百分比产生的效果应与从开盘价指定的百分比相同。

辅助函数 `stoploss_from_absolute()` 可用于将绝对价格转换为相对于当前价格的止损百分比，以便从 `custom_stoploss()` 返回。

??? Example "示例：在自定义止损函数中返回基于绝对价格的止损"

    如果我们想在当前价格下方 2xATR 处跟随止损，可以调用 `stoploss_from_absolute(current_rate + (side * candle["atr"] * 2), current_rate=current_rate, is_short=trade.is_short, leverage=trade.leverage)`。
    对于期货，我们需要调整方向（上或下），并考虑杠杆，因为 [`custom_stoploss`](#自定义止损-custom-stoploss) 回调返回的是 [“该交易的风险”](stoploss.md#止损与杠杆) —— 而非相对价格变动百分比。

    ``` python
    # 默认导入

    class AwesomeStrategy(IStrategy):

        use_custom_stoploss = True

        def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
            dataframe["atr"] = ta.ATR(dataframe, timeperiod=14)
            return dataframe

        def custom_stoploss(self, pair: str, trade: Trade, current_time: datetime,
                            current_rate: float, current_profit: float, after_fill: bool,
                            **kwargs) -> float | None:
            dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
            trade_date = timeframe_to_prev_date(self.timeframe, trade.open_date_utc)
            candle = dataframe.iloc[-1].squeeze()
            side = 1 if trade.is_short else -1
            return stoploss_from_absolute(current_rate + (side * candle["atr"] * 2), 
                                          current_rate=current_rate, 
                                          is_short=trade.is_short,
                                          leverage=trade.leverage)
    ```

## 自定义 ROI (Custom ROI)

交易平仓前，每次迭代（大约每 5 秒）都会为所有未平仓位调用。

必须在策略对象上设置 `use_custom_roi=True` 方可启用。

此方法允许您定义自定义的最小 ROI 阈值，以比率形式表达（例如，`0.05` 代表 5% 利润）。如果同时定义了 `minimal_roi` 和 `custom_roi`，则其中较低的一个阈值将触发平仓。例如，如果 `minimal_roi` 设置为 `{"0": 0.10}`（0 分钟时 10%），而 `custom_roi` 返回 `0.05`，那么利润达到 5% 时将平仓。同理，如果 `custom_roi` 返回 `0.10` 且 `minimal_roi` 设置为 `{"0": 0.05}`，利润达到 5% 时也将平仓。

该方法必须返回一个 float，代表新的 ROI 阈值比率，或者返回 `None` 以回退到 `minimal_roi` 逻辑。返回 `NaN` 或 `inf` 值将被视为无效并等同于 `None`。

### 自定义 ROI 示例

以下示例说明了如何使用 `custom_roi` 实现不同的 ROI 逻辑。

#### 按多空方向设置自定义 ROI

根据 `side` 使用不同的 ROI 阈值。在此例中，多单为 5%，空单为 2%。

```python
# 默认导入

class AwesomeStrategy(IStrategy):

    use_custom_roi = True

    # ... populate_* 方法

    def custom_roi(self, pair: str, trade: Trade, current_time: datetime, trade_duration: int,
                   entry_tag: str | None, side: str, **kwargs) -> float | None:
        """
        自定义 ROI 逻辑，返回新的最小 ROI 阈值（比例，例如 0.05 代表 +5%）。
        仅在 use_custom_roi 设置为 True 时调用。

        如果同时使用了 minimal_roi，则达到的较低阈值将触发平仓。
        
        :param pair: 当前分析的交易对
        :param trade: 交易对象
        :param current_time: 当前时间 datetime 对象
        :param trade_duration: 交易已持续的分钟数
        :param entry_tag: 随入场信号提供的可选入场标签
        :param side: 'long' 或 'short' - 表示当前交易的方向
        :param **kwargs: 确保保留此参数
        :return float: 新的 ROI 比率值，或返回 None 以回退到 minimal_roi 逻辑
        """
        return 0.05 if side == "long" else 0.02
```

#### 按交易对设置自定义 ROI

根据 `pair` 使用不同的盈利阈值。

```python
# 默认导入

class AwesomeStrategy(IStrategy):

    use_custom_roi = True

    # ... populate_* 方法

    def custom_roi(self, pair: str, trade: Trade, current_time: datetime, trade_duration: int,
                   entry_tag: str | None, side: str, **kwargs) -> float | None:

        stake = trade.stake_currency
        roi_map = {
            f"BTC/{stake}": 0.02, # BTC 为 2%
            f"ETH/{stake}": 0.03, # ETH 为 3%
            f"XRP/{stake}": 0.04, # XRP 为 4%
        }

        return roi_map.get(pair, 0.01) # 其他所有交易对为 1%
```

#### 按入场标签设置自定义 ROI

根据入场信号附带的 `entry_tag` 使用不同的 ROI 阈值。

```python
# 默认导入

class AwesomeStrategy(IStrategy):

    use_custom_roi = True

    # ... populate_* 方法

    def custom_roi(self, pair: str, trade: Trade, current_time: datetime, trade_duration: int,
                   entry_tag: str | None, side: str, **kwargs) -> float | None:

        roi_by_tag = {
            "breakout": 0.08,       # 标签为 "breakout" 时为 8%
            "rsi_overbought": 0.05, # 标签为 "rsi_overbought" 时为 5%
            "mean_reversion": 0.03, # 标签为 "mean_reversion" 时为 3%
        }

        return roi_by_tag.get(entry_tag, 0.01)  # 未知标签为 1%
```

#### 基于 ATR 的自定义 ROI

ROI 值也可以根据 DataFrame 中存储的指标计算。此例使用 ATR 比例作为 ROI。

``` python
# 默认导入
# <...>
import talib.abstract as ta

class AwesomeStrategy(IStrategy):

    use_custom_roi = True

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # <...>
        dataframe["atr"] = ta.ATR(dataframe, timeperiod=10)

    def custom_roi(self, pair: str, trade: Trade, current_time: datetime, trade_duration: int,
                   entry_tag: str | None, side: str, **kwargs) -> float | None:

        dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
        last_candle = dataframe.iloc[-1].squeeze()
        atr_ratio = last_candle["atr"] / last_candle["close"]

        return atr_ratio # 返回 ATR 全比例作为 ROI
```

## 自定义订单价格规则 (Custom order price rules)

默认情况下，Freqtrade 使用挂单簿自动设置订单价格（[相关文档](configuration.md#订单使用的价格)），您也可以根据策略自定义订单价格。

您可以通过在策略文件中创建 `custom_entry_price()` 函数来自定义入场价格，或者创建 `custom_exit_price()` 来自定义出场价格。

这些方法都在实际向交易所下单前被调用。

!!! Note "注意"
    如果您的自定义定价函数返回 `None` 或无效值，价格将回退到 `proposed_rate`（基于常规价格配置）。

!!! Note "注意"
    使用 `custom_entry_price()` 时，一旦创建了第一个关联该交易的订单，Trade 对象即变为可用。对于首笔入场订单，`trade` 参数的值将为 `None`。

### 自定义订单入场和出场价格示例

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    def custom_entry_price(self, pair: str, trade: Trade | None, current_time: datetime, proposed_rate: float,
                           entry_tag: str | None, side: str, **kwargs) -> float:

        dataframe, last_updated = self.dp.get_analyzed_dataframe(pair=pair,
                                                                timeframe=self.timeframe)
        new_entryprice = dataframe["bollinger_10_lowerband"].iat[-1]

        return new_entryprice

    def custom_exit_price(self, pair: str, trade: Trade,
                          current_time: datetime, proposed_rate: float,
                          current_profit: float, exit_tag: str | None, **kwargs) -> float:

        dataframe, last_updated = self.dp.get_analyzed_dataframe(pair=pair,
                                                                timeframe=self.timeframe)
        new_exitprice = dataframe["bollinger_10_upperband"].iat[-1]

        return new_exitprice

```

!!! Warning "警告"
    修改入场和出场价格仅对限价单有效。根据所选的价格，可能会导致大量订单无法成交。默认情况下，当前价格与自定义价格之间允许的最大距离为 2%，此值可以通过配置中的 `custom_price_max_distance_ratio` 参数进行更改。
    **示例**：
    如果新 entry_price 为 97，proposed_rate 为 100，且 `custom_price_max_distance_ratio` 设置为 2%，则保留的有效自定义入场价格将是 98，即比当前建议价低 2%。

!!! Warning "回测"
    回测支持自定义价格（从 2021.12 版本开始），如果价格落在 K 线的最高/最低价范围内，订单将成交。
    未能立即完成的订单将受到常规超时处理（详见下文）。
    `custom_exit_price()` 仅对出场信号、自定义出场和部分平仓类型的卖单被调用。所有其他平仓类型将使用常规回测价格。

## 自定义订单超时规则 (Custom order timeout rules)

可以通过策略或配置在 `unfilledtimeout` 部分配置简单的基于时间的订单超时。

此外，Freqtrade 还为两种订单类型提供了自定义回调，允许您根据自定义标准决定订单是否已超时。

!!! Note "注意"
    回测只要价格在范围内就会成交。
    对于未能立即成交的订单（使用自定义定价），下述回调将在每个（精简）K 线被调用一次。

### 自定义订单超时示例

只要订单尚未成交或撤单，就会为每一个开启的订单调用。
`check_entry_timeout()` 为交易入场调用，而 `check_exit_timeout()` 为交易平仓订单调用。

下面是一个简单的示例，它根据资产的价格应用不同的未成交超时时间。
对高价资产应用较紧的超时限制，而允许低价币有更多时间去成交。

该函数必须返回 `True`（取消订单）或 `False`（保持订单在线）。

``` python
    # 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    # 将配置文件中的 unfilledtimeout 设置为 25 小时，因为后续自定义逻辑的最大值为 24 小时。
    unfilledtimeout = {
        "entry": 60 * 25,
        "exit": 60 * 25
    }

    def check_entry_timeout(self, pair: str, trade: Trade, order: Order,
                            current_time: datetime, **kwargs) -> bool:
        if trade.open_rate > 100 and trade.open_date_utc < current_time - timedelta(minutes=5):
            return True
        elif trade.open_rate > 10 and trade.open_date_utc < current_time - timedelta(minutes=3):
            return True
        elif trade.open_rate < 1 and trade.open_date_utc < current_time - timedelta(hours=24):
           return True
        return False


    def check_exit_timeout(self, pair: str, trade: Trade, order: Order,
                           current_time: datetime, **kwargs) -> bool:
        if trade.open_rate > 100 and trade.open_date_utc < current_time - timedelta(minutes=5):
            return True
        elif trade.open_rate > 10 and trade.open_date_utc < current_time - timedelta(minutes=3):
            return True
        elif trade.open_rate < 1 and trade.open_date_utc < current_time - timedelta(hours=24):
           return True
        return False
```

!!! Note "注意"
    在上述示例中，`unfilledtimeout` 必须设置为大于 24 小时的某个值，否则配置中的默认超时将首先生效。

### 自定义订单超时示例（使用额外数据）

``` python
    # 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    unfilledtimeout = {
        "entry": 60 * 25,
        "exit": 60 * 25
    }

    def check_entry_timeout(self, pair: str, trade: Trade, order: Order,
                            current_time: datetime, **kwargs) -> bool:
        ob = self.dp.orderbook(pair, 1)
        current_price = ob["bids"][0][0]
        # 如果价格高于订单价 2%，则取消买单。
        if current_price > order.price * 1.02:
            return True
        return False


    def check_exit_timeout(self, pair: str, trade: Trade, order: Order,
                           current_time: datetime, **kwargs) -> bool:
        ob = self.dp.orderbook(pair, 1)
        current_price = ob["asks"][0][0]
        # 如果价格低于订单价 2%，则取消卖单。
        if current_price < order.price * 0.98:
            return True
        return False
```

## 机器人订单确认 (Bot order confirmation)

确认交易的入场 / 出场。
这些是订单下单前的最后一层保障方法。

### 交易入场确认

`confirm_trade_entry()` 可用于在最后时刻终止交易入场（可能因为当时的实时价格不符合预期）。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    def confirm_trade_entry(self, pair: str, order_type: str, amount: float, rate: float,
                            time_in_force: str, current_time: datetime, entry_tag: str | None,
                            side: str, **kwargs) -> bool:
        """
        下单入场单之前立即调用。
        该函数的时间关键性极高，因此避免执行大量的计算或网络请求。

        :param pair: 即将被买入/现货开空的交易对
        :param order_type: 订单类型（由 order_types 配置）。通常为 limit 或 market。
        :param amount: 目标基准货币的数量。
        :param rate: 限价单使用的价格或市价单的当前价格。
        :param time_in_force: 生效时间。默认为 GTC (永不过期)。
        :param current_time: 包含当前日期时间的 datetime 对象
        :param entry_tag: 随入场信号提供的可选标签。
        :param side: "long" 或 "short" - 指明拟议交易的方向
        :param **kwargs: 保留此参数以便后续兼容。
        :return bool: 返回 True 时，订单将发送至交易所；False 将中止下单流程。
        """
        return True

```

### 交易出场确认

`confirm_trade_exit()` 可用于在最后时刻终止交易出场（卖出）（可能因为价格或利润不理想）。

在一次迭代中，如果适用不同的平仓逻辑，可能会针对同一笔交易多次调用此函数。执行顺序如下：

* `exit_signal`（由于策略信号） / `custom_exit`（自定义出场逻辑）
* `stop_loss`（止损）
* `roi`（收益率离场）
* `trailing_stop_loss`（追踪止损）

``` python
# 默认导入

class AwesomeStrategy(IStrategy):

    # ... populate_* 方法

    def confirm_trade_exit(self, pair: str, trade: Trade, order_type: str, amount: float,
                           rate: float, time_in_force: str, exit_reason: str,
                           current_time: datetime, **kwargs) -> bool:
        """
        常规出场单下单之前立即调用。
        该函数的时间关键性极高，避免重负荷计算。

        :param pair: 交易对
        :param trade: 交易对象
        :param order_type: 订单类型（limit 或 market）
        :param amount: 基准货币数量
        :param rate: 限价或建议的成交价
        :param time_in_force: 生效时间 (GTC)
        :param exit_reason: 出场原因
            可以是 ["roi", "stop_loss", "stoploss_on_exchange", "trailing_stop_loss",
                    "exit_signal", "force_exit", "emergency_exit"]
        :param current_time: datetime 对象
        :param **kwargs: 附加参数
        :return bool: 为 True 则下单，否则中止。
        """
        if exit_reason == "force_exit" and trade.calc_profit_ratio(rate) < 0:
            # 拒绝负利润的强制平仓（这仅是个逻辑展示，通常根据自己需求决定）
            return False
        return True

```

!!! Warning "警告"
    `confirm_trade_exit()` 可以阻止止损出场，这可能会导致因止损失效而产生重大损失。
    `confirm_trade_exit()` **不会** 为爆仓（Liquidations）调用 —— 因为爆仓是由交易所强制执行的，无法拒绝。

## 调整交易仓位 (Adjust trade position)

策略属性 `position_adjustment_enable` 开启了 `adjust_trade_position()` 回调的使用。
出于性能考虑，它默认是禁用的，如果启用，Freqtrade 在启动时会显示警告。
`adjust_trade_position()` 可用于执行额外的订单，例如通过 DCA（定投/马丁）管理风险，或者增加或减少仓位。

额外订单还会产生额外的费率，并且不计入 `max_open_trades` 限制。

当有挂单（入场或离场）等待执行时，该回调也会被调用 —— 并且如果新的数量、价格或方向不同，它将取消已有的挂单并下达新订单。订单的一部分成交也会被取消，并根据回调返回的新数量进行替换。

在交易存续期间，`adjust_trade_position()` 会被频繁调用，因此请务必保持实现的高效。

仓位调整始终应用于交易的方向：正值表示增加头寸，负值表示减少头寸，无论多空。返回一个 2 元素的元组可以为调整订单分配标签，例如 `return 250, "increase_in_favorable_conditions"`。

不支持修改杠杆，返回的投额默认假设是应用杠杆前的原金额。

仓位目前已用的总投额保存在 `trade.stake_amount` 中。因此，每次通过 `adjust_trade_position()` 进行的额外买入或部分卖出，`trade.stake_amount` 都会相应更新。

!!! Danger "逻辑严密性"
    在干跑和实盘中，该函数每 `throttle_process_secs`（默认为 5 秒）就会被调用一次。如果您的逻辑不够严密（例如，只要上根 K 线 RSI < 30 就加仓），机器人将每 5 秒加一次仓，直到您的钱用光、达到 `max_position_adjustment` 限制，或者出现 RSI > 30 的新 K 线。

    部分卖出也可能发生同样的情况。
    因此，请务必建立严格的逻辑约束，或者检查上一次成交的订单以及当前是否有挂单。

!!! Warning "大量加减仓的性能问题"
    仓位调整是提高策略效益的好方法，但过度使用会有负面影响。
    每个子订单在交易期间都会附加到交易对象上，从而增加内存占用。
    持有时间长且包含数十或上百个仓位调整的交易是不推荐的，应定期平仓以避免影响性能。

!!! Warning "回测"
    回测期间，该函数在每个策略时间范围或精简时间范围的 K 线都会调用。
    这还可能导致实盘和回测结果偏差，因为回测在每根 K 线内仅能调整一次，而实盘每根线可以根据循环频率调整多次。

### 增加仓位 (加仓)

当需要额外订单时（头寸增加），策略预期返回一个正的 **stake_amount**（以结算货币为单位），且在 `min_stake` 到 `max_stake` 之间。

如果钱包资金不足，信号将被忽略。属性 `max_entry_position_adjustment` 用于限制单次交易可执行的额外入场订单次数（初始订单除外）。缺省值为 -1，表示不限次数。

达到最大限额后，加仓将被忽略，但回调仍会被调用以便处理可能的“减仓”需求。

!!! Note "关于投额大小"
    使用固定投额设置时，它将作为初始订单的金额，与不开启调整逻辑时一样。
    如果您希望通过 DCA 加仓，请务必预留足够的余额。
    在 DCA 时使用 `"unlimited"` 设置需要您自行为 `custom_stake_amount()` 回调编写逻辑，以防所有余额都被分配给了初始订单。

### 减少仓位 (减仓)

策略预期为部分出场（减仓）返回一个负值的投额。返回此时名义上的全部头寸金额 (`-trade.stake_amount`) 将导致完全平仓离场。如果试图减少超过此时头寸的金额，信号会被忽略。

计算逻辑：部分平仓时，卖出的货币数量 = `negative_stake_amount * trade.amount / trade.stake_amount`。此计算不关心当前持仓的盈亏比例，只关心原始持仓数量和投入资金量。

举例：您以 50 的价格买了 2 个代币，此时 `trade.stake_amount` 是 100。现在价格涨到了 200，您想卖一半。此时应返回 `trade.stake_amount` 的 -50%，即 -50。机器人会计算出应卖出 1 个代币 (`50 * 2 / 100`)。如果您返回 -200（想基于当时市值卖一半），逻辑会不通，因为投额只有 100，卖 200 相当于要卖 4 个代币，所以会被忽略。

如果您想按当时市值提取投资。例如提取 100 USDT 以回收本金。此时需要反向算出比例。对应 200 的价格，100 USDT 等于 0.5 个代币。反推回 adjust 函数就需要返回 `(-0.5 * trade.stake_amount / trade.amount)`，也就是 -25。

!!! Warning "止损计算"
    止损始终基于初始开仓价，而非平均成本价。
    常规止损规则仍适用（止损不能下调）。

    `/stopentry` 命令会阻止机器人新开交易，但仓位调整功能仍会继续为现有交易进行买入。

``` python
# 默认导入

class DigDeeperStrategy(IStrategy):

    position_adjustment_enable = True

    # DCA 处理大跌。需要较大的止损阈值。
    stoploss = -0.30

    # ... populate_* 方法

    max_entry_position_adjustment = 3
    max_dca_multiplier = 5.5

    # 初始下单
    def custom_stake_amount(self, pair: str, current_time: datetime, current_rate: float,
                            proposed_stake: float, min_stake: float | None, max_stake: float,
                            leverage: float, entry_tag: str | None, side: str,
                            **kwargs) -> float:
        # 分配较少资金，为可能的 DCA 留足余地
        return proposed_stake / self.max_dca_multiplier

    def adjust_trade_position(self, trade: Trade, current_time: datetime,
                              current_rate: float, current_profit: float,
                              min_stake: float | None, max_stake: float,
                              current_entry_rate: float, current_exit_rate: float,
                              current_entry_profit: float, current_exit_profit: float,
                              **kwargs
                              ) -> float | None | tuple[float | None, str | None]:
        """
        :param current_profit: 当前利润
        :param current_entry_profit: 使用入场价计算的利润
        :return float: 正值加仓，负值减仓。或元组带有成交理由。
        """
        if trade.has_open_orders:
            return

        if current_profit > 0.05 and trade.nr_of_successful_exits == 0:
            # +5% 利润时获利一半离场
            return -(trade.stake_amount / 2), "half_profit_5%"

        if current_profit > -0.05:
            return None

        # 跌幅超过 5% 时处理
        dataframe, _ = self.dp.get_analyzed_dataframe(trade.pair, self.timeframe)
        last_candle = dataframe.iloc[-1].squeeze()
        previous_candle = dataframe.iloc[-2].squeeze()
        if last_candle["close"] < previous_candle["close"]:
            return None # 价格还在跌时不抄底

        count_of_entries = trade.nr_of_successful_entries
        # 设置倍数逐步加仓，最多加 3 次。总投入倍数为 1 + 1.25 + 1.5 + 1.75 = 5.5x。
        try:
            filled_entries = trade.select_filled_orders(trade.entry_side)
            stake_amount = filled_entries[0].stake_amount_filled
            stake_amount = stake_amount * (1 + (count_of_entries * 0.25))
            return stake_amount, "DCA_increase"
        except Exception:
            return None
```

### 仓位调整计算逻辑

* 进场均价使用加权平均计算。
* 平仓（出场）不影响已有的入场均价。
* 部分平仓利润是相对于当时的入场均价计算的。
* 最终的总利润是基于总投资额计算的。

??? example "计算示例"
    *以简化的 0 费率和做多为例*

    * 第一笔买入：100@8$
    * 第二笔买入：100@9$ -> 均价：8.5$
    * 第一笔部分卖出：100@10$ -> 均价：8.5$，已实现利润 150$，回报率 17.65%
    * 重新买入：150@11$ -> 新持仓均价变为 10$（计算方式：原市值 100*8.5 + 新入 150*11 / 总持有量 250）
    * 第二笔部分卖出：100@12$ -> 均价 10$，已实现总利润 350$，回报率 20%
    * 全部卖出：150@14$ -> 均价 10$，最终 realized profit 950$，总收益 40% <- *最后这条卖出记录为离场*

    总利润为 950$，总投资本金分三次进入（800+900+1650=3350$）。最终相对利润展示为 28.35% (950 / 3350)。

## 调整订单价格 (Adjust order price)

`adjust_order_price()` 可供开发者在每个新 K 线生成时刷新/替换限价单。
每迭代一次会调用一次，除非订单在当前 K 线内已经替换过。这意味着初始下单后的下一个 K 线开始才会第一次触发。

价格替换后，原订单会被撤销并按新价下单。如果撤单失败，替换也会取消。

!!! danger "与 `adjust_*_price()` 的不兼容性"
    如果实现了 `adjust_order_price()`，则较旧的 `adjust_entry_price()` / `adjust_exit_price()` 将失效。混合使用会报错。

## 杠杆回调 (Leverage Callback)

在杠杆交易市场，该方法返回期望的倍数（默认为 1 倍）。

所有利润和指标计算都会受到杠杆影响。例如 10x 杠杆下，设置 10% 止损表示底部价格变动 1% 就会触发清算平仓。

``` python
# 默认导入

class AwesomeStrategy(IStrategy):
    def leverage(self, pair: str, current_time: datetime, current_rate: float,
                 proposed_leverage: float, max_leverage: float, entry_tag: str | None, side: str,
                 **kwargs) -> float:
        """
        自定义每一笔交易的杠杆。
        :return: 处于 1.0 到交易所 max_leverage 之间的值。
        """
        return 1.0
```

## 订单成交回调 (Order filled Callback)

每次订单成交（无论是入场、离场、止损还是调仓）后调用。可用于在成交时刻记录瞬间的数据（如 K 线的高点）。

``` python
class AwesomeStrategy(IStrategy):
    def order_filled(self, pair: str, trade: Trade, order: Order, current_time: datetime, **kwargs) -> None:
        dataframe, _ = self.dp.get_analyzed_dataframe(trade.pair, self.timeframe)
        last_candle = dataframe.iloc[-1].squeeze()
        
        if (trade.nr_of_successful_entries == 1) and (order.ft_order_side == trade.entry_side):
            # 记录下单那一刻的 K 线最高价
            trade.set_custom_data(key="entry_candle_high", value=last_candle["high"])
```

## 绘图标注回调 (Plot annotations callback)

用于 freqUI 在图表上绘制特定的文字、区域或线条。它对交易循环没有实际意义，仅供可视化。
